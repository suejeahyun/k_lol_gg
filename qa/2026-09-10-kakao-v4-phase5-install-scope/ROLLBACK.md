# 롤백 절차

## 적용 전

이번 패치는 소스와 QA만 변경했다. 운영 배포, DB 마이그레이션, 비밀값 변경이 없으므로 현재 시점의 롤백은 브랜치를 배포하지 않는 것으로 충분하다.

## 적용 후 문제가 발견된 경우

1. V4 RECRUIT와 FEATURES 전화 프로필을 중지해 신규 V4 요청을 차단한다.
2. V3/V41 라우트와 기존 방 등록·페어링 DB는 그대로 유지한다. V4와 V41을 동시에 활성화하지 않는다.
3. 서버를 기준 커밋 `924ebd187c0064274a403414881fbf7cd4a3b362` 또는 이 패치 직전의 검증된 배포 이미지로 되돌린다.
4. current/previous signing key나 identity secret을 롤백 과정에서 임의로 변경하지 않는다. 침해 사고인 경우에만 별도 비밀 회전 절차를 따른다.
5. V4 내부 설치 범위로 생성된 행과 내구성 영수증은 삭제하거나 하향 마이그레이션하지 않는다. 먼저 읽기 전용으로 영향 범위를 확인하고 보존한다.
6. V3/V41 회귀, V4 비활성 상태, 오류율을 확인한 뒤 종료한다.

## 데이터 주의사항

- 스키마 변경이 없으므로 down migration은 없다.
- 롤백 후 과거 V4 시험 행이 남아도 V3/V41 방 페어링 데이터와 자동으로 합쳐지지 않는다.
- identity secret 변경은 새로운 installation ID와 내부 범위를 만들므로 단순 롤백 수단으로 사용하면 안 된다.
