# Kakao V4 R4 V1 화면 호환·응답 최적화 QA

## 범위와 판정

- 목표: 사용자가 입력하는 명령, 받는 양식, 현황·상세·반영·마감·전적·최근·랭킹 문구를 V1 방식으로 유지한다.
- 의도적으로 유지한 최신 요구사항: 파티 양식 호출은 활성 구인글을 만들지 않는다. 서버는 숫자 모집번호 확보용 `DRAFT`만 숨겨 저장하고, 사용자가 채운 전체 양식을 보내면 `IN_PROGRESS`로 전환한다.
- 내부 변경: MessengerBot 설정의 요청 단위 캐시, 같은 로그 재전송 본문 재사용, 상태 조회 projection, 텍스트 경로의 Sharp 런타임 분리.
- 운영 반영: GitHub `main`과 Vercel Production 반영을 확인했다. 배포 ID와 운영 점검 결과는 `PRODUCTION_DEPLOYMENT.md`에 기록했다.

## 사용자 가시 호환

- `/` 유무와 관계없이 공개 명령 분류가 같다.
- `2인파티`, `5인파티` 등은 V1 숫자 모집번호가 포함된 복사 양식을 반환한다.
- 양식에는 시작시간·게임정보 입력란을 노출하지 않는다. 작성 양식 제출 뒤 서버 기본값 또는 인식값을 반영 결과·상세에서 보여준다.
- 구인현황, 상세, 전체 양식 동기화, `번호ㅉ` 마감 문구를 V1 형식으로 복구했다.
- 전적·최근 경기·랭킹의 티어, 세트 수, KDA, 링크와 빈 상태·정수 승률 문구를 V1 형식으로 복구했다.
- 같은 방의 다른 사용자가 작성·수정·마감할 수 있고 관리자 전용 제약은 추가하지 않았다.

## 성능·안정성 변경

- V4 명령 함수 번들에서 이미지 처리용 Sharp를 분리했다.
- 최종 V4 commands NFT: 165개 파일, 2,420,599 bytes(2.308 MiB), Sharp 0개.
- 이전 측정 13,779,950 bytes 대비 11,359,351 bytes, 약 82.4% 감소했다.
- 구인현황은 파티만, 스크림현황은 스크림만 조회해 각각 불필요한 세 쿼리를 제거했다.
- 한 번의 휴대폰 콜백에서 동일 설정값을 반복 읽지 않는다.
- 같은 Kakao `logId` 재전송은 event ID뿐 아니라 서명된 본문도 그대로 재사용해 409 충돌을 방지한다.

## 남은 위험과 확인 항목

- 실제 MessengerBot R 휴대폰 입력·카카오 수신 속도는 새 단일 파일을 붙여넣은 뒤 확인해야 한다.
- 사용하지 않고 남은 `DRAFT` 번호가 하루 99개까지 누적될 수 있다. 일반 사용량에는 영향 가능성이 낮지만, 장기적으로 만료형 번호 예약 테이블이 더 안전하다.
- KDA는 게시된 경기의 킬·데스·어시스트 합산값으로 계산한다. V1 예시 fixture의 임의 숫자 조합과 실제 계산 결과가 다를 수 있으나 출력 형식은 동일하다.
