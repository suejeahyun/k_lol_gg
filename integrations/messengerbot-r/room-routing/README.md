# 카카오 방 라우터

카카오톡 알림에 대화 제목이 없고 Legacy `room`이 발신자 이름으로 전달되는 기기용 공통 모듈이다. 기존 네 봇 프로필을 유지하고, 원본 알림의 명시적으로 등록된 채팅방 식별값으로만 명령을 전달한다.

## 설치 구성

- 공통 코드: `/sdcard/msgbot/global_modules/KAKAO_ROOM_ROUTER.js`
- 바인딩: DataBase의 `KAKAO_ROOM_BINDINGS_V1` JSON 문자열
- 기존 프로필: KLOLMain, KLOLM, NEXUS-Main, NEXUS-otuce

네 프로필의 전체 코드, 공통 모듈, 기기용 바인딩을 함께 설치한다. 공통 모듈을 별도 봇 프로필로 등록하지 않는다. 모듈이 없거나 잘못된 경우 컴파일을 실패시키며 Legacy 방 이름 처리로 되돌아가지 않는다.

바인딩은 `version: 1`, 비어 있지 않은 `revision`, `slots`를 포함한다. `slots`에는 `KLOL_MAIN`, `KLOL_RECRUIT`, `NEXUS_MAIN`, `NEXUS_RECRUIT`가 모두 있어야 한다. 각 항목은 Android 사용자 식별자의 문자열 `user`와 `Notification.getShortcutId()`의 원문 문자열 `shortcutId`로 구성한다. 네 식별값은 서로 달라야 한다. 숫자로 보이더라도 숫자 변환, 공백 제거, 대소문자 변경을 하지 않는다. `extras.threadId`와 메시지용 `chatLogId`로 방을 식별하지 않는다.

실제 식별값은 사용자 또는 사용자가 명시적으로 허용한 작업자가 각 방에 입력한 서로 다른 일회용 연결 코드의 알림에서 수집한다. 이름이나 발신자, 알림 순서, 샘플 숫자로 채우지 않는다. 실제 채팅방과 임시 수집 결과의 네 슬롯을 대조한 후 전체 registry를 한 번에 활성화한다. 기존 슬롯을 다른 방으로 덮어쓰지 않으며, 재연결은 새 수집·검증 절차로 진행한다. 운영 식별값과 설정 파일은 공개 저장소에 포함하지 않는다.

## 동작과 확인

KLOLMain은 K-LOL의 두 슬롯, NEXUS-Main은 NEXUS의 두 슬롯만 처리한다. KLOLM과 NEXUS-otuce는 각 구인구직 슬롯만 처리한다. 허용되지 않은 알림은 기존 명령 처리 함수에 전달하지 않는다. 공통 registry는 방 구분 정보만 보관하며 서비스별 API 인증·DB namespace는 기존 설정을 사용한다.

답장은 수신 알림에서 확보한 Action에 고정한다. 발신자 이름으로 방을 찾거나 전역 답장 세션을 검색하지 않는다. 기존 `response` 자동 실행과 원본 알림 실행을 동시에 활성화하지 않는다. 재컴파일은 기존 처리와 사이트 알림 세션을 정리하며, 사이트 알림은 각 구인구직방에서 별도 일회용 코드로 등록한다.

설치 후 네 방에서 `봇버전`을 보내 서비스가 맞고 답장이 한 번씩 오는지 확인하고, 구인방의 `구인현황`으로 서비스별 데이터가 구분되는지 확인한다. 구인방에서는 `사이트알림상태`와 실제 새 알림 수신을 별도로 확인한다. 명령 답장과 세션 등록만으로 신규 사이트 이벤트의 자동 알림까지 검증됐다고 기록하지 않는다.

실기기 근거와 진행 상태는 [QA 문서](../../../docs/qa-evidence/kakao-notification-routing-2026-10-28/README.md)에 기록한다.
