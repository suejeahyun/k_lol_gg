# 카카오봇 V4 재설계 — V1 호환 계약

계약 버전: `KLOL_KAKAO_V4_V1_COMPAT_2026_09_14_R5`

V1 strict 설치본 식별 버전은 `KLOL_KAKAO_BOT_V40_R16_2026_09_14`이다. 휴대폰에서 `/봇버전`으로 R16 설치 여부를 구분한다.

이 문서는 V4 구현이 지켜야 할 사용자 관찰 가능 동작을 고정한다. 이 문서의 파생 계약 원본은 `tests/fixtures/kakao-v4-v1-compatibility-contract.json`이다. 실제 V1에 있었던 동작인지 판정할 때는 변경 불가 원본과 확장 경계를 정한 `docs/contracts/KAKAO_V1_STRICT_BOUNDARY.md`를 우선한다.

## 근거와 판정

- 확인됨: 원본 V1 단일 파일 SHA-256은 `c91a56a289a762fe7e08143e8fd4b55c9695c4df68ebfcb6689613dcb73776b7`이다.
- 확인됨: 기존 V40/V41 골든 테스트가 도움말, 파티, 내전, 스크림, 전적·최근·랭킹, 운영 양식, 등록·경고 안내 문구를 고정한다.
- 확인됨: 구형 참가행 양식은 시작 시간이 없으면 서버 접수 시각 KST `HH:mm`, 게임 정보가 없으면 `미입력`을 쓰는 하위 호환을 유지한다.
- 확인됨: 현재 V4 애플리케이션 권한은 동일한 프로필별 installation scope의 사용자에게 파티·스크림 수정 권한을 주며 다른 installation scope에서는 대상을 숨긴다.
- V4 요구사항으로 확정: 전체 양식은 권위 있는 스냅샷이며 A→B→A 재수정을 모두 새 리비전으로 수용한다.
- 미확인: V4의 실제 라우터·저장소 구현과 운영 JAR 반영 여부. 이 산출물은 계약과 독립 검증 픽스처만 추가하며 운영 배포를 하지 않는다.

## 1. 공통 입력 경계

명령어는 선행 ASCII `/`가 없거나 정확히 하나 있는 두 형태만 같다. 예를 들어 `도움말`과 `/도움말`, `5인파티`와 `/5인파티`는 같은 라우트와 같은 응답을 가져야 한다.

아래 입력은 명령어가 아니다.

- `//도움말`, `//5인파티`: 선행 슬래시가 두 개다.
- `/ 5인파티`: 슬래시와 명령어 사이가 떨어져 있다.
- `https://k-lol-gg.vercel.app/도움말`: URL 안의 슬래시다.
- `오늘 /내전현황`, `구인/현황`: 문장 중간의 슬래시다.

전체 양식 본문은 명령어 라우팅보다 별도 양식 파서에서 판정한다. 봇 자신이 보낸 운영 양식은 재접수하지 않는다.

## 2. installation scope·사용자 권한

모집 소유권은 발신자 개인이 아니라 V4 프로필에서 파생한 installation scope에 귀속된다.

- 동일 installation scope 사용자라면 최초 작성자가 아니어도 이름 추가·삭제, 전체 양식 수정, 파티 마감을 할 수 있다.
- 다른 installation scope에서는 읽기·수정·마감을 할 수 없다.
- 발신자 ID는 감사 추적에는 남기되 권한 소유자 키로 사용하지 않는다.
- 현재 V4 command gateway는 방 이름·channel ID·room parser·canonical room registry를 인증이나 라우팅에 사용하지 않는다. 내부 `room-*` 값은 실제 카카오톡 방 ID가 아니라 프로필 installation ID에서 파생한 저장 scope다.

서로 다른 세 `sender-*`가 같은 installation scope의 모집을 수정·마감할 수 있어야 하는 시나리오를 픽스처에 고정했다. 픽스처의 `differentRoomId`는 레거시 필드명을 유지하지만 의미는 다른 installation scope 거부 예시다. 한 휴대폰·한 봇 프로필·두 물리 방 구성에서는 메시지 내용이 `RECRUIT`/`FEATURES`를 선택하므로, 잘못된 물리 방에 입력한 명령도 해당 프로필 scope에서 실행될 수 있다는 운영 한계를 별도로 안내해야 한다.

## 3. 전체 양식 수정 계약

파티·내전·스크림의 복사 가능한 전체 양식은 부분 패치가 아니라 현재 상태 전체를 나타낸다.

1. A 양식을 보내면 리비전 1에 A 전체가 저장된다.
2. B 양식을 보내면 누락된 A의 이름·필드는 삭제되고 리비전 2에 B 전체가 저장된다.
3. 다시 A 양식을 보내면 과거 내용이라는 이유로 버리지 않고 리비전 3에 A 전체가 저장된다.
4. 이름이 0명이면 현재 명단을 비운다. 파티는 빈 모집, 내전 참가자는 동일 방·동일 회차에서 취소/철회로 처리한다.

동일 배달 ID의 즉시 재전송만 중복 콜백으로 억제할 수 있다. 내용 해시를 영구 중복 키로 쓰면 A→B→A가 깨지므로 금지한다.

## 4. 파티 구인

### 명령과 별칭

| 흐름 | 별칭 |
|---|---|
| 숫자 파티 | `N인파티`, `N인구인` |
| 협곡·랭크 | `5인협곡`, `5인협곡파티`, `5인 협곡 파티`, `자랭구인`, `일반구인`, `솔랭구인` |
| 칼바람·기타 | `칼바람구인`, `증바람구인`, `기타게임구인` |
| TFT | `롤체일반구인`, `롤체랭크구인`, `더블업구인` |
| 현황 | `현재구인구직현황`, `현재구인현황`, `구인구직현황`, `구인현황`, `현황` |
| 상세 | `구인상세 #N`, `상세 N` |
| 이름 빠른 추가 | `상세 N 추가 이름` |
| 이름 빠른 삭제 | `상세 N 삭제 이름` |
| 마감 | `N쫑`, `#Nㅉ`, `N번 파티 마감`, `N인 구인 종료`, `구인마감 #N`, `구인쫑 #N`, `구인종료 #N` |

최초 `N인파티`는 활성 모집을 만들지 않고 현재 오전 6시 기준 운영일의 DRAFT 번호만 예약한다. 응답 양식에는 `운영일: YYYY-MM-DD`와 빈 `》시작시간 :`, `》게임정보 :`, `》주최자 :` 세 줄을 반드시 표시하고 참가행은 넣지 않는다. 새 양식 제출은 표시된 운영일을 우선하여 오전 6시 경계를 넘어도 예약 원장을 오염시키지 않으며, 운영일이 없는 구형 양식은 제출 시각 기준 계산을 유지한다. 주최자를 채운 전체 양식을 다시 보내면 같은 DRAFT를 `IN_PROGRESS`로 활성화하고 주최자를 첫 번째 참가자로 원자 등록한다. 시작시간을 비우면 작성본을 받은 현재 KST `HH:mm`, 게임정보를 비우면 `미입력`을 적용한다. 세 줄을 모두 비운 무편집 양식은 활성화하지 않는다. 활성화 이후 주최자 문구만 바꾸거나 같은 양식을 재전송해도 기존 참가 명단은 유지하며, 주최자와 같은 이름을 빠른 추가하면 중복 등록하지 않는다.

기존 번호·포지션 참가행이 있는 V1 전체 양식은 계속 파싱한다. 참가자가 하나 이상 채워진 구형 양식은 주최자 줄이 없어도 DRAFT를 활성화할 수 있고, 시작시간·게임정보 기본값도 종전대로 유지한다. DRAFT는 현황·상세·빠른 추가·삭제 대상에서 숨긴다. 활성화된 모집의 현황·상세에는 주최자를 표시한다.

전체 양식에는 `모집번호: #N`이 반드시 있어야 한다. 없으면 다음 정확 문구를 보낸다.

```text
[K-LOL.GG 양식 확인 필요]
모집번호를 찾지 못했습니다.

봇이 출력한 원본 양식의 ‘모집번호: #번호’를 유지해서 다시 보내주세요.
```

최초 5인 템플릿, 기본값 상세, 구인 도움말의 정확 줄바꿈은 픽스처에 원문 그대로 들어 있다.

### 이름 빠른 추가·삭제 확장

`상세 N 추가 이름`과 `상세 N 삭제 이름`은 V1 전체 양식 수정을 대체하지 않는 V4 승인 확장이다. 대상은 요청 시각으로 계산한 현재 모집 운영일, 서명 검증된 `RECRUIT` installation scope의 `IN_PROGRESS` 파티로 제한한다. DRAFT, 과거 운영일, 다른 installation scope, 종료·취소된 파티는 찾은 것으로 취급하지 않는다.

- 추가는 주 참가자 빈 자리를 먼저 사용하고 주 정원이 찼으면 예비로 배치한다.
- 같은 정규화 이름이 이미 있으면 변경하지 않고 중복 안내를 응답한다.
- 삭제 대상이 없으면 변경하지 않고 이름 없음 안내를 응답한다.
- 같은 정규화 이름이 둘 이상이면 임의 삭제하지 않고 전체 양식에서 정확한 줄을 비우도록 안내한다.
- 참가자와 예비를 합쳐 99명 한도에 도달하면 추가하지 않고 한도 안내를 응답한다.
- 대상 모집이 없거나 위 업무상 변경 불가 결과가 발생해도 generic HTTP 400으로 숨기지 않는다. 구체적인 한국어 `reply`를 HTTP 200으로 보내고, 그 뒤 최신 전체 구인 현황을 붙인다.
- 성공과 업무상 무변경 모두 `RecruitMutationBody.data`의 `action`, `outcome`, `name`, `slotNo`, `substitute`, `memberCount`, `reserveCount`를 기준으로 응답한다. 전체 양식 스냅샷과 기존 마감 흐름은 그대로 유지한다.

구인 도움말과 파티 상세에는 각각 `상세 번호 추가 이름` / `상세 번호 삭제 이름` 형식을 안내한다. 상세의 기존 전체 양식 수정 문구와 편집 가능한 전체 명단은 삭제하거나 축약하지 않는다.

## 5. 내전

생성 별칭은 `내전구인구직`, `내전구인`, `내전모집`이며 종목·날짜·시간·`#모집번호`·`N명`을 뒤에 붙일 수 있다. `내전상세`, `내전현황`, `시즌내전현황`, `AI공지`, `내전참가`, `내전신청`, `참가신청`을 유지한다.

| 종목 | 입력 별칭 | 참가자 필드 | 시즌 명단 반영 |
|---|---|---|---|
| 협곡 | `협곡`, `rift` | 이름/현티어/최고티어/주라인/부라인 | 예 |
| 칼바람 | `칼바람`, `aram` | 이름 | 아니오 |
| 증바람 | `증바람`, `증강칼바람`, `augmentaram` | 이름 | 아니오 |

생성 명령은 DRAFT 회차 번호와 전체 양식만 반환하며 공개 현황에는 노출하지 않는다. 주최자 또는 참가자를 채운 전체 양식이 제출될 때 모집을 활성화한다. 활성화 이후 전체 양식 재전송은 확인창 없이 즉시 같은 방·회차의 참가자 스냅샷을 교체하고, 비어 있는 전체 양식은 기존 명단의 0명 철회로 처리한다. `내전상세 N 추가 이름`과 `내전상세 N 삭제 이름`은 같은 installation scope의 활성 회차에만 적용한다. `내전 Nㅉ`과 `/내전 Nㅉ`은 현재 운영일·같은 scope의 활성 회차만 마감하고, 성공 직후 마감된 회차가 제외된 최신 내전현황을 함께 반환한다. 지원하지 않는 종목에 대한 정확 종목 선택 안내는 픽스처에 고정했다.

## 6. 스크림

생성은 `스크림구인`, `스크림모집`, `멸망전스크림`, `멸망전스크림구인`, `멸망전스크림모집`을 유지한다. 현황·목록·상세는 `스크림`과 `멸망전스크림` 접두형을 모두 유지한다.

- 신규 전체 양식 제출은 한 번 저장하고 `[K-LOL.GG 스크림 등록 완료]`를 응답한다.
- 생성 명령은 DRAFT 번호와 빈 양식만 반환하며 공개 현황에는 노출하지 않는다. 주최자 또는 우리팀을 채운 작성본만 활성화한다.
- `스크림상세 N 추가 이름`과 `스크림상세 N 삭제 이름`은 같은 installation scope의 활성 모집에만 적용한다.
- 기존 번호 전체 양식은 별도 확인 없이 수정 가능한 필드를 교체하고 기존 멸망전 연결을 보존한다.
- 번호 없는 `스크림참가`, `스크림확정`, `스크림취소`, `스크림마감/종료` 및 멸망전 접두형은 상태를 변경하지 않고 V1의 사용 중단 안내를 정확히 응답한다.
- `스크림 Nㅉ`과 `/스크림 Nㅉ`은 현재 운영일·같은 scope의 활성 모집만 `COMPLETED`로 마감하고, 성공 직후 최신 스크림현황을 함께 반환한다.
- 수동 번호 마감과 별개로 매일 오전 6시 KST 자동 종료를 유지한다.

초기 양식, 빈 현황, 등록 완료, 번호 마감 안내, 네 가지 사용 중단 응답의 정확 문구는 픽스처에 있다.

## 7. 전적·최근·랭킹

- `전적 닉네임#태그`: 시즌, 현재/최고 티어, 참여, 전적, KDA, MVP, 최근 경기, 플레이어 링크를 표시한다.
- `최근 닉네임#태그`: 최근 경기와 플레이어 링크를 표시한다.
- `랭킹`: 최소 참여 기준과 TOP 5를 표시한다.

선행 `/` 유무로 조회 대상이나 표시 내용이 달라지면 안 된다. 대표 응답은 픽스처의 `exactReplies.record`, `recent`, `ranking`에 정확히 고정한다.

| 정모 | 주최자 이름 및 닉네임, 일자, 장소, 참여자 명단 |
| 외출 | 이름 및 닉네임, 외출기간, 외출사유, 외출범위 |

외출 양식은 `💟간편 공지💟`, `2. 양식작성 후 전송`, `<외출>`, `&lt;외출&gt;` 래퍼를 모두 허용한다. 필드 누락 시 누락 라벨을 순서대로 보여준다. `오픈채팅봇` 발신 양식은 echo로 간주해 저장·응답하지 않는다.

## 9. 등록·경고 안내

| 흐름 | 별칭 |
|---|---|
| 쉬운 등록 센터 | `등록`, `등록도움말`, `사진취소` |
| 내전 결과 등록 | `내전등록`, `결과등록`, `내전결과` |
| 결과 접수 현황 | `내전등록현황`, `결과현황` |
| 관리자 경고 등록 | `경고등록`, `경고` |
| 경고 차감 사진 | `인증`, `경고인증` |
| 내 경고 현황 | `경고현황` |

각 흐름의 정확 제목·설명·URL·줄바꿈은 픽스처의 `registrationHub`, `inhouseResultGuide`, `inhouseResultStatusGuide`, `disciplineCreateGuide`, `disciplineEvidenceGuide`, `disciplineStatusGuide`에 고정한다. URL의 호스트만 배포 환경의 공개 기본 URL로 치환할 수 있다.

## 10. 사용자 도움말과 V2 운영 진단 분리

사용자용 `도움말`/`명령어`와 `구인도움말`에는 아래 항목을 넣지 않는다.

- `V2도움말`, `V2진단`, `V2연동확인`
- `V2모집`, `V2시즌`, `V2양식`, `V2사진세션`
- raw JSON 입력 예시

이 항목들은 운영자 진단 표면에서만 제공한다. 사용자 도움말에는 V1 명령과 사이트 기반 등록 안내만 노출한다.
