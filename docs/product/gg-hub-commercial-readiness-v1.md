# GG HUB 유료 서비스 완성 기준

기준일: 2026-11-01 (Asia/Seoul). 사용자의 “실제 사업으로 이용료를 받고 계속 잘 쓰는 서비스” 요구를 반영한다. 제품 방향과 출시 기준이며, 아래 계획이 전부 구현됐거나 과금을 시작했다는 뜻은 아니다. 기존 [제품 기획](gg-hub-platform-plan-v1.md)의 사이트 독립성·선택적 공유·운영 기록 권한 원칙을 유지한다.

## 고객과 판매할 가치

첫 고객은 반복적으로 모집·회원·내전·대회를 운영하는 커뮤니티 소유자다. 일반 회원의 기본 가입·참여는 무료로 두고, 운영자가 자기 사이트와 운영 도구에 비용을 지불하는 방향으로 설계한다. 최종 상품·가격은 아직 확정하지 않는다.

고객이 비용을 낼 이유는 브랜드 사이트, 모집과 참가자 정리, 운영진 인수인계, 방 연결, 기록 보존, 공동 활동을 한곳에서 처리하면서 시간과 실수를 줄이는 것이다. 사이트 개수나 기능 개수보다 실제 운영 성과를 측정한다. 밴 기록 접근이나 “위험 인물 점수”를 판매하지 않는다.

## 유료 출시의 통과 조건

| 고객의 일 | 구현·검증해야 하는 계약 | 통과 근거 |
| --- | --- | --- |
| 시작 | 신청→심사→개설→첫 로그인→소개·가입 정책→첫 회원→첫 모집 | 개발자나 DB 직접 조작 없이 운영자 혼자 완료; 중도 재접속 가능 |

| 공동 모집·대회 | 모집 원본 하나, 합의된 규칙 버전·명단·결과 | 마지막 자리 동시 신청, 취소, 중복 출전, 결과 이의·정정 통과 |
| 결제 | 주문·구독·청구·이용 권한을 분리, webhook 중복·순서 역전 처리 | 결제 제공자 sandbox에서 성공/실패/재전송/갱신/해지/환불 검증 |

목표와 현재 사실을 구분한다. 첫 가치 도달 시간, 주간 활동 운영자, 모집 완료율, 중복/오발송 건수, 문의 첫 응답·해결 시간, 사이트별 원가와 유지율의 기준선을 먼저 수집한다. “99.9% 보장”이나 특정 응답 시간을 측정·인력 근거 없이 판매 문구에 넣지 않는다.

## 상품과 과금 설계 방향

- 검증용 체험과 운영자 구독을 구분한다. 기본 구독 + 명확한 자원 한도를 우선 비교한다. 테마 3개를 요금제 3개와 혼동하지 않는다.
- 가격은 사이트당 고정·변동 원가, 봇 기기 운영, 고객지원 시간을 측정하고 초기 고객의 지불 의사를 확인한 뒤 결정한다. 무제한 제공과 임의 가격표를 먼저 게시하지 않는다.
- 일반 회원·참가자의 필수 이용, 자기 정보 확인·정정, 제재 이의, 결제 해지에 추가 요금을 부과하지 않는 방향이다.
- 결제 실패는 안내·재시도·유예·제한 상태로 처리한다. 진행 중 대회 마무리와 데이터 내보내기를 무조건 막지 않는다.
- 사업자·판매자 표시, 실제 연락처, 세금/영수증, 가격·환불·해지·보관 정책, 결제 제공자 계약은 사업 주체의 실제 정보로 확정한다. 자동으로 사업자를 생성하거나 계약·요금을 확정하지 않는다.

## 외부 연동과 수익화 확인

2026-11-01 확인한 [Riot 일반 정책](https://developer.riotgames.com/policies/general)은 수익화에 등록 제품의 Approved/Acknowledged 상태와 무료 접근 계층 등 조건을 두며, 공식 실력 랭킹 대체/MMR·ELO 계산기 제한도 명시한다. 운영자 도구 요금으로 이름을 바꾸는 것만으로 조건 충족을 단정하지 않는다. GG HUB·개별 커뮤니티·내전 평가의 실제 승인 범위와 제품별 키 적용을 확인한 뒤 판매 범위를 확정한다. 현재 승인을 새로 확인한 것으로 기록하지 않는다.

카카오 알림 기반 휴대폰 봇은 기기 전원·알림 권한·앱 상태에 영향을 받는다. 이 방식의 실측 가용성·복구·지원 가능 범위를 검증하고 제공 조건에 반영한다. 자동 연결을 구현하기 전에는 사이트 설정 저장만으로 실제 폰 연결 성공을 표시하지 않는다.

## 실행 순서

1. **사용 가능한 운영 흐름:** 문의 접수/처리의 끊긴 이동 수정, 불확실한 접수 재확인, 개설 상태별 다음 행동, 도움말과 문의 접근성.
2. **개설부터 첫 활동:** 운영자 한 명의 실제 가입·개설·첫 회원·첫 모집 흐름과 실패 복구를 격리 환경/허용된 시험 사이트에서 검증.
3. **기존 계정·동적 방:** 확인된 소속과 설정 기반 폰 연결. 기존 두 사이트·네 방 회귀 확인.
4. **고객지원·운영 관리:** 문의 대화·담당·내 문의 상태, 장애·복구·사용량, 내보내기, 운영진 인수인계.
5. **제휴와 공동 활동:** 양측 합의·공유·모집·대회. 운영 기록은 지정 담당자·정정·회수 조건을 충족한 뒤 활성화.
6. **상용화 검증:** 승인 범위·판매 조건 확정, 결제 sandbox·구독/해지/환불·원가 검증, 제한된 초기 고객 운영 후 정식 판매.

각 단계는 실제 동작·권한·실패 복구·모바일 검증·배포 근거까지 남긴다. 결제 버튼 추가만으로 유료 서비스 완성으로 처리하지 않는다. MMR 새 산식은 기존 점수와 병렬 검증하고 진행 중 대회의 버전을 보존한다.

## 첫 적용 범위

이번 구현 단위는 1번의 문의·운영 안내다. 기존 문의 저장/감사/권한/보관 정책을 재사용한다. 새 과금, 외부 메시지 자동 발송, 운영 DB 수정, 계약 변경은 포함하지 않는다. 신규 기능과 미완료 항목은 후속 릴리스의 QA 근거로 갱신한다.
