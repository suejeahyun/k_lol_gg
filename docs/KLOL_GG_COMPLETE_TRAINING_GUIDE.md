# K-LOL.GG 전체 사용·운영 교육자료

기준일: 2026-08-31
사이트: https://k-lol-gg.vercel.app  
카카오봇 소스 기준 버전: `KLOL_KAKAO_BOT_V39_FAST_REGISTRATION_R1_2026_08_31`

이 문서는 일반 사용자, 운영진, 최고관리자가 사이트와 카카오톡 봇을 안전하게 사용하는 방법을 한 번에 교육하기 위한 운영 매뉴얼이다.

| 구분 | 상태 | 설명 |
|---|---|---|

| 실제 카카오톡 송수신 | 사용자 확인 필요 | 메신저봇R의 사진 이벤트와 방 권한은 실제 단말에서 최종 확인 필요 |

### 3.1 내전 참가와 결과 확인

1. `/progress`에서 진행 중 이벤트 또는 멸망전을 연다.
2. 상세 화면의 참가 신청 버튼을 누른다.
3. 요청되는 포지션·참가 정보를 입력하고 제출한다.
4. 신청 상태는 해당 상세 화면과 관리자 처리 결과에서 확인한다.
5. 종료 후 `/matches`에서 확정된 내전 결과를 확인한다.

### 3.2 Riot 계정 연결

1. 로그인 후 `/me/riot`로 이동한다.
2. 닉네임과 태그를 확인하고 연결 절차를 진행한다.
3. 동기화 버튼으로 티어와 최근 데이터를 갱신한다.
4. 검색 결과가 다르면 태그와 계정 소유 여부를 먼저 확인한다.

### 4.1 운영 시작 전 점검

1. 관리자 홈에서 오류와 미처리 접수를 확인한다.
2. `/admin/kakao/settings`에서 필요한 기능만 켜져 있는지 확인한다.
3. `/admin/logs/kakao`에서 최근 인증·서버 오류가 없는지 확인한다.
4. 사진 기능은 Blob 연결이 확인되기 전 활성 운영으로 간주하지 않는다.
5. 데이터 삭제·초기화·전체 재계산은 백업과 영향 범위를 확인한 뒤 실행한다.

## 5. 주의·경고·벤 정책과 처리

### 5.1 정책

- 주의 3회는 경고 1회로 전환한다.
- 경고 3회 누적 시 강퇴 검토 건을 만들고 관리자가 최종 결정한다.
- 일반 경고는 부여일부터 30일 안에 서로 다른 게임 사진 10장을 인증한다.
- 내전 경고는 부여일부터 30일 안에 서로 다른 게임 사진 15장을 인증한다.
- 한 판당 사진 한 장을 제출한다.
- 경고 사유는 카카오 공개 양식에 쓰지 않고 사이트 승인 창에서 비공개로 입력한다.

### 5.2 경고 등록 흐름

1. 운영진이 카카오에서 `/경고`를 보낸다.
2. 봇이 반환한 v1 양식의 대상 이름, 닉네임#태그, 경고 구분, 부여일, 근거 사진 수를 채운다.
3. 양식 전체를 같은 방에 보낸다.
4. 근거 사진 수가 1~3이면 30분 안에 같은 보낸 사람으로 사진을 한 장씩 보낸다. 사진이 없으면 0으로 제출한다.
5. 접수번호 `DS...`를 보관하고 `/경고현황 DS...`로 상태를 조회한다.
6. 관리자가 `/admin/discipline`에서 증빙을 확인하고 비공개 사유를 입력해 승인 또는 반려한다.
7. 승인되면 인증번호 `WR...`가 발급된다.

### 5.3 경고 차감 인증 흐름

1. 대상자가 `/경고인증 WR인증번호`를 보낸다.
2. 봇이 현재 수량과 남은 수량을 안내한다.
3. 30분 안에 한 판당 한 장씩 사진을 보낸다.
4. 세션이 끝났으면 같은 명령으로 이어서 제출한다.
5. `/경고현황 WR인증번호`로 진행률을 확인한다.
6. 목표 수량 도달 후 관리자가 사진을 확인하고 승인하면 연결된 경고 1건만 비활성화한다.

### 5.4 0~3장과 10·15장의 차이

| 구분 | 제출자·시점 | 수량 | 목적 |
|---|---|---:|---|
| 경고 부여 근거 | 운영진이 경고 접수 직후 | 0~3장 | 위반 사실 검토 자료 |
| 일반 경고 차감 | 승인된 대상자가 30일 안에 | 10장 | 일반 경고 해제 조건 인증 |
| 내전 경고 차감 | 승인된 대상자가 30일 안에 | 15장 | 내전 경고 해제 조건 인증 |

## 6. 종료된 내전 결과 접수

1. 진행자가 카카오에서 `/내전등록`을 보낸다.
2. 진행일, 진행자, 세트 수 2 또는 3, 내전 회차, 팀 밸런스 번호, 특이사항을 작성한다.
3. 양식 전체를 보내고 접수번호 `MR...`를 확인한다.
4. 30분 안에 1세트부터 결과 사진을 한 장씩 보낸다.
5. `/내전등록현황 MR접수번호`로 사진 수량과 상태를 확인한다.
6. 관리자가 `/admin/matches/submissions`에서 사진을 확인하고 `수기 등록 시작`을 누른다.
7. 기존 내전 등록 화면에서 선수, 챔피언, KDA, 승리팀을 입력해 최종 확정한다.

사진만으로 내전 결과가 자동 확정되지는 않는다. 중복 수기 등록은 연결 ID 제약으로 차단한다.

| 상세 조회 | `구인상세 12`, `상세 #12` |
| 마감 | `12ㅉ`, `#12ㅉ`, `12번 파티 마감` |

생성 후 봇이 준 양식을 복사해 이름을 추가·삭제한 뒤 양식 전체를 다시 보낸다. 기존 구인을 수정할 때는 반드시 `모집번호: #번호`를 유지해야 한다. 이 번호가 없으면 새 구인 또는 내전 양식으로 오인될 수 있다.

### 7.3 내전 구인

| 목적 | 명령 |
|---|---|
| 종목 선택 안내 | `/내전구인` |
| 협곡 | `/내전구인 협곡` |
| 칼바람 | `/내전구인 칼바람` |
| 증바람 | `/내전구인 증바람` |
| 날짜·시간 지정 | `/내전구인 협곡 2026-08-26 21:00` |
| 번호 지정 | 명령 끝에 `#3`처럼 번호 추가 |
| 현황·상세 | `/내전현황`, `/내전상세 3` |

협곡 내전 참가 명단을 수정할 때도 헤더의 `#번호`를 삭제하지 않는다. 내전과 스크림 모집은 매일 오전 6시에 자동 종료된다.

### 7.4 스크림 구인

| 목적 | 명령 |
|---|---|
| 양식 호출 | `/스크림구인` 또는 `/스크림모집` |
| 전체 현황 | `/스크림현황` 또는 `/스크림목록` |
| 상세 조회 | `/스크림상세 번호` |

우리 팀이 먼저 번호가 포함된 양식을 등록하고, 상대 팀이 같은 번호 양식에 정보를 추가한다. 모집 완료·취소 등 상태 변경은 봇이 안내하는 번호 명령을 따른다.

### 7.5 운영 관리 명령

| 명령 | 설명 |
|---|---|
| `/경고` | 경고 등록 양식 호출 |
| `/경고현황 DS접수번호` | 경고 접수 승인 상태 조회 |
| `/경고현황 WR인증번호` | 경고 차감 사진 진행률 조회 |
| `/인증 WR인증번호` | 일반 10장·내전 15장 사진 세션 시작 또는 재개. 기존 `/경고인증`도 지원 |
| `/사진취소` | 현재 진행 중인 사진 접수 취소 |
| `/경고인증완료 WR인증번호` | 완료 상태 안내 요청 |
| `/결과등록` | 종료된 2·3세트 내전 결과 접수 양식 호출. 기존 `/내전등록`도 지원 |
| `/결과현황 MR접수번호` | 내전 결과 사진·검토 상태 조회. 기존 `/내전등록현황`도 지원 |

### 7.6 운영 신청 양식

운영 신청은 항목명을 유지한 전체 양식을 보내면 봇이 유형을 판별해 사이트에 기록한다.

| 유형 | 반드시 포함할 항목 | 관리자 확인 위치 |
|---|---|---|
| 지인·디스코드 | 지인 이름, 지인 닉네임, 이용기간, 디스코드 닉네임 변경 | 운영 신청 > 지인·디스코드 |
| 건의 | 본인 이름 및 닉네임, 건의 사유, 건의 내용 | 운영 신청 > 건의 |
| 모임 | 주최자 이름 및 닉네임, 일자, 장소, 참여자 명단 | 운영 신청 > 모임 |
| 외출 | 이름 및 닉네임, 외출기간, 외출사유, 외출범위 | 운영 신청 > 외출 |

## 8. 사진 메시지가 텍스트와 분리될 때

텍스트 양식과 사진이 별도 메시지여도 괜찮다. 봇과 서버는 활성 접수번호, 방 이름, 보낸 사람, 30분 세션을 함께 확인한다.

- 반드시 양식을 보낸 같은 방에서 사진을 보낸다.
- 반드시 같은 카카오 표시 이름으로 보낸다.
- 사진은 한 장씩 순서대로 보낸다.
- 30분이 지나면 상태 명령 또는 인증 명령으로 세션을 다시 연다.
- PNG, JPG, WebP만 사용하며 원본 한 장은 3MB 이하로 준비한다.
- 여러 명이 동시에 제출할 때 표시 이름이 같은 경우 혼선을 피하도록 운영진이 순서를 나눈다.

## 9. 접수 상태와 오류 대응

| 표시 | 의미 | 다음 행동 |
|---|---|---|
| `PENDING_REVIEW` | 관리자 검토 대기 | 관리자 사이트에서 승인·반려 |
| `AWAITING_UPLOAD` | 사진 업로드 대기 | 같은 방·보낸 사람으로 사진 전송 |
| `DS...` | 경고 접수번호 | `/경고현황 DS...` |
| `WR...` | 경고 차감 인증번호 | `/경고인증 WR...` 또는 `/경고현황 WR...` |
| `MR...` | 내전 결과 접수번호 | `/내전등록현황 MR...` |
| 이미 접수된 양식 | 중복 차단 정상 동작 | 기존 접수번호 사용 |
| 사진 저장 중 오류 | 저장소 또는 서버 설정 오류 | 카카오 로그와 Blob 연결 확인 |
| 기능이 중지됨 | 관리자 기능 스위치 꺼짐 | `/admin/kakao/settings` 확인 |

문제 발생 시 운영진은 시간, 방 이름, 보낸 사람, 입력 명령, 접수번호, 봇 응답을 기록하고 `/admin/logs/kakao`와 대조한다. 인증값이나 토큰 원문은 채팅·스크린샷·문서에 남기지 않는다.

## 10. 배포·보안·저장소 운영

- 봇 소스에는 비밀값을 하드코딩하지 않는다.
- 메신저봇R DataBase에는 `KLOL_KAKAO_RECRUIT_SECRET`, `KLOL_KAKAO_OPENCHAT_SECRET`, `KLOL_KAKAO_SEARCH_PLAYER_SECRET`을 저장한다.
- Vercel의 `BLOB_READ_WRITE_TOKEN`은 카카오봇에 넣지 않는다. Vercel 프로젝트의 비공개 Blob 연결 또는 OIDC에서만 관리한다.
- Google Drive는 사진 저장소로 사용하지 않는다.
- 비공개 사진은 관리자 인증 프록시를 통해서만 조회한다.
- 사진 메타데이터의 만료 기준은 90일이며, 자동 삭제 스케줄이 연결되기 전에는 수동 점검한다.

이전 비공개 Blob 검증에서는 실제 저장 성공 기록이 있다. 다만 V38 배포에서는 환경 연결 상태가 달라질 수 있으므로 운영 전용 테스트 접수로 저장·관리자 열람·삭제 가능성을 다시 확인한다.

## 11. 운영 체크리스트

### 매일

- 관리자 홈의 미처리 접수와 오류 확인
- 카카오 처리 로그에서 반복 오류 확인
- 진행 중 구인·스크림·내전 번호와 상태 확인
- 경고·내전 결과 접수의 사진 수량과 검토 상태 확인

### 변경 전

- 변경 대상과 영향 범위 기록
- DB 마이그레이션·환경변수 필요 여부 확인
- 민감 데이터 백업과 복구 방법 확인
- 기능 스위치 기본값 확인

### 변경 후

- 배포 상태와 커밋 확인
- 사이트 데스크톱·모바일 핵심 화면 확인
- 카카오 `/봇버전`, `/도움말`, 텍스트 양식 호출 확인
- 사진 1장 실제 저장·관리자 열람·중복 차단 확인

## 12. 사용자가 마지막으로 직접 확인할 항목

다음 항목은 실제 카카오톡과 Vercel 저장소 권한이 필요하므로 운영 단말에서 최종 확인한다.

1. Vercel Blob 연결을 고친 뒤 `/경고` 근거 사진 1장을 보내 성공 응답을 확인한다.
2. 같은 사진을 다시 보내 중복 사진 차단을 확인한다.
3. 관리자 `/admin/discipline`에서 비공개 사진을 열어 본다.
4. 테스트 경고를 승인한 뒤 `/경고인증 WR...`로 일반 10장 또는 내전 15장 진행률을 확인한다.
5. `/내전등록`으로 2장과 3장 접수를 각각 완료하고 `/admin/matches/submissions`에서 사진 순서를 확인한다.
6. `수기 등록 시작` 후 기존 내전 등록 폼에 연결되고, 최종 저장 후 중복 등록이 차단되는지 확인한다.
7. `/봇버전`이 `KLOL_KAKAO_BOT_V39_FAST_REGISTRATION_R1_2026_08_31`인지 확인한다.
