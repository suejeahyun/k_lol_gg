# V2 역할 분배와 통합 규칙

이 프로젝트는 한 대화에서 총괄하되, 독립 검토가 가능한 작업은 담당 역할로 병렬 분배한다.

## 담당 역할

| 역할 | 책임 | 필수 산출물 |
|---|---|---|
| 총괄·통합 | 요구사항 분해, 우선순위, 담당 배정, 충돌 해결, 최종 판정 | 통합 계획, 상태 보고, 다음 작업 |
| V1 보존 | 블루-블랙 기준점, 최신 보안 수정 보존, 복원 후보 검증 | 기준 SHA, 변경 목록, 복구 절차, 검증 기록 |
| V2 아키텍처·기능 | 기능 계약, 도메인 경계, 화면·API·데이터 흐름 | 기능 명세, 구현, 단위·통합 검사 |
| 제품 디자인 | 정보 구조, 디자인 토큰, 반응형 화면, 이미지 자산 | 화면 규칙, 접근성 기준, 자산 출처·해시 |
| QA·보안 | 회귀, 접근성, 성능, 권한·개인정보, 빌드 검증 | 재현 가능한 검사 결과와 남은 위험 |

## 속도 우선 작업 흐름

기능 범위와 최종 품질 기준은 줄이지 않고, 반복 공정만 제거한다.

1. 이미 확정한 V1 사용자 73개·관리자 81개 카탈로그를 기준으로 사용하며 같은 화면을 다시 조사하지 않는다.
2. 조사 담당은 다음 웨이브의 모호한 계산·권한·데이터 규칙만 먼저 확정한다.
3. 구현 담당은 서로 다른 namespace와 경로를 맡아 도메인·API·화면을 병렬 구현한다.
4. 공통 transaction session guard, HTTP 문제 규약, idempotency receipt, audit/outbox, 목록·상세 UI를 재사용한다.
5. 슬라이스 중에는 변경 범위의 lint·타입·단위 테스트만 실행한다. 데이터 손상 위험이 있는 migration·집계·멱등성은 focused PostgreSQL 계약까지 즉시 확인한다.
6. 총괄은 focused gate가 끝난 작은 커밋을 바로 메인에 통합한다. 전체 build·HTTP 행렬·브라우저·스크린샷은 반복하지 않는다.
7. 웨이브가 끝날 때 상태 문서와 동등성 ledger만 한 번 갱신한다. 역할별 중복 보고서와 임시 스크린샷은 만들지 않는다.
8. 모든 기능이 합쳐진 S14에서 전 페이지 DB/HTTP/브라우저·접근성·반응형·성능·복구·비밀정보 검사를 한 번에 수행한다.

## 검사 게이트

### 슬라이스 fast gate

- 변경 파일 lint와 TypeScript 검사
- 변경 도메인의 순수 계산·권한·DTO·상태 전이 테스트
- migration·집계·금액·멱등성처럼 손상 전파 위험이 있는 변경만 focused PostgreSQL 계약
- `git diff --check`와 운영 데이터·비밀정보 미사용 확인

### S14 final gate

- 전체 lint, 타입, 단위·계약 테스트와 production build
- fresh/upgrade/idempotent migration, 전체 DB·HTTP 권한 행렬과 복구 테스트
- 모든 canonical/legacy 사용자·관리자 경로의 정상·빈·오류·권한 상태
- 모바일·데스크톱, 키보드, 스크린리더, 감소된 모션, 가로 overflow
- 자동 스크린샷 inventory, console/pageerror 수집, 성능 예산과 비밀정보 검사
- 알려진 중요 결함과 미완료 기능 0, 깨끗한 Git 상태 확인

슬라이스 fast gate 통과는 구현 후보라는 뜻이며, 최종 검증 완료나 운영 반영을 뜻하지 않는다.

## 배포 경계

- V1과 V2는 별도 저장소·Vercel 프로젝트·환경 변수·데이터 저장소를 사용한다.
- V2가 기능 동등성, 보안, 접근성, 성능, 복구 훈련을 모두 통과하기 전에는 운영 별칭을 전환하지 않는다.
- 운영 배포·데이터 변경·별칭 전환은 이 개발 흐름의 자동 권한에 포함하지 않는다.
