## 변경 내용

### 원인

기존 협곡 내전 파서는 참가자 정보를 `/` 기준으로 나눴다. 실제 입력 `2.김동휘/M/M/Mid all`은 주라인 `Mid`와 부라인 `all` 사이 슬래시가 빠져, `Mid all` 전체를 주라인으로 읽었다. 허용되지 않은 주라인으로 판정돼 양식 전체가 `INVALID_FORM`, HTTP 400으로 종료됐다.

### 수정

- 내전 참가자 행 전용 파서를 추가했다.
- 정상 입력 `1.지오/G/E/AD/Mid`는 주라인 `ADC`, 부라인 `MID`로 처리한다.
- 제한된 입력 `2.김동휘/M/M/Mid all`은 주라인 `MID`, 빈 부라인으로 복구한다.
- 복구는 공백으로 붙은 정확히 두 개의 유효 포지션 별칭에만 적용한다.
- 참가자가 없는 3~10번 행은 빈 슬롯으로 허용한다.
- `없음`, `-`, `미정`은 부라인에서만 빈값으로 처리한다.
- 그 밖의 미지정 포지션 토큰은 추정하지 않고 계속 거절한다.
- 기존 V1 화면 문구, 출력, 사용 순서와 단일 5초 HTTP 요청은 유지한다.

## 사용자 영향

- 실제 제보와 같은 `Mid all` 입력이 슬래시 하나 누락됐다는 이유만으로 전체 접수를 막지 않는다.
- 빈 3~10번 슬롯을 채우지 않아도 정상적인 전체 양식으로 처리한다.
- 정의되지 않은 포지션은 자동 변환하지 않아 잘못된 라인 저장을 막는다.
- 서버 수정은 배포됐지만 휴대폰 현장 확인 전이므로, 문제 입력이 실제 방에서 정상 접수되는지는 후속 확인이 필요하다.

## 롤백 방법

DB migration이나 데이터 일괄 변경은 없다. 배포 뒤 이상이 확인되면 서버를 직전 확인된 R4 릴리스로 되돌리고, 휴대폰 설치본도 직전 확인 파일로 교체한다. 기존 신청 데이터나 receipt는 삭제하지 않는다.
