# 카카오 양식의 순서와 문장부호가 달라도 안전하게 확인하도록 개선

## 적용 상태

- 소스 반영: 현재 커밋 전 작업 트리에서 확인
- 로컬 집중 테스트: 97건 중 pass 96, todo 1, fail 0
- 전체 검사: `npm run check` 통과
- 최종 독립 P1 재검사: 서버 16/16, 휴대폰 17/17, 전체 계약 344/344, TypeScript·대상 ESLint·Rhino ES5 통과
- 운영 서버 배포: 미진행
- MessengerBot R 휴대폰 설치: 미확인
- 실제 카카오 구인구직방·고객센터방 E2E: 미확인

운영 반영 시점은 아직 정해지지 않았다. 별도 운영 공지가 나오기 전에는 사용자가 설치나 입력 방식을 바꿀 필요가 없다.

## 변경 내용

### 파티 양식

- 참가자 행의 순서가 달라지거나 전각 숫자·문장부호, 카카오 이스케이프가 포함돼도 같은 슬롯으로 읽도록 개선했다.
- 시작 시간과 게임 정보가 여러 줄이어도 다음 필드와 구분해 읽는다.
- 값이 있는 행, 사용자가 빈칸으로 만든 행, 양식에서 빠진 행을 구분한다. 빠진 행은 기존 값을 유지하고, 명시적으로 빈 행만 기존 값을 비운다.
- 서로 다른 값의 중복 슬롯, 중복 라벨, 한 줄에 합쳐진 슬롯은 임의로 덮어쓰지 않고 입력 오류로 처리한다.
- 수정 양식의 제목이나 정원은 DB에 저장된 모집 제목·정원을 바꾸지 않는다.
- 저장 내용이 이전과 같으면 revision, 저장, audit, outbox를 추가하지 않고 요청 receipt만 완료한다.

### 고객센터 양식 4종

- 지인·디스코드, 건의, 모임, 외출 양식의 필드 순서가 달라도 처리한다.
- 필수 항목이 비어 있어도 양식 후보를 서버에 전달해, 빠진 필드명을 정확히 안내할 수 있게 했다.
- 같은 값이 반복된 필드는 한 번만 사용하고, 서로 다른 값이 반복되면 해당 필드를 고쳐 다시 보내도록 막는다.
- 안내, 주의, 예시, 감사 문장이 마지막 입력값에 섞이지 않도록 꼬리말을 분리한다.
- 일반 대화와 단순한 필드명 언급은 접수 양식으로 취급하지 않는다.
- `<지인>`, `<건의>`, `<모임>`/`<정모>`, `<외출>` 및 HTML entity 제목은 한 행 전체일 때만 양식 후보로 본다. 기존 범위의 번호·불릿 제목은 허용하지만, `공지에 <외출>이라고 적어 주세요.` 같은 문장 속 인용은 전송하지 않는다.

### 휴대폰 봇 경계

- V1의 문구와 사용 순서를 유지한다.
- 한 번의 입력은 서버에 한 번만 전송하며 HTTP 제한시간은 기존 5초를 유지한다.
- 생성된 설치본의 코드 버전은 `KLOL_KAKAO_BOT_V40_SITE_FIRST_NO_CODES_R4_2026_09_11`이다.
- 설치본 SHA-256은 `6B991CE28AD00FE4216419F2EA38FFB69E9C064AD00722139AEA2839A8A2FFB0`이다.

## 사용자 영향

- 모바일 복사·붙여넣기 과정에서 숫자, 점, 줄바꿈이 바뀌어도 정상 양식이 거절될 가능성이 줄어든다.
- 양식 일부가 빠졌을 때 기존 파티 참가자가 의도치 않게 삭제될 위험이 줄어든다.
- 고객센터 양식에 빠진 값이나 충돌하는 중복값이 있으면 어떤 필드를 고쳐야 하는지 안내할 수 있다.
- 이미 같은 내용이 반영된 재전송은 불필요한 변경 기록을 만들지 않는다.

## 알려진 제한과 위험

- 실제 MessengerBot R 휴대폰 설치와 두 카카오방 송수신은 아직 확인하지 않았다.
- 같은 방의 다른 사용자 수정·마감과 다른 방 변경 차단의 PostgreSQL 실계약 테스트 1건은 TODO다.
- 운영 배포 전이므로 현재 운영 카카오봇에 반영됐다고 안내하면 안 된다.
- 입력 허용 범위가 넓어져 새로운 일반 대화 오분류 가능성은 남는다. 배포 뒤 결과 코드만 익명 집계해 확인해야 한다.

## 구현 난이도·우선순위·기대효과

| 항목 | 난이도 | 우선순위 | 기대효과 | 부작용·관찰 항목 |
|---|---:|---:|---|---|
| 파티 tri-state와 DB 기준 병합 | 높음 | P0 | 의도하지 않은 참가자 삭제와 제목·정원 변조 방지 | 슬롯 오분류, 기존 참가자 보존 여부 |
| 문장부호·순서·다중 줄 허용 | 중간 | P0 | 카카오 복사·붙여넣기 실패 감소 | 일반 대화 오분류율 |
| 중복 충돌 진단 | 중간 | P0 | 마지막 값 임의 덮어쓰기 방지 | 사용자의 수정 재전송률 |
| 고객센터 4종 누락 전달·꼬리말 격리 | 중간 | P0 | 누락 필드 안내 개선, 안내문 혼입 방지 | 유형별 누락·충돌 비율 |
| 의미상 no-op 억제 | 중간 | P1 | revision·audit·outbox 잡음 감소 | receipt 완료율, no-op 비율 |

성공 여부는 정상 양식 성공률, `INVALID_FORM` 비율, 재전송률, timeout 비율, 처리시간 p50·p95, no-op 억제 건수로 판단한다. 운영 기준선이 없어 목표 수치는 제안하지 않았으며, 개인정보나 양식 원문은 KPI에 포함하지 않는다.

```text
[카카오 구인·고객센터 양식 입력 개선 예정]

카카오에서 양식을 복사하고 작성할 때 생기는 문장부호와 줄바꿈 차이를 더 안정적으로 처리하도록 개선했습니다.

변경 내용
- 참가자 행의 순서가 달라지거나 전각 숫자·점, 카카오 이스케이프가 포함돼도 같은 항목으로 확인합니다.
- 양식에서 빠진 참가자 행은 기존 값을 유지하고, 직접 빈칸으로 만든 행만 비웁니다.
- 중복된 항목에 서로 다른 값이 있으면 임의로 저장하지 않고 다시 확인하도록 안내합니다.

- 고객센터 제목은 독립된 한 줄일 때만 양식으로 인식하며, 문장 속에 제목 표기를 인용한 일반 대화는 전송하지 않습니다.
- 필수 항목이 빠지면 고쳐야 할 항목을 구분해 안내합니다.
- 안내문과 예시가 마지막 입력 내용에 섞이지 않도록 개선했습니다.

사용자 영향
- 기존 V1 양식과 사용 순서는 바뀌지 않습니다.
- 별도 운영 공지가 나오기 전에는 설치나 입력 방식을 변경할 필요가 없습니다.

적용 상태
- 소스와 로컬 검사를 통과했습니다.
- 운영 서버 배포와 실제 휴대폰·카카오방 검증은 아직 진행 전입니다.
```
