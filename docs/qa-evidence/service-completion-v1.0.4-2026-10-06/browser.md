# 실제 브라우저 확인

2026-10-06. CUA in-app browser, Windows 호스트의 합성 PostgreSQL fixture. 실제 회원 데이터·운영 신청·운영 계정은 쓰지 않았다. 해상도는 브라우저 viewport이며 실물 휴대폰 검증이 아니다.

## 순서별 실행

1. **홈/탐색:** 1280px에서 홈 제목→랭킹→과업→소식→내 활동→기록 순서와 main 하나, 가로 넘침 없음 확인. 생성 케이틀린 이미지/배경 유지. fixture 랭킹은 최소 참여 미충족 빈 상태로 집계 기준을 표시했다. 전체 검색을 열고 `동전` 검색→`진영 정하기` 결과, Escape 닫기와 검색 버튼 포커스 복귀 확인.
2. **로그인:** 실제 화면에서 관리자 링크 중복과 초기 일반 안내문을 발견해 제거했다. 새 빌드의 390px 화면에서 관리자 링크 하나·빈 상태 박스 없음·가로 넘침 없음. 빈 입력 제출은 실제 서버 오류를 표시하고, 합성 계정 정상 로그인은 `next=/applications`로 복귀했다. 비밀번호 화면은 실제 경고 한 곳과 세 필수 입력을 확인했으며 비밀번호를 변경하지 않았다.
3. **참가:** 저장된 1회차를 본 참가/미드에서 예비/탑으로 수정. 저장 중 비활성→완료 메시지→본 참가 0/10, 예비 1, 목록의 주 탑/부 서폿·예비 반영 확인. 390px 가로 넘침과 끊어진 aria-describedby 없음. 초기 상시 새로고침 설명을 추가 발견해 후속 삭제했다. 실제 conflict 오류 안내는 유지한다.
4. **파티:** 31개 참가 가능/1개 정원 마감의 합성 자료에서 현재 인원·정원·예비·마감 표시를 확인했다. 첫 파티의 명단 조회 명령 버튼을 눌러 실제 시스템 clipboard가 `구인상세 1`인 것을 확인했다. 카카오 방 전송/봇 ACK는 실행하지 않았다.
5. **이벤트:** 없는 이름 검색→빈 결과와 복구 링크→필터 초기화→기존 목록 복귀. query의 빈 status/format 때문에 오류가 나지 않았다.
6. **멸망전:** 목록의 완료/주장 선정 상태 확인. 방식 선택의 BO1/BO3가 같은 이름으로 보이는 것을 실제 발견했다. 기존 정확한 도메인 label을 재사용하는 후속 수정과 원본 FAIL→수정 PASS 회귀를 `core-after.md`에 연결한다.
7. **팀:** 실력별 도구의 참가자 선택→포지션 단계, 0/10·입력 초기화·기록 없음/계산 비활성 상태 확인. 이번 브라우저에서 실력별 10명 선택·저장 전체를 재실행하지는 않았다. 관련 도메인/DB 실행과 구분한다.
8. **무작위 팀:** 합성 이름 10개 입력→팀 섞기→중복 없는 5:5 결과와 결과 영역 포커스→초기화 후 빈 결과 복귀를 실제 확인했다.
9. **경기 제출:** 320px에서 모든 필수 입력에 label이 있고 가로 넘침 없음. 제목·주최자·날짜 입력→새 접수 생성→2장 중 0장→합성 PNG 한 장 등록→1/2→두 번째 등록→2/2·검토 대기·이미지 제출 완료까지 수행했다. 첫 file chooser 선택은 AX가 삽입한 공백과 DOM label 차이로 도구 selector가 실패했다. 실제 DOM label을 읽고 정상 업로드했으며 제품 업로드 오류로 세지 않는다. 실제 OCR 정확도는 미검증이다.
10. **기록/커뮤니티/연동:** 플레이어·랭킹·갤러리·징계·문의·Riot·카카오 도움말·설치·비밀번호 페이지를 390px에서 순서대로 확인. main 하나·가로 넘침 없음·끊어진 aria-describedby 없음. 랭킹 첫 관측은 로딩 상태였고, 별도 로딩 종료 후 시즌·최소 참여·빈 통계 상태와 기준을 확인했다. 실제 연동/메시지 전송/OS 설치로 확대하지 않는다.
11. **관리자:** 합성 관리자 로그인→`next=/admin/users` 복귀. 계정 검색으로 합성 승인 대기 계정 1개 조회, 390px 가로 넘침 없음. MMR의 재계산·조정·현재 보정 버튼과 조회 화면을 확인했으며 운영 MMR을 실행하지 않았다. 화면에서 발견한 S01 등의 구현 코드와 기본 상태의 내부 설명은 마지막 후속 정리 대상에 포함했다.
12. **승인 대기:** 합성 대기 계정으로 다시 로그인→참가 폼을 제공하지 않고 제한 상태와 내 계정/문의 링크 제공. 일반 승인 계정의 신청 수정과 구분해 확인했다.

## 증거와 해석

- [홈 데스크톱](home-desktop.jpg), [로그인 모바일](login-mobile.jpg), [제출 완료](submission-complete.jpg), [화면별 DOM 관측](browser-layout.json).
- 첫/두 번째 fixture의 108페이지·169조건 HTTP는 각각 별도 JSON에 있다. 페이지가 열린 것을 저장 완료 검증으로 세지 않는다.
- 위 실제 실행은 마지막 관리자 장식·신청 초기 설명·멸망전 필터 후속 수정 전까지의 결과다. 해당 후속 수정 이후 확인은 최종 검증/운영 문서에 추가하며 이전 실행을 새 결과로 둔갑시키지 않는다.
- 키보드는 검색 Escape와 포커스, 기존 회귀의 랭킹/팀 동작을 구분했다. 실제 스크린리더·신규 이용자 실험·OS 모션 감소 설정 전환은 미실행이다.

## 마지막 후속 변경 이후 확인

최종 check로 생성한 빌드와 새 합성 fixture에서 [전체 108페이지/169조건 HTTP](release-http.json)를 다시 통과했다. 실제 CUA에서는 멸망전 8개 option의 이름이 모두 구분되고 단판 선택이 `format=FULL_ROUND_ROBIN_BO1`로 반영되는 것을 확인했다. 초기 label selector의 exact 문자열 차이는 DOM 이름을 읽은 뒤 실제 select로 접근했으며 화면 오류가 아니었다.

최종 관리자 로그인이 계정 목록으로 복귀하며 `S01` 장식이 사라진 것을 확인했다. 계정 상세와 관리자 멸망전은 내부 트랜잭션/기본 조작 설명·빈 상태 상자가 없고 실제 제목·작업 입력이 유지된다. 최종 사용자 로그인→신청 복귀 후 상시 새로고침 설명이 없고 신청 입력이 남는다. 이 후속 화면도 390px 가로 넘침이 없었다. [단판 필터 화면](destruction-filter-final.jpg).
