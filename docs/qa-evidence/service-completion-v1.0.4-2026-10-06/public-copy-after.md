## 설치 흐름에서 재현한 오류와 수정

`install-actions.tsx`의 실제 click handler/effect를 합성 native 이벤트와 지연 Promise로 실행했다. 수정 전 `tests/install-actions-recovery.test.mjs`는 다음 4건 모두 실패했다.

1. `prompt()` 거절을 처리하지 않아 처리되지 않은 Promise와 복구 없는 화면이 남음.
2. 요청 중에도 버튼이 활성화되어 같은 native prompt를 중복 호출함.
3. `beforeinstallprompt`가 초기 animation frame보다 먼저 오면 뒤늦은 환경 확인이 준비 상태를 덮어씀.
4. `appinstalled`가 먼저 온 뒤 늦은 choice가 도착하면 설치 완료가 취소 상태로 되돌아감.

수정은 즉시 요청 잠금, 한 번 사용한 이벤트 폐기, 오류와 브라우저 메뉴 복구, 조건부 초기 상태 설정, 완료 상태 보호로 한정했다. `accepted`는 설치 요청 전달, `appinstalled`/이미 독립 앱 환경은 설치 확인 상태로 구분했다. 새 `beforeinstallprompt`가 오면 다시 시도할 수 있다. 사용자 선택 없이 설치 창을 열지 않는다.

브라우저 이벤트 한 건의 prompt는 한 번만 사용하고 사용자 행동에서 호출한다는 기준을 확인했다. [MDN prompt](https://developer.mozilla.org/en-US/docs/Web/API/BeforeInstallPromptEvent/prompt), [MDN appinstalled](https://developer.mozilla.org/en-US/docs/Web/API/Window/appinstalled_event). 실제 휴대폰 설치는 이 합성 검증으로 대체하지 않았다.

## 전체 검사에서 발견된 구 문구 계약 후속 확인

전체 검사 중 `riot-adapter-contracts.test.ts`가 이전의 “현재 Riot 연동은 해제된 상태”라는 장문만 기대하여 실패했다. 현재 제품에는 `link.status === "CONNECTED"` 판정과 비연결 상태의 “연동 해제됨 · 다시 연결 가능”이 있고, RSO가 아닌 연결의 “공개 전적 연결 · Riot 계정 소유권 미인증”도 남아 있었다. 제품 기능 오류가 아닌 승인된 문구 축약과 구 테스트 기대값의 불일치로 분류했다.

제품 소스는 변경하지 않았다. 해당 테스트가 비연결 상태에서만 복구 문구를 출력하는 조건, `RSO_VERIFIED`와 공개 전적 연결의 구분, 상태 전달, 직접 연결/해제 API와 revision 전달, RSO 준비 전 비활성화, If-Match를 함께 검사하도록 강화했다. 기존 스키마·마이그레이션·feature flag·합성 adapter 동작·쿼리 검증은 그대로 유지했다.

## 실제 로그인 화면 재검토의 추가 발견

root의 실제 브라우저 재검토에서 소스 1차 정리에서 놓친 두 항목을 확인했다. `/login/page.tsx`의 관리자 로그인 링크가 `UserLoginForm` 내부 링크와 중복되고, `UserLoginForm`의 메시지 없는 기본 화면에 승인 대기·거절·이용 제한 계정의 로그인 가능 여부를 설명하는 장문이 남아 있었다. 둘 다 정적 반복 부가 설명/중복 진입으로 분류했다. root가 페이지 중복 링크를 제거하고 로그인 메시지는 실제 실패·성공 결과가 있을 때만 표시하도록 수정했으며, 후속 독립 소스 읽기에서도 확인했다. 계정 상태별 로그인 기능은 유지했다.

인증 컴포넌트를 다시 읽은 결과 `/account/password/page.tsx`의 전체 기기 재로그인 경고와 `AccountPasswordForm`의 기본 메시지가 같은 내용을 두 번 표시하는 항목도 추가로 찾았다. root가 필수 경고를 폼 한 곳에 남기고 상단 중복을 제거했으며 후속 소스 읽기에서 확인했다. 이 하위 재검토에서는 제품 소스나 테스트를 변경하지 않았다. root의 focused lint 통과 및 실제 브라우저 확인은 통합 점검에 기록한다.

보존 근거도 다시 확인했다. `postgres-account-repository.ts:1133`의 기존 플레이어 존재 여부에 따라 `PENDING`/`APPROVED`가 나뉘고 기존 연결 요청을 따로 생성하므로 Signup의 신규/기존 선수 구분은 필수다. 비밀번호 복구는 계정 일치 여부를 노출하지 않는 동일한 관리자 검토 접수 응답(`postgres-account-repository.ts:1374`)을 사용하므로 비공개·검토 절차도 보존한다. 나머지 계정/관리자 인증 컴포넌트의 정적 문구는 입력 제약·동의·Riot ID 변경 연동 해제 경고로 분류되며, 이번 읽기 재검토에서 추가 삭제할 선택적 설명은 발견하지 못했다.

## 마지막 독립 소스 재검토

공개 route와 계정/인증/공개 Riot/문의 컴포넌트 **90개 TSX**를 TypeScript AST로 읽어 정적 `p`/`small`/`span`/`em` 후보 **169개**를 추출하고, 조작 교습·홍보 문구와 내부 구현 용어를 `rg`로 추가 조회했다. 출력 후보는 실패·복구, 실제 상태/집계, 입력 제약, 개인정보/정책, 사용자가 선택해서 여는 도움말 본문과 장식으로 구분했다. 숫자·BLUE/RED·MVP·통계 분모·미수집·갱신·브라우저 저장 조건은 실제 정보라 남겼고, 캐러셀의 `sr-only` 키보드 설명도 제거 대상에서 제외했다.

새로운 중대 동작 문제는 발견하지 않았다. 잔여 장식 2개는 root에 전달했다: `player-riot-profile.tsx:93`의 `RIOT MATCH INSIGHTS`, `team-balance-recommendations-panel.tsx:37`의 `PICK · BAN`. 모두 실제 수치/권한/상태가 아닌 제목·탭과 중복되는 장식이므로 root가 정확히 해당 span만 제거했고 focused ESLint를 통과했다. 이후 독립 읽기에서 두 문자열이 실제로 없음을 확인했다. 이 하위 검토에서는 제품 코드를 수정하지 않았다.

검토한 공개 영역의 이번 변경 범위에서 새로운 중대 오류나 명확한 과업 방해 요소, 남은 반복 홍보·장식·구현 설명을 추가로 발견하지 않았다. 유지한 문구는 기능 상태·실패 복구·제약·동의/정책·실제 콘텐츠·집계 의미와 사용자가 선택한 도움말 본문이다. 이 결론은 위 소스 검토와 실행 검증의 범위에 한정한다. 동적 조건의 모든 조합, 실기기 설치, live 외부 연동을 AST 검사만으로 완료했다고 판정하지 않으며 이 경계들은 통합 검증에서 별도 구분한다.
