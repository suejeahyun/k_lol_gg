# 확인창 해제 후 실제 조작 검증 · 2026-10-07

대상은 소스0716a60b의 최적화 서버, 새 일회성 PostgreSQL, 합성 SUPER_ADMIN/ACCOUNT와 합성 파일이다. 원본 ready/TOTP/stderr는 ignored .tmp에만 보관한다. 운영 회원 자료를 시험 변경하지 않는다. 제품 후속 변경과 실제 실행한 빌드 시점을 구분한다.

## 운영에서 해소한 조작 제약

사용자가 이전 로컬 확인창 탭을 닫은 뒤 운영 홈에서 최다 참여→최다 MVP 직접 선택, Left 키로 최다 참여 복귀, 승률 선택을 실제 확인했다. 제목·01/02/03 표시·전체 순위 링크가 일치한다. [결과](production-ranking-interaction.json), [화면](production-ranking-interaction.png). 운영 MMR 화면의 로그인은 확인됐으나 실제 역할은 ADMIN으로 SUPER_ADMIN 전환 권한이 없다. 권한 우회나 임의 승격을 하지 않았다.

## 1. 미디어 목록·공개 연결

- 갤러리 pageSize=1에서6페이지, 다음/이전 이동을 확인했다. 초안을 선택하고 적용하지 않은 채 다음으로 가면 적용된 전체 상태로 복원된다.
- 게시됨 필터 적용 뒤1/2→2/2 이동에 status=PUBLISHED/pageSize=1 유지. 전체 적용은 status= 빈 값으로 제출되지만 정상 목록1/6으로 복원된다.
- page=0은 조건 오류와 목록 초기화를 표시한다. 초기화→게시된 상세→공개 화면 보기→같은 제목의 공개 상세 로딩 완료를 확인했다. 시드 갤러리 자산은 합성 DB 메타데이터만 있어 이미지 오류 대체 상태가 보인다. 이를 실제 파일 전송/이미지 표시 통과로 세지 않는다.
- 하이라이트에 합성 초안1개를 실제 생성하여2페이지를 준비했다. 다음/이전·미적용 초안 선택의 초기화·초안 적용·전체 복원을 확인했다. YouTube 주소는 입력 검증용이며 외부 영상 재생은 실행하지 않았다.

## 2. 참가 전 이벤트 설정

새 합성 이벤트를 실제 생성하고 참가0명 PLANNED에서 이름·한국시간을 저장했다. 제목 변경, 키보드로 시작18:00→18:01/마감20:00→20:01 변경 후 저장, 새로고침 뒤 제목·시간 유지, 취소 후 편집 폼 제거, 이전 단계 복구 후 내용·편집 폼 복원을 확인했다. 변경 버전은 최종6이다. [복구 화면](event-settings-restored.png).

datetime-local의 도구 fill은 DOM 값만 바꾸고 controlled React 값이 저장되지 않는 현상이 있었다. 이를 제품 오류로 단정하지 않고 실제 Arrow 키로 다시 검증했다. 시작 연도를2027로 바꾸자 ‘모집 마감은 시작보다 늦어야 합니다’가 나타났고,2026 복원 후 분을 변경하자 올바르게 저장됐다. .000 형식 도구 입력 거부도 실행 환경 오류로 분리한다.

실제 상세의 POSITION·PLANNED 등 내부 영문 코드 노출을 새로 발견했다.1.0.8 후속에서 기존 한국어 표시 함수를 재사용하여 보완하며, 이 문서의1.0.7 화면을 수정 후 결과로 세지 않는다.

## 3. 해소 과제 제출·검토

합성 계정의 경고와 해소 과제를 관리자 화면에서 생성했다. 계정 화면에서 서로 다른 합성 PNG 10장을 선택하여 10/10 검토 대기, 새로고침 유지, 관리자 증빙 10개 표시를 확인했다. 관리자의 검토 메모 저장·과제 승인 후 경고 종료/변경 버전1, 당사자 화면의 승인 완료·10/10·진행 경고0을 확인했다. [승인 화면](owner-task-approved.png). 실제 회원의 징계나 자료는 변경하지 않았다. 이 실행은 정상 업로드 수명주기이며 네트워크 실패·READY 재개는 기존1.0.6 actual-handler 근거와 분리한다.

## 4. 저장 팀 → 경기 접수 → 검토안

실제 팀 목록에서 저장된 ‘저녁 내전’ 상세로 이동하고 ‘이 팀으로 경기 결과 접수’를 선택했다. 합성 경기 접수에 이미지2장을 등록하자 검토 대기·2/2로 전환됐다. 관리자가 현재 팀 배치를 불러오면 두 게임의20행에 저장 버전7의 블루1/2/8/4/10, 레드6/7/3/9/5 배치가 이어졌고 모든 원본 대조는 미확인이었다.

연결 시즌, 게임별 승리 팀, 각 게임의 서로 다른 챔피언10명, 합성 K/D/A를 입력하고20행을 확인했다. 확인 전 저장/승인이 차단되고, 저장 후 변경 버전3·새로고침 뒤20행/BLUE·RED/승인 활성화가 유지됐다. 첫 행 킬 수정은 원본 대조와 승인을 다시 잠갔으며 재확인·저장 후 버전4·확인됨20개·승인 활성화를 확인했다. [저장 화면](linked-team-review-saved.png).

‘승인·경기 공개’ 클릭에서 IAB Input.dispatchMouseEvent가 시간 초과되었다. getJsDialog는 undefined였고 이후 AX 조회도 시간 초과로 도구가 초기화되었다. 사용자에게 로컬 확인창 처리/해당 탭 닫기를 요청했다. **최종 공개 승인·당사자 공개 링크는 아직 실제 브라우저 통과로 판정하지 않는다.** 같은 도구 제약으로 참가 취소→재신청, 별도 접수 취소 확인창 조작도 보류한다. 기존 격리 HTTP/DB 검증을 실제 클릭으로 바꾸어 쓰지 않는다.

합성 단색 이미지는 입력/저장 수명주기를 확인하기 위한 것이며 실제 스코어보드 OCR 정확도 또는 경기 기록의 사실 검증으로 세지 않는다. 최초에 잘못된 QA 체크리스트 경로 `/tools/team-balance/{id}`를 열어404를 본 뒤 실제 목록 링크 `/tools/team-balance/drafts/{id}`로 수정했다. 실제 메뉴의 끊어진 링크가 아니므로 제품 변경을 하지 않았다.

## 격리 환경 종료

전체 DB 계약과 인증 HTTP 준비를 완료한 동일 환경에서 위 과업을 수행했다. 확인창 도구 중단 뒤 하니스를 정상 종료해 pool/cluster 종료·일회성 경로 제거·exit0을 확인했다. [정리한 실행 로그](database-contracts.log). 로컬 합성 데이터는 종료와 함께 제거됐다.
