# 첫 방문 직관성·화면 완성도와 오류 복구 개선 1.0.3

1.0.2 배포 후 독립 검토에서 `/matches/submit?code=invalid`의 최종 404 안내에 공개 메뉴·본문·푸터가 두 번 표시되는 P2를 실제 운영 브라우저로 확인했다. 로딩 화면이 끝난 뒤의 접근성 트리와 화면 모두 중복을 보였다. root `not-found.tsx`의 SiteShell이 공개 layout의 SiteShell 아래 다시 렌더링되는 원인이다. 관리자도 자체 404가 없는 하위 경로에서 공개 틀이 들어갈 수 있었다.

기존 StatusPanel의 404 내용과 복구 링크를 재사용 가능한 내용 컴포넌트로 분리한다. 공개 경로와 관리자 경로에 각각 오류 경계를 두어 현재 layout을 한 번만 유지한다. 어느 경로에도 매칭되지 않는 root 주소는 기존 SiteShell을 그대로 사용한다. 관리자는 관리 홈·검색으로 복귀하고 기존 권한 검사를 유지한다. 새 메뉴나 기능군은 추가하지 않는다.

후속 사용자 요구인 ‘처음 보고도 행동을 짐작할 수 있는 화면’을 기준으로 별도 소스·실행 감사를 진행했다. 다음 문제를 같은 patch에 통합한다.

| 중요도 | 발견된 문제 | 원인과 개선 |
|---|---|---|
| P2 | 랭킹 점 버튼만 보고 세 종류를 알기 어려움 | 승률·최다 참여·최다 MVP를 이름 있는 직접 선택으로 표시하고 중복 다음 안내 제거. 한 슬라이드·직접 조작·재생/감소 모션 유지 |
| P2 | 새 결과 제출보다 접수 코드 입력이 먼저, 선택 입력·기술 용어가 중요한 입력과 같은 비중 | 새 경기 정보→결과 이미지→접수 상태를 명확히 구분. 선택 정보는 접고 필수 입력은 항상 보임. 새 접수 버튼이 실제 다음 행동을 안내. 실패한 이어하기는 코드/내 기록 복구를 우선 |
| P2 | 이벤트전·멸망전 신청에서도 오늘 내전이 현재 메뉴로 표시 | URL 쿼리의 신청 종류를 현재 메뉴 판정에 반영, 종류 변경 시 메뉴 닫기 |
| P2 | 지연된 팀 검색을 지우면 검색 중 안내가 남음 | 입력 삭제·초기화 시 loading 해제. 취소된 이전 응답의 상태 덮어쓰기 방지 유지 |
| P3 | 한글로 고른 포지션이 신청 결과에서 영문 코드로 표시 | 입력·내 상태·명단에서 기존 한글 표시 상수를 공유 |
| 보안 | 실행 의존성 검사에서 Next.js 보안 권고와 개발 도구 하위 경고 발견 | 실제 호출 경로·공식 수정 버전·실행/빌드 도구 경계를 확인 후 최소 보안 patch 적용. 최종 결과는 의존성 점검 기록과 필수 검사로 확인 |

새로운 사용자 과업 없이 메뉴나 시스템을 늘리지 않았다. 제출 화면은 기존 입력 이름과 저장 payload를 유지하고, 접힌 선택 정보도 동일한 form 안에 둔다. 이미지 등록·수정·취소의 기존 권한·중복 요청·화면 전환 잠금과 원래 접수 복귀는 보존한다. 주된 행동, 선택 정보, 현재 상태를 여백·대비·크기와 읽을 수 있는 이름으로 구분한다.

## 전체 작업과 범위의 연결

전체 기능은 [386개 경로·499개 method·조작/메뉴 원장](../2026-10-05-service-completion/feature-inventory.md)을 기준으로 하며 [현재 소스 재대조](../service-completion-v1.0.2-2026-10-06/inventory-reconciliation.json)에서 누락이 없었다. 이 patch의 오류 경계는 신규 page/API 경로가 아니다. 이전 원장의 시점별 미확인 상태는 아래 최신 근거와 함께 읽는다.

| 사이트 목적·기능군 | 최신 검증과 결과 | 남는 경계 |
|---|---|---|
| 처음 방문·메뉴·검색·도움말 | 실제 시작 안내→모집→명령 복사→도움말, 기능 검색→Enter 이동; 홈 여섯 영역·단일 랭킹 슬라이드 유지 | 실제 신규 이용자 대상 사용성 조사 미실행 |
| 로그인·승인 대기·일반 계정·관리자 | 격리 인증/세션·폐기·권한·페이지 회귀, 로그인 후 원래 제출 복귀 확인 | 실제 SUPER_ADMIN 운영 로그인 아직 없음 |
| 내전·대회 참가·모집 | 회차 문맥·ARAM 표시·정원·예비 계약, 실제 신청 취소와 HTTP 재신청 및 상태 문구 확인 | 실제 회원의 신청을 임의 변경하지 않음 |
| 실력·포지션별 팀 만들기 | 실제 격리 초안 생성·저장·동시 수정·재평가·복구·제출 원본 연결 검증 | 최대 규모 실사용 부하·실기기 조작 미확인 |
| 경기 결과 제출·관리자 검토·공개 | 생성→수정→이미지→반려→재개→승인→공개 격리 HTTP, 브라우저 파일 선택·중복 오류 복구까지 확인 | 네이티브 취소 확인창의 CUA 제어 한계, 실제 OCR 공급자 정확도 미확인 |
| 전적·승률·MVP·참여 랭킹 | 공통 정렬·동률·필터·표시 일치와 운영 API 대조 PASS | 운영 원본 결과를 시험 목적으로 수정하지 않음 |
| MMR·자동 반영 | 페이지/포지션/빈 상태 수정, 실제 미리보기와 격리 전환·권한·재시도, 전환 전 논리 백업 실제 복원 PASS | 구 공식의 운영 전환은 최고관리자 로그인 필요; 13개 미소비 변경 이벤트 남음 |
| 커뮤니티 이미지·하이라이트·선수·징계·문의 | 전체 페이지 HTTP와 관련 단위/계약·격리 DB, 공개 자산 MIME/hash, 문의 보존 cron 관측 | 모든 글/영상·모든 보조기기·실제 외부 경보 수신은 미확인 |
| Riot·카카오·예약 작업 | 실제 Riot status 및 갱신, Blob 왕복, 카카오 일일 마감·통계·문의 보존 제공자 기록 확인 | RSO client·소유자 동의, 전화기 설치/수신, Riot PARTIAL 개별 원인 별도 |
| 운영 설정·감사·DB·배포·복구 | 관리자 계약/HTTP·동시성·인증, 스키마·migration 검증, 버전별 source/tag/deployment 연결 | 제공자 PITR·Blob 전체복구·키 복구 미확인 |
| 잘못된 주소·권한 없음·복구 | 이 patch에서 공개/관리자/root 404의 단일 화면 틀과 복구 경로를 실제 HTTP로 검사 | 실제 브라우저 최종 결과와 배포 근거는 후속 운영 기록 |

[1.0.0 주요 원인·기능 개선](../2026-10-05-service-completion/README.md), [1.0.2 owner 쓰기 오류·재신청 수정](../service-completion-v1.0.2-2026-10-06/README.md), [실제 격리 업무 HTTP](../2026-10-06-owner-task-http/README.md), [브라우저 결과](../service-completion-v1.0.2-2026-10-06/browser.md), [외부 운영 경계](../service-followup-2026-10-06/external-runtime.md), [MMR 영향·복구 조건](../service-followup-2026-10-06/mmr-transition-review.md)를 연결한다. 실제 실행하지 않은 전체 버튼×상태×기기 조합을 통과로 취급하지 않는다.

## 추가하지 않는 기능과 성능 판단

참가·모집→팀 편성→결과 제출·검토→전적·공유의 기본 기능군은 존재한다. 발견된 결함은 기존 경로를 고쳐 해소한다. 카카오 원본과 경쟁하는 별도 모집 편집, 새 알림 공급자, 새 인증 체계를 만들 근거가 없다. 실제 hydration 충돌과 잘못된 상태 보존은 원인을 제거했고, 단발 HTTP 시간만으로 새 캐시·쿼리/번들 변경의 효과를 주장하지 않는다. 홈 순서·생성 이미지·기존 접근성과 직접 조작/모션 감소 처리는 유지한다.
