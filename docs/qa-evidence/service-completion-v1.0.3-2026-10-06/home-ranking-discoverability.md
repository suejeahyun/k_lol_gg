# 홈 랭킹 선택의 발견성 개선

문제: 홈 랭킹의 직접 선택 버튼은 점 세 개로만 보였다. 처음 방문한 사용자는 다른 슬라이드가 승률·참여·MVP라는 것을 점에서 알 수 없고, ‘다음’ 안내 버튼과 다음 화살표가 같은 행동을 반복했다. 별도 랭킹 기능을 추가하는 대신 이미 존재하는 세 기준을 이름으로 직접 선택하도록 바꾼다.

## 수정

- 슬라이드 위에 **승률 / 최다 참여 / 최다 MVP** 버튼을 둔다. 항상 한 슬라이드만 표시하고 선택 상태를 `aria-pressed`와 명확한 배경/문자 대비로 전달한다.
- 점 버튼과 중복 ‘다음: …’ 버튼을 제거한다. 이전·다음·사용자가 시작하는 재생/정지와 현재 기준의 전체 순위 링크는 유지한다.
- 직접 선택은 재생을 멈추고 해당 슬라이드·전체 순위 목적지를 함께 바꾼다. 기존 방향키·스와이프·focus 정지·숨긴 탭 정지·모션 감소 규칙을 바꾸지 않는다.
- CSS module 안에서만 변경한다. 생성 아이콘·배경 이미지, 단상, 홈 여섯 영역 순서, API·집계 기준을 유지한다. 선택 버튼은 최소 높이 44px, 축소 가능한 flex 항목과 wrap, 작은 화면의 13px 이름 표시를 사용한다. 가장 좁은 화면에서는 하단 조작을 가운데 정렬해 줄바꿈에도 한쪽으로 치우치지 않게 한다. 고대비 모드의 선택 상태도 제공한다.

## 검증

- [수정 전 회귀](home-ranking-before.log): 이름으로 선택하는 두 과업 실패, 기존 방향키/이동과 빈/단일 상태는 통과. 기존 점 버튼에 직접 선택 이름이 없음을 검증했다.
- [수정 후 focused](home-ranking-focused.log): 새 behavior 4개 + 기존 홈 계약 7개, 총 11 PASS. 세 이름/선택 상태/한 슬라이드, 재생 중 직접 선택→정지→목적지 변경, 이전·다음·방향키, 빈/단일 상태, 홈 순서·기존 피드 계약을 확인한다.
- [focused ESLint](home-ranking-lint.log): component/behavior regression exit 0. `git diff --check` 통과.
- [CSS 색상 대비 계산](home-ranking-contrast.json): 선택 버튼의 세 강조 배경에서 11.31~12.50:1, 비선택 버튼은 흰 배경이 비치는 보수적 계산에서 11.07:1. 실제 화면 픽셀/스크린리더 검사로 확대하지 않는다.

실제 320/390px 브라우저의 overflow·44px 영역·focus/Enter·이전/다음·재생 조작과 이미지 위 가독성은 통합 담당자에게 전달했다. 이 문서는 CSS 의도와 component handler 검증 기록이며 아직 수행하지 않은 실기기나 최종 배포 검사를 통과로 표시하지 않는다. 전체 type/build/check, 교차 독립 검토와 운영 배포는 통합 담당자의 최종 증거에 연결한다. 구현 담당자는 자기 변경을 별도 독립 검토 완료로 세지 않는다.
