# 경기 제출 화면 교차 검토

2026-10-06 KST. 구현 담당자와 별도로 `submission-form.tsx`, `page.tsx`, `submit.module.css` diff와 실제 컴포넌트 실행을 검토했다. 이 검토에서 제품 소스를 직접 수정하지 않았다.

## 발견 후 반영한 사항

**P2 · 이어하기 실패 후 신규 제출로 오인할 수 있는 배치.** 올바른 형식의 접수 코드가 현재 계정에 없으면 `requestedCode`는 있지만 `submission`은 없다. 최초 UX 변경은 이때도 새 접수 폼과 주 행동 버튼을 먼저 보여 주고, 열린 코드 입력을 그 아래에 배치했다. 이어가기 사용자가 코드를 고치거나 본인 기록을 찾는 행동보다 신규 접수를 먼저 선택하기 쉬웠다.

담당자에게 보고한 뒤 `recoveringCode` 분기를 추가했다. 해당 문맥은 오류 → 열린 코드 입력 → 내 제출 기록 및 명시적 새 경기 제출 링크로 이어지며, 신규 폼과 신규 제출 진행 단계는 노출하지 않는다. 정상 신규 방문은 경기 정보 입력이 먼저 보인다. 후속 실제 렌더에서 새 접수 폼이 없고 코드 입력이 열려 있음을 확인했으며 해당 기존 회귀도 보강됐다.
