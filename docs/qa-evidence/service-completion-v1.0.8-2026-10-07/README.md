# 관리자 표시·MMR 요청 복구 후속 · 1.0.8 후보

기준 운영 버전은 1.0.7 source `0716a60bf09654118cc40493481839d75269b3f7`이다. 이 문서는 그 이후의 소스 수정과 검증을 기록한다. **1.0.8 통합 check·최적화 빌드는 PASS, 새 격리 DB/HTTP는 통과, 최종 빌드 실제 UI·배포는 미완료**다. 기존 1.0.7의 통과·배포를 이번 후보의 결과로 옮기지 않는다. 이후 배포 상태는 [통합 배포 기록](production.md)을 기준으로 확인한다.

## 목적과 확인한 문제

함께 참가할 경기 찾기, 팀 편성, 결과 기록과 운영 관리의 기존 기능을 유지하면서 관리자가 현재 단계와 저장 완료 여부를 정확히 판단하도록 보완한다. 새 기능·API·DB 스키마·외부 제공자·기술 교체는 추가하지 않는다. 홈의 여섯 영역 순서, 단일 랭킹 슬라이드와 생성 이미지 테마도 유지한다.

| 중요도 | 발견과 원인 | 수정·근거 |
|---|---|---|
| P3 | 관리자 이벤트의 방식·진행 단계·참가자 포지션/출처/상태를 내부 enum으로 표시 | 기존 한국어 표시 함수를 재사용하고 해당 Page의 참가 출처·상태를 구분. [실제 Page SSR 전후](event-admin-display.md) |
| P2 | MMR HTTP 성공만으로 완료를 알림; 빈 객체·다른 작업/계산 버전도 성공 처리 가능 | 작업별 응답 본문·원래 플레이어·정수 revision/generation·재계산 결과를 확인. [담당자 재현·수정](mmr-admin-recovery.md) |
| P2 | MMR 응답 유실 후 재시도마다 새 키를 만들고 같은 tick 중복 제출을 허용 | 기존 key store와 즉시 ref 잠금으로 원래 본문·계산 버전·요청 키를 유지. 미확정 상태에서 `같은 요청 다시 확인` 제공 |
| P2 | 성공 직후 서버의 새 결과가 도착하기 전에 이전 계산 버전으로 다시 조작 가능 | refresh와 실제 새 generation 도착까지 잠금. 이전 결과가 반환되면 잠금을 유지하고 결과 새로고침 제공 |
| P2 독립 검토 | 단순히 증가한 generation을 확인하여 요청의 정확한 다음 버전과 다른 성공 응답도 수락 | 서버의 `expectedGeneration + 1` 계약과 대조해 정확한 다음 버전으로 검증. [독립 재현·후속 확인](independent-review.md) |

MMR의 401/403은 원래 요청을 보존하고 관리자 로그인으로 연결한다. 412는 명시적으로 최신 결과를 불러와 재검토하며, 확정된 입력 오류는 수정할 수 있다. 서버 권한·영수증·전역 잠금·공식·기존 데이터 정합성 정책은 유지한다. 중복 전송 재현을 중복 DB 원장 생성으로 확대하지 않는다. 기존 서버는 조정 삽입 전에 generation을 확인한다.

## 전체 기능 원장과 실제 조작 구분

[18개 기능군별 기존 원장](../service-completion-followup-2026-10-07/README.md), [현재 386개 경로·1145개 UI 조작 소스 위치](interface-inventory.json), [경로·HTTP method·6예약 대조](inventory-reconciliation.json)를 연결한다. 기존 1.0.7의 1141개에서 재시도·로그인·새로고침 4개 위치가 추가됐고, 경로·HTTP method·예약 정의는 변동이 없다. 이 수치는 구조 조사이며 실제 클릭 수나 모든 상태를 검증한 수가 아니다. 이번 제품 변경은 05 이벤트전, 11 랭킹·MMR의 관리자 화면에 한정된다. 나머지 기능군의 기존 근거와 미확인 조건은 원장에 유지한다.

[확인창 해제 후 실제 조작](../service-completion-interactions-2026-10-07/browser-journeys.md)은 **1.0.7 source 0716a60b의 최적화 빌드**를 사용했다. 미디어 목록·공개 연결, 이벤트 이름/한국시간 저장·취소·복구, 기타 후속 조작은 해당 문서에 실제 완료 범위대로 기록한다. 여기에서 새로 발견한 이벤트 코드 노출은 1.0.8 수정 이유이며, 그 1.0.7 화면을 수정 후 브라우저 결과로 세지 않는다. 운영 홈 랭킹 선택·키보드 조작도 별도 실제 근거이고 이번 관리자 소스 검증과 합산하지 않는다.

위 개별 검사 수를 서로 더해 실제 과업 완료 수로 주장하지 않는다. API·스키마 변경이 없다는 사실도 기존 권한·멱등성·DB 계약 확인을 대체하지 않는다.

첫 통합 검사는 [check-first.log](check-first.log)에 계약 612 PASS·1 FAIL로 보존했다. 실패는 `busy || !playerId`라는 소스 문자열을 요구하던 picker 검사였다. 실제 제출 조건은 미확정 요청·새 결과 대기까지 포함한 `locked`로 강화됐으므로, 변수명 검사 대신 실제 핸들러에서 선수 미선택 시 전송 없음, 선택 후 제출 가능, 처리 중 버튼·fieldset 잠금과 같은 tick 중복 차단을 확인하도록 보강했다. 기존 picker·원격 endpoint·raw UUID 입력 금지 검사는 유지했다. 이 수정이 포함된 최종 전체 계약은 613 PASS다. 별도 로그가 남지 않은 후속 focused 실행 보고는 추가 통과 수로 합산하지 않는다.

## 전체 완료를 보류하는 조건

- 운영 로그인은 확인됐으나 실제 역할이 ADMIN이다. MMR 공식 전환은 SUPER_ADMIN 세션, 최신 영향 확인 및 검증된 백업·복원 조건을 충족한 뒤 진행해야 한다. [전환 준비](../service-completion-interactions-2026-10-07/mmr-transition-preparation.md)는 실행 완료 기록이 아니다.
- native confirm 이후 브라우저 도구가 다시 멈춰, 그 뒤의 신청 취소/재신청·최종 경기 승인 등 미완료 조작은 실제 interactions 문서의 경계를 따른다. 이전 격리 하니스는 정상 정리 exit 0을 확인했다. handler·HTTP 통과로 실제 확인창 조작 성공을 대신하지 않는다.
- 실제 카카오 기기·방·수신 ACK, RSO 소유자 승인, 실기기 설치·스크린리더·신규 사용자 관찰, 실제 OCR 정확도, 장시간 부하 및 provider PITR/Blob 전체 복구는 기존 외부 조건으로 분리한다.

새 기능이나 기술 교체가 필요한 근거는 발견되지 않았다. 확인된 문제의 최소 수정·개별 회귀·최종 통합 검사 범위에서는 추가 구조 변경이 불필요하다고 판단하지만, 운영 배포와 위 미확인 항목까지 완료됐다고 선언하지 않는다. [사용자용 변경 안내](../../patch-notes/2026-10-07-service-completion-1.0.8.md).
