## 수정 전 실제 브라우저 근거

별도 임시 PostgreSQL 18과 합성 계정의 optimized Next 서버를 사용했다. 실제 회원 신청·경기·계정은 변경하지 않았다.

- 로그인 `next=/matches/submit` → 원래 제출 화면 복귀 성공.
- 새 접수 생성 → 코드 URL/이미지 등록 화면 → ‘새 결과 접수’ 클릭 → 제목·주최자·코드가 빈 새 폼으로 전환 성공.
- 방금 만든 코드 입력·불러오기 → 저장한 제목·주최자와 이미지 등록 상태 복원 성공.
- 접수 정보 수정에서 제목만 변경 → 일반 오류 안내. 동일 요청의 격리 HTTP가 500을 재현했고 내부 scope 예외를 확인했다. 콘솔에 오류가 없다는 사실을 저장 성공으로 취급하지 않는다.
- 내전 신청 취소 → ‘취소’ 상태·성공 안내·본 참가 1명에서 0명·명단 빈 상태 확인. CUA 클릭 호출은 확인창 때 시간 초과했지만 다음 UI가 ‘취소 중’에서 완료 상태까지 변경되었다. 이번 실행에서는 이전 확인창 도구 한계를 넘어 실제 취소 결과를 확인했다.
- 운영 읽기 전용: 시작 안내 → 파티 목록 → 참가 명령 복사 완료 안내 → 참여 방법 펼치기 → 모집방 안내 → 문의/사이트 신청 복구 링크. 전역 검색 ‘결과 제출’ → 결과 1개 → Enter로 제출 화면 이동. 카카오 메시지는 보내지 않았다.

최종 수정 후 검증·배포는 별도 기록으로 이어지며 이 수정 전 기록을 최종 통과로 표시하지 않는다.

## 전체 기능 원장과 현재 점검 범위

기존 [386개 경로·499개 method·조작/메뉴 원장](../2026-10-05-service-completion/feature-inventory.md)은 기능 목록의 기준이다. 해당 원장의 소스·단위/계약·격리 DB·페이지 HTTP·브라우저·운영 구분을 유지한다. 이번 추가 검증은 접수 소유자 쓰기, 팀 도구 쓰기, 운영 외부 연동과 MMR 최신성에 연결한다. 모든 버튼의 모든 실패·실기기 조합을 통과했다는 뜻은 아니다.

[소유자·팀·관리자 HTTP 검증](../2026-10-06-owner-task-http/README.md)은 생성·재생, 동시 수정 200/412, 최신 revision 복구, 잘못된 이미지 후 정상 업로드, 취소·재시도, 타인/승인 대기/익명/폐기 세션의 차단, 팀 초안 생성·저장·재계산, 반려 사유·재개·승인·공개 전환을 실제 임시 DB/서버 요청으로 확인한다. 외부 저장·OCR은 로컬 합성 adapter이며 실제 공급자와 구분한다.

[실제 외부 연동·자동 작업](../service-followup-2026-10-06/external-runtime.md)은 운영 Blob 왕복, Riot status-v4, 실제 요약 갱신과 예약 로그를 확인했다. MMR은 구공식 보호로 409를 반환하며 미소비 변경 이벤트 13건을 최신 반영 완료로 표시하지 않는다. 별도 전환 영향과 접근 조건은 최종 운영 기록으로 이어진다. 코드 릴리스가 MMR 공식 전환이나 실제 휴대폰 설치 완료를 대신하지 않는다.
