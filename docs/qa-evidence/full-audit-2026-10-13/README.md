## 판단

## 개선 제안 및 운영 확인

1. **Riot 처리량.** 저장소의 자동 예약은 5분당 1건, 6시간당 최대 72회다. 연결 수·재시도 증가에 맞춰 API 제한을 지키는 여러 작업 처리/주기 조정을 검토한다. 외부 소비자가 더 실행할 수 있고 현재 운영 지연은 측정하지 않았다. 기존 `oldestPendingAt`·30분 경고는 이미 있으므로 중복 구현하지 않는다. 아직 queue에 들어오지 않은 갱신 기한 초과 연결도 측정하는 것이 유용하다.
2. **모집 최신성.** 탭 복귀 갱신·수동 갱신·마지막 확인 시각부터 보완한다. 서버 정원 검사는 유지하고, 화면이 보일 때만 주기 갱신하는 방식은 실제 이용량에 맞춰 판단한다.
3. **게시 취소와 캐시.** 공개 이미지의 max-age/stale 허용 시간과 비공개 전환 기대를 맞춘다. 기존에 내려받은 복사본을 회수할 수 있다는 의미로 안내하지 않는다. 현재 CDN 잔존 시간은 미측정이다.
4. **설치 앱의 정적 이미지 갱신.** PWA가 동일 URL 이미지에 cache-first를 사용한다. 이미지 변경 시 URL hash/cache version 갱신 규칙을 명시한다.
5. **반복 보안 점검.** 의존성 advisory와 main push의 secret scan 누락을 CI 운영 정책과 대조한다. 기존 테스트가 제품 간 상호작용과 대량 경계를 검증하도록 보강한다.

## 다음 수정의 검증 기준

- 먼저 D1을 고치고 실제 저장 경로로 경기 공개→MMR→정정→재집계를 확인한다. 과거 MMR 이력·감사 기록·경기 revision을 보존한다.
- D2는 같은 transaction 안 분할 INSERT 후 409/410 및 더 큰 데이터에서 일치·원자성·실패 rollback을 확인한다.
- 입력 보존은 네트워크 오류와 409/412를 격리 브라우저에서 재현하고 초안·안내·재시도 결과를 검증한다.
- 101건 이상 운영 신청, 일반 Blob 삭제 대기, 만료 세션은 실제 실행 경로를 포함하는 합성 DB 검증을 추가한다.
- 공개 이미지 정리는 합성 EXIF/GPS, 최종 hash/size, 공개/비공개 경계를 검사한다.
- RSO는 제공자 활성화 전에 서로 다른 사이트 왕복으로 쿠키·state·소유자·일회성 소비를 검증한다.
- 카카오 실기기·방은 이미 완료된 사용자 확인을 유지한다. 새로운 외부 조건과 혼합해 다시 준비를 요구하지 않는다.

점검 산출물은 수정/배포 완료의 근거가 아니다. 이번에 확인한 문제는 아직 수정하지 않았다.
