# 같은 휴대폰의 K-LOL / NEXUS 방 분리 수정

사용자가 NEXUS 방에 K-LOL 구인현황이 나타난다고 보고했다. 기존 K-LOL 일반 봇의 진입 함수에는 NEXUS 방 제외 조건이 없었다. 합성 VM에서 NEXUS 두 방의 `구인현황` 명령이 K-LOL 서버 요청과 같은 방 답장으로 이어지는 것을 재현했다. 실제 휴대폰의 설치본·구독 선택은 직접 확인하지 않았다.

전달한 NEXUS 설치본 두 파일의 서버 주소·키와 저장 namespace는 NEXUS 운영 설정과 일치한다. 별도 운영 DB의 엄격한 대상 확인 및 읽기 전용 검사에서 시즌·신청·내전라운드·파티·스크림·사이트알림과 command receipts는 모두 0건이었다. 확인한 NEXUS DB에서 모집 자료 혼입 흔적은 없다. 이는 휴대폰 전체 설정이 검증됐다는 뜻은 아니다.

## 수정 범위

기존 K-LOL 일반 봇은 `NEXUS`, `NEXUS 구인구직방` 메시지를 어떤 조회·저장·답장보다 먼저 무시한다. K-LOL 알림 companion에도 같은 입력 경계를 적용한다. NEXUS 산출물로 변환할 때는 K-LOL 제외 조건을 제거하고 기존 NEXUS 허용 조건을 유지한다. NEXUS 설치본의 설정·키·기존 동작은 유지한다.

서버 API, DB, 모집 기록과 Vercel 배포는 바꾸지 않는다. 기존 두 방의 표시 이름을 바꿀 경우 코드·봇 구독 목록을 함께 점검해야 한다. 방 이름은 사용자 인증 수단이 아니다.

## 휴대폰 반영

이미 정상 작동 중인 **기존 K-LOL 봇 프로필**의 코드만 수정본으로 교체한다. 이 교체본에는 비밀키가 없으며 같은 프로필에 저장돼 있는 기존 DataBase 설정을 사용한다. 새 프로필을 만들거나 기존 DataBase를 지우는 설치 방식이 아니다. 새 설치에는 별도의 인증 설정이 필요하다.

기존 K-LOL 봇의 구독 대상에서도 NEXUS 두 방을 제외하고, NEXUSMain은 NEXUS 두 방만 선택한다. 저장·컴파일 후 NEXUS 방의 `봇버전`은 NEXUS 코드만, 기존 K-LOL 방의 같은 명령은 수정된 K-LOL 코드만 보여야 한다. NEXUS 방의 `구인현황`은 NEXUS의 비어 있는 현황이어야 한다.

일반 봇 교체는 알림 companion의 재등록을 요구하지 않는다. K-LOL 알림 companion을 별도로 재컴파일하면 메모리 수신 세션이 사라져 새 일회용 등록 코드로 다시 등록해야 한다. 현재 구인현황 중복 응답의 직접 수정 대상은 일반 봇이다.

## 검증과 상태

합성 VM의 양방향 방 격리, 차단된 방의 요청·답장·저장 0회, 기존 방의 명령 동작과 기존 설정 보존, NEXUS 생성본 보존, ES5/Rhino 및 CRLF 편집기 제한을 검사한다. 최종 결과는 validation.json에 기록한다.

코드·설치 파일 준비와 실제 기기 설치는 구분한다. 상태는 **PENDING_USER_INSTALL**이며 이 감사에서는 실제 카카오 메시지 전송·휴대폰 코드 교체를 수행하지 않았다.
