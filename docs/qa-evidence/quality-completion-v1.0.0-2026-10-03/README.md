# 전체 화면·조회 복구 품질 개선 1.0.0

## 실제로 발견하고 수정한 문제

- 이벤트전·멸망전에서 선택하지 않은 상태/방식 필터가 빈 문자열로 전송되면 정상 검색도 오류 화면으로 이동했다. 미선택 값을 정상 처리하고 중복·알 수 없는 값·공백만 있는 값은 계속 거부한다.
- 내 제출 기록에서 '전체 상태'를 적용하면 오류가 발생했다. 동일한 경계를 수정하고 잘못된 주소에서 전체 기록으로 복귀할 수 있게 했다.
- 대회 필터 초기화 후 이전 선택값이 남을 수 있었다. URL 조건이 바뀌면 폼 값을 함께 초기화한다.
- 대회 잘못된 주소 화면에 페이지 제목(h1)이 없었다. 목록 내부 상태(h2)와 페이지 오류(h1)를 구분했다.
- 모바일 팀 참가자 입력란이 14px로 표시됐다. 16px 입력 규칙의 우선순위를 바로잡았다.
- 팀 생성 후 결과를 찾기 위해 내려가야 했다. 결과 제목으로 키보드 포커스와 화면을 이동한다. 인원·티어 오류는 해당 입력으로, 초기화는 이름 입력으로 이동한다.
- 참가 조회 장애에서 새로고침 안내만 있었다. 선택한 모집 회차와 진입 경로를 유지하는 '다시 불러오기'를 제공한다. 제출 조회 장애에도 재시도 동작을 제공한다.

- 320px에서는 플레이어 상세·MMR·갤러리 작성·이벤트 운영 화면의 그리드 최소 너비가 내용을 밀어냈다. 입력과 콘텐츠가 실제 너비에 맞게 줄어들고 긴 이름은 줄바꿈되도록 수정했다.
- 참가 신청 로딩 화면이 상위 main 안에 또 main을 만들었다. 이름이 있는 상태 영역으로 변경했다.

- 카카오 방 구성원 역할 선택에 접근성 이름이 없었다. 방·구성원이 포함된 이름을 추가하고 옵션을 회원/매니저/관리자로 표시한다. 저장 값과 권한 정책은 유지한다.

## 검증 방법

운영 데이터의 변경 없이 PostgreSQL 18 일회성 클러스터와 합성 계정을 사용한다. 필수 검사와 별도로 전체 DB 계약·인증 HTTP·백업 복구를 실행한다. 브라우저 HOLD 모드는 HTTP 계약을 생략하므로 별도의 일반 test:db 실행이 필요하다.

브라우저 조작은 CUA로 수행한다. 원본 ready payload의 임시 로그인 정보는 .tmp에만 보관하며 이 폴더에는 기록하지 않는다. qa/verify-quality-http.mjs는 loopback origin에서만 로그인하고 같은 origin으로만 쿠키를 전달한다.

- 공개 28개 운영 경로: 320·390·1440px 사전 점검.
- 전체 108개 페이지와 상세 탭/검색 변형 54개: 320·390·1440px, 총 486개 화면 조건에서 DOM 구조 점검.
- DOM 확인 항목: 가로 넘침, 보이는 페이지 제목, main, 문서 언어, 중복 ID, 조작 요소 이름, 모바일 입력 글자 크기, 이미지 로드·대체 텍스트.
- 전체 HTTP는 169개 주소(기본·상세 탭·빈 필터·잘못된 필터)와 실제 인증 세션으로 검사한다.
- 필수 check: 계약 445개 + 단위 1,045개 통과, 환경 조건부 1개 skip. 타입·ERD·아트 검증·프로덕션 빌드 통과. 기존 lint 경고 58개, 오류 0개.

모든 버튼의 업무 시나리오를 전수 실행하거나 WCAG 적합성을 인증했다는 의미가 아니다. 사진 목록/계정 상세의 최초 관찰에서 로딩 프레임 2건이 잡혔고, 로딩 완료 후 정상 제목을 확인했다. 원본 관찰과 재확인 기록을 함께 보존한다.

## 테스트 환경 정비

1. 구버전 → 현재 스키마 업그레이드 계약이 빈 DB에서 먼저 실행되도록 순서를 복구했다.
2. 회원가입 동의 버전 기대값을 현재 정책 상수와 연결했다.
3. 계정 HTTP 검증의 과거 2FA 재등록 기대도 현재의 비밀번호 로그인·폐기 API 410에 맞췄다. 대상 확인·최고 관리자 권한·세션 폐기·오래된 revision·삭제/복구 검증은 유지한다.
4. 2026-09-30부터 적용된 관리자 비밀번호 로그인 정책에 맞춰 폐기된 TOTP 가입 HTTP 흐름을 기존 비밀번호 HTTP 계약으로 연결했다. 역할·상태·동일 출처·서명·세션 폐기 검증과 기존 암호화 자격증명 보존 검증을 유지한다.
5. 미디어·챔피언·팀 점수 계약에서 현재 허용되는 비밀번호 세션과 폐기/오래된 세션을 구분했다. 런타임 인증 정책은 변경하지 않았다.
6. 멸망전 계약이 다른 계약의 사이트 설정을 오염시키지 않도록 변경 전 기능 설정을 복원한다.
7. 취소 요청 제한 검증은 합성 참가자 13명을 예비로 명시 신청하도록 수정했다. 본 참가 10명 제한을 완화하지 않는다.
8. HTTP 로그인 제한 검사가 실제 5분 집계 구간 경계를 걸치지 않도록 경계 직전에는 다음 구간을 기다린다. 제한값과 운영 코드는 유지한다.

## 남은 확인의 범위

- 실제 iPhone/Safari·Android/Chrome, 통신 지연/오프라인, 스크린리더·확대·색 대비 전수 확인은 이 PC 브라우저 검사와 별개다.
- 신규 사용자에게 참가·모집·전적·제출 4개 과업을 제시해 성공률과 막힌 위치를 확인해야 직관성을 실제 이용자로 검증할 수 있다.
- PageSpeed Insights API는 이번 요청에 HTTP 429를 반환했다. Lighthouse/Web Vitals 점수를 만들거나 통과로 기록하지 않는다. HTTP 응답 시간은 LCP/INP가 아니다.
- Google/Naver 검색 도구의 소유권 등록, 실제 외부 계정/기기·운영 알림 수신은 해당 서비스와 기기에서 확인해야 한다.
- 기존 lint 경고와 환경 조건부 테스트 skip은 최종 로그에 그대로 남긴다. '모든 환경에서 완벽'이라고 판정하지 않는다.
