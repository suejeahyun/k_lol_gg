## 확정 요구와 제안 구분

- 사용자 확정: 협곡·칼바람·증바람 모두 본 참가 10명 고정 + 예비, 사이트 회원은 나중에 연결, 복사·붙여넣기 유지. 1.1부터 협곡은 이름과 라인 필수, 다른 종목은 이름만 접수.
- 1.1 추가 확정: 10명 달성 즉시 디스코드 대기 안내를 표시한다. 실제 10분 전 예약 발송이 아니다. `/`·`,`·한글·영문 라인, `top,all`의 나머지 네 라인, 단독 `all`을 지원한다.
- N인 파티에서 수용된 흐름을 내전에 적용한 양식·목록·편집 규칙을 제안한다.
- `내전 Nㅉ` 명단 보존 마감은 추천안이다. 별도 질문의 사용자 응답이 없어 확정으로 표시하지 않았다.

## 독립 설계 검토 반영

읽기 전용 검토에서 제기한 네 사례를 설계에 반영했다.

1. 사이트·카카오·미연결 이름의 합산 정원과 회원 연결 시 중복 집계 방지.
2. 사이트·운영진 보호 사유를 번호 행과 분리하여 표시하고, 보호 항목 편집을 일부 성공처럼 숨기지 않음.
3. 별칭·라인 변경과 참가 항목의 신원을 구분. 미선택을 모든 라인 가능으로 단정하지 않음.
4. 마감 후 읽기 전용 명단과 신규 신청 차단을 양쪽 채널에서 일치시킴.

검토 에이전트는 파일 수정·테스트·배포를 하지 않았다. 실제 설치폰·운영 송수신 호환은 미확인이다. 앱 테스트를 이번 문서 작업의 검증 결과로 재사용하지 않는다.

## 문서 검사 — 설계 1.0 당시 기록

- 문서 4개에서 상대 링크 6개가 실제 파일로 연결됨을 확인했다.
- 내전 양식 예시 2개 모두 본 참가 1~10번과 예비 1번을 포함한다.
- 마감 정책 미확정·운영 배포 변경 없음 표기를 확인했다.
- 독립 최종 검토에 따라 전체 이름 삭제 규칙을 보호 항목이 없는 경우로 한정했다.
- `git -c core.autocrlf=false diff --no-index --check -- /dev/null <문서>`로 문서 4개의 whitespace 진단이 없음을 확인했다. 새 파일과 비교하는 no-index의 종료 코드 1은 내용 차이로 구분했다.
- `git status --short`에서 기존 N인 파티 설계 문서·QA 폴더와 새 내전 설계 문서·QA 폴더만 미추적 상태임을 확인했다. 소스·스키마·휴대폰 파일 변경은 없다.
- 앱 테스트·실기기 검증은 실행하지 않았다.

## 다음 구현 추천

1. **마감 상태와 통합 10명 접수부터 구현**: 현재 마감이 신청 취소이며 사이트 신청 경로에 통합 정원 검사가 없어, 표시보다 먼저 데이터 규칙을 맞출 필요가 있다.
2. **참가 항목 식별·표시 이름·회원 연결 분리**: 동명이인과 연결 전후 중복 집계·별칭 변경 문제를 함께 해결한다.
3. **협곡 필수 라인과 편집 병합**: 기존 이름 단독·오타 복구 경로를 조정하고 사이트·카카오에서 라인 뜻을 일치시킨다. 사이트 신청·운영진 결정은 계속 보호한다.
4. **양식·목록·10명 안내와 직접 상세**: 저장 결과를 기준으로 달성 안내를 붙이고 반복 저장·예비 추가의 중복 알림을 막는다. 사이트 기점 카카오 알림은 별도 전달 경로 검토가 필요하다.
