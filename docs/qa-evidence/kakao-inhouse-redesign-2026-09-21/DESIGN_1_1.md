# 내전 설계 1.1 — 만원 안내와 협곡 필수 라인

- 날짜: 2026-09-21
- 범위: 설계·QA 계획·공지 초안만 수정. 애플리케이션 소스·DB·휴대폰 파일·운영 배포 변경 없음.
- 기준: [ADR 0012 1.1](../../architecture/0012-kakao-inhouse-editable-copy-flow.md). 사용자 편집으로 제거된 양식의 안내 칸은 다시 추가하지 않았다.

## 이번 확정 요구

1. 모든 종목 본 참가가 10명이 되는 즉시 `시작 시간 10분 전 내전 디스코드방에 대기해주세요~`를 표시한다. 사용자 응답으로 즉시 표시가 확정되었으며 예약 발송이 아니다.
2. 협곡은 이름과 라인을 필수로 받는다. 기존 선택 라인·이름만 입력 시 ALL 자동 지정 제안은 대체한다. 사이트 회원 가입·연결은 접수 필수가 아니다.
3. `top/mid`, `탑/미드`, `top,mid`, `top,all`, `all`을 허용한다. `top,all`은 TOP + JGL/MID/ADC/SUP, 단독 `all`은 모든 라인 가능이다.

## 소스와 독립 검토

- 기존 `inhouse-snapshot-parser.ts:60`은 첫 `/` 뒤의 라인에서 구분자·별칭·부 ALL 확장을 이미 처리한다. 이를 재사용하되 이름만 입력·라인 오타를 접수로 복구하는 경로와 기존 테스트 기대값은 협곡 필수 계약에 맞춰 바꿔야 한다.
- R24 휴대폰은 `response()` 메시지 수신 → `handleCopyRosterForm()` → HTTP 결과의 `replier.reply()` 방식이다. 카카오 저장 결과가 10명이 된 경우 같은 응답에 안내를 붙이는 구조를 사용할 수 있다. 이번에는 실행 검증하지 않았다.
- 제한적 읽기 검색에서 R24의 주기 조회·타이머·별도 방 전송 경로를 찾지 못했다. 사이트 신청은 DB 저장·audit·HTTP 응답이며, scheduled-notice API도 안내 데이터 조회 역할로 전송 책임을 외부 봇에 둔다. 사이트 접수로 10명이 된 순간 카카오방에 즉시 알리는 기능을 현 R24 무수정으로 보장하지 않는다.
- 실제 설치본·카카오 송수신·사이트 기점 전달 경로는 미검증이다. 카카오 저장 응답과 사이트발 자동 알림을 서로 다른 검증 항목으로 남긴다.

## 추가 구현 검증 계획

| 범위 | 검증할 계약 |
|---|---|
| 필수 입력 | 협곡 본 참가·예비의 이름 단독/오타/빈 토큰 거부, 빈 번호 칸 허용, 칼바람·증바람 이름 단독 허용 |
| 라인 의미 | 사용자 예시 5종, 대소문자·공백, 부 ALL의 네 라인 확장, 단독 ALL, 주 ALL+부라인 오류, 정규 표시 재입력 |
| 저장 원자성 | 잘못된 라인이 있으면 다른 이름도 일부 접수하지 않음. 기존 명단·필드 보존 |
| 인원 안내 | 세 종목 9→10/최초 10명 등록 안내, 예비 제외·미연결 이름 포함, 같은 내용 재시도·10→10 수정의 새 안내 방지, 10→9→10 재안내 |
| 동시성 | 카카오·사이트 동시 신청에도 정원 초과와 동일 달성 이벤트 중복 없음 |
| 전송 | 카카오 저장 응답의 문구 확인, 사이트 저장 응답 확인, 사이트에서 카카오방으로 전달하는 경로는 별도 검증 |

## 문서 확인

이번 변경에 맞춰 양식 예시·라인 편집·오류 처리·현재 코드 차이·필수 검증·공지 문구를 함께 갱신했다.

- 문서 4개의 상대 링크 6개가 실제 파일로 연결됨을 확인했다.
- 양식 2개의 본 참가 1~10번·예비 칸을 확인하고, 작성 예시의 모든 이름에 협곡 라인이 있음을 확인했다.
- 사용자 요청 입력 5종과 즉시 안내 문구가 문서에 있으며, 이전 이름 단독/자동 ALL/오타 접수 정책은 제거되었음을 확인했다. 파서 실행 결과를 뜻하지 않는다.
- 문서 4개에 `git -c core.autocrlf=false diff --no-index --check -- /dev/null <문서>`를 실행하여 whitespace 진단이 없음을 확인했다. 새 파일 내용 차이인 종료 코드 1은 오류와 구분했다.
- `git diff --stat`은 추적 파일 변경 없음, `git status --short`는 기존 파티 및 내전 설계 문서·QA 폴더만 미추적 상태였다. 소스·DB 스키마·휴대폰 파일 변경은 없다.
- 앱 테스트·빌드·실기기 테스트·운영 배포는 실행하지 않았다. 기존 도움말과 사이트 기점 카카오 즉시 알림의 전송 경계는 구현 후 확인할 항목으로 남았다.
