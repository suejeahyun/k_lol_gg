# 카카오 네 프로필 방 제한

사용자 사진에는 `NEXUS 구인구직방`의 `봇버전`에 K-LOL R30이 답한 모습이 있다. 실제 콜백의 방 문자열·휴대폰 전체 코드는 확인하지 못했으므로 R30 조건이 실기기에서 통과한 원인을 확정하지 않는다. 사용자가 네 프로필의 전체 코드와 네 방의 명시적인 분리를 요청했다.

## 적용 경계

| 기존 프로필 | 역할 | 허용 방 |
| --- | --- | --- |
| KLOLMain | 일반 명령 R31 | LOL - K, K롤방 구인구직방 |
| KLOLM | 사이트 알림 1.0.4 | K롤방 구인구직방 |
| NEXUS-Main | 일반 명령 R31 | NEXUS, NEXUS구인구직방 |
| NEXUS-otue | 사이트 알림 1.0.4 | NEXUS구인구직방 |

패키지와 방 허용 목록은 outer response 첫 줄에서 검사한다. 공백과 zero-width 문자를 제거한 정확한 이름만 허용하며 대소문자·추가 문구는 임의 허용하지 않는다. `NEXUS 구인구직방`과 `NEXUS구인구직방`을 같은 대상으로 처리한다. 차단된 콜백에서는 진단 답장, 서버 요청, 저장 접근도 하지 않는다. 알림 폴링은 허용된 구인방에서 명시 등록한 Replier 세션으로만 수행한다. 안정된 채널 ID가 없는 기존 SDK에서 같은 이름을 가진 별개 방까지 식별하는 것은 보장하지 않으므로 앱의 응답 대상 선택도 제한한다.

## 전달 및 설치

기존 네 프로필의 코드를 백업한 후 OFF로 하고 각 파일의 전체 내용을 각각 교체한다. 코드를 이어 붙이거나 중복 프로필을 추가하지 않는다. 서비스별 인증·저장 namespace는 독립적으로 유지한다. DataBase·알림 ledger를 삭제하지 않는다. main 두 개를 저장·컴파일한 뒤 companion 두 개를 저장·컴파일하고, 새 일회용 등록 코드는 각 서비스 구인구직방에서만 운영자가 직접 전송한다. 재컴파일은 메모리 수신 세션을 없애므로 이미 소비한 등록 코드는 재사용하지 않는다.

실제 연결 설정과 등록 코드를 포함하는 파일은 ignored `.private/room-bots-r31/`에만 둔다. 소스 및 공개 QA에는 비밀값을 기록하지 않는다. `INSTALL.md`에 파일별 프로필과 등록 방법을 적고 `metadata.json`에 파일 해시·길이만 기록한다.

## 검증 및 상태

생성 재현, 공유 저장소 합성 VM의 양방향 네 방·이름 변형·잘못된 패키지 차단, 허용 방별 서버 경로, 알림 등록 대상 제한, 기존 인증·ledger 보존, ES5/Rhino와 LF/CRLF 편집기 제한을 검사한다. 전체 `npm run check` 및 비밀정보 검사를 수행하고 결과는 `validation.json`에 기록한다.

이 작업은 폰 코드만 변경한다. 서버·Vercel·운영 DB 변경, 실제 카카오 메시지 전송, 휴대폰 설치는 수행하지 않는다. 설치 상태는 **PENDING_USER_INSTALL**이다. 실제 네 방의 `봇버전`/`구인현황`, 구인방의 `사이트알림상태`, 새 충원 알림 수신은 사용자 설치 후 확인해야 한다.
