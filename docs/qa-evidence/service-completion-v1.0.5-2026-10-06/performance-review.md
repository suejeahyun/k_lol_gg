## 소스 확인과 판단

- 홈은 현황·세션·일일 챔피언·시즌 랭킹을 `Promise.all`로 요청한다. SiteShell과 홈의 `getCurrentSession("ACCOUNT")` 중복 호출은 `runtime-session.ts`의 React `cache`에 의해 같은 요청 인자 범위에서 재사용되므로 중복 인증 DB 호출로 단정하지 않았다.
- `PostgresHomeRepository.load()`의 주요 현황 10개 조회는 병렬이다. 최근 경기/파티/대회 각각 최대 4개, 우승 갤러리 최대 3개를 선택한다. 실제 갤러리 이미지는 1~5개 조건으로 검사한다. 화면 카드가 모든 경기/모집 데이터를 무제한 렌더하는 구조는 아니다.
- 다만 홈의 일일 챔피언 선택은 활성 챔피언 전체를 페이지 크기 100으로 읽는다. 시즌 랭킹도 해당 시즌/generation의 플레이어 통계 전체를 읽어 서버에서 정렬한 뒤 홈 요약을 선택한다. 데이터 증가 시 확인할 조회 후보이며, 현재 표본으로 SQL 병목을 입증하지는 못했다. 관측 없이 캐시를 늘리거나 정합성 기준을 바꾸지 않았다.
- 경기 목록 저장소는 기본 pageSize 12와 `pageSize + 1` 제한을 사용하고 커서가 있으면 offset 대신 커서 조건을 사용한다. 전체 건수 조회와 제한된 목록 조회는 구분되어 있다. 정상 목록이 전체 경기 상세를 렌더하지 않는다.
- 팀 만들기는 선택 10명을 유지하고 참가자/검색 요청에 AbortController를 사용한다. 검색은 250ms 지연 후 실행한다. 원격 검색·추천 API/계산 속도는 이 측정에서 검증하지 않았다.
- 안내 챔피언은 기존 WebP와 고정 width/height를 사용한다. `HomeGuideArt`의 820px 이하 picture source는 작은 data URI라 큰 장식 이미지를 모바일에 그대로 요구하지 않는다. 실제 모바일 네트워크/이미지 decode/화면 이동은 별도 브라우저·기기 측정이 필요하다.

대표 HTML의 응답이 중대하게 지연되거나 실패한 증거는 없었다. 따라서 이번 관측만으로 조회/캐시/이미지 테마를 바꾸는 최적화나 새 기능을 추가하지 않았다. 이는 전 경로·승인 회원·저속 기기 성능 통과 선언이 아니다. 팀 도구의 추가 JS 크기와 홈 랭킹/챔피언 전체 조회는 실제 사용자 지연 또는 데이터 증가가 관측되면 모듈 분석/쿼리 실행 계획과 연결할 조사 지점으로 남긴다. 전후 성능 개선 수치는 없다.
