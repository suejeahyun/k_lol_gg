# 이벤트전 생성 재시도

P2. 생성 UI는 매 submit마다 새 eventId와 요청 키를 만들었고, 렌더 전 중복 제출을 막지 못했다. 응답 유실·서버 오류 뒤 재시도는 같은 대회를 중복 생성할 수 있었다. 원본 실제 TSX handler 검사에서 3 FAIL/정상 거절 수정 1 PASS를 확인했다([원본](event-create-before.log)).

멸망전의 기존 미확정 요청 보존 패턴을 따라 생성 ID·키·본문을 함께 유지한다. 처리 중/미확정 동안 입력을 잠그고 버튼을 `생성 결과 다시 확인`으로 바꾼다. 15초 제한, 동시 submit 가드와 성공 후 이동 잠금을 추가했다. 확정된 입력 거절 후에는 입력 수정을 허용한다. UI 방식은 기존 도메인 한글 label을 사용하며 API 값은 유지한다.

독립 검토에서 유실 뒤 401/403/429가 이전 요청의 실패를 증명하지 못한다는 점을 추가로 확인했다. 해당 응답에도 원래 요청을 보존하고 새 창의 관리자 로그인 링크를 제공한다. 원래 폼을 열어 둔 상태에서 인증을 복구해 재시도할 수 있다. 실제 비밀번호를 변경하거나 새 계정을 만들지 않는다. 불명확한 결과의 페이지 강제 종료·새 탭 간 공유는 이 메모리 내 재시도와 다르다.

[최종 개별 검사](event-create-after.log)는 생성 회귀 7개와 기존 이벤트 UI 계약 3개 PASS. 초기 신규 코드의 ref 렌더 접근/테스트 변수 이름 lint 오류는 별도 상태값과 변수 정정으로 해소했다([초기](event-create-lint.log), [수정 후](event-create-lint-after.log)). 전체 검사·새 빌드 UI·운영 배포는 통합 기록에 별도 연결한다.
