# 1.0.11 신청·투표 가능 상태 독립 검토

검토일: 2026-10-08. 검토자: 구현 담당자와 다른 `release_inventory` 에이전트.
기준은 `63de4f71` 이후 작업 트리의 아래 세 제품 파일과 회귀 변경이다. 1.0.10 태그와 기존 증거는 수정하지 않았다.

## 판단과 범위

새로운 중대 오류나 명확한 과업 차단 요소를 발견하지 않았다. 변경은 모집·투표가 닫힌 상태에서 불가능한 행동의 선행 조건처럼 로그인·승인을 요구하던 표시 순서를 바로잡는 범위다. 활성 모집의 입력, 신청·취소·투표 요청 형식, 본인 기록 조회, 서버 권한과 원장 정책을 변경하지 않는다.

독립 검토에서는 제품 diff, 현재 도메인·repository 계약, 실제 TSX/Page 회귀 구현 및 담당자가 남긴 수정 전후 로그를 읽었다. 제품 편집, 추가 테스트 실행, 빌드, DB·운영 쓰기, 브라우저 조작은 하지 않았다. `git diff --check`는 exit 0이었다.

| 제품 | 독립 확인 결과 |
| --- | --- |
| `destruction-owner-actions.tsx` | 신청과 MVP 영역이 각자의 lifecycle을 먼저 표시한다. 완료·취소에는 신청 종료와 투표 종료를 표시하며 투표 로그인 유도가 없다. 모집 이후 로그인 링크는 본인 신청 확인 목적을 명시한다. 예선·본선 투표 로그인은 기존 상세 페이지의 `?tab=mvp`로 돌아간다. |
| `event-application-actions.tsx` | 서버에서 계산한 `open`이 거짓이면 기존 마감 표시를 인증 분기보다 먼저 반환한다. 모집 중 로그인·승인 안내, `?action=apply` 복귀, 신청 수정·취소 폼과 핸들러는 그대로다. |
| `applications/page.tsx` | 시즌 신청 기간 종료 또는 선택 회차 마감이면 인증·플레이어 연결 안내와 신청 입력보다 마감 상태를 먼저 표시한다. 시즌 없음·조회 실패·잘못된 주소 복구, 회차 이동, 별도 본인 상태와 공개 참가 명단은 유지된다. |

## 서버 계약 및 본인 기록 대조

- 멸망전 `destruction-command-handler.ts`는 일반 신청·취소를 `RECRUITING`, MVP 투표를 `PRELIMINARY`·`TOURNAMENT`에서 허용한다. 확정된 칼바람·증바람 참가자의 승패 수정은 `RECRUITING`·`TEAM_BUILDING`이고 팀이 없을 때 허용하는 기존 예외다. UI는 이를 재정의하지 않고 repository의 `canEditModeRecord`를 계속 사용한다.
- 멸망전 `getOwnApplication`은 대회 상태 필터 없이 대회와 본인 계정 ID로 읽는다. 상세 페이지의 승인 사용자 조회도 변경되지 않았다. 종료 후 신청 상태·주장 지원 여부·본인 기재 승패가 남고, 익명 사용자의 로그인 링크는 이 읽기 과업을 위한 것이다. 읽기 실패의 다시 불러오기 및 불확실한 변경 요청의 동일 요청 재확인 경로도 유지된다.
- 이벤트 `eventAcceptsApplications`는 모집 상태와 모집 시작·종료 시각을 함께 검사하며 DTO의 `applicationsOpen`으로 전달된다. 이번 UI는 그 값을 우선 사용한다. `getOwnApplication` 조회와 기존 승인 사용자의 닫힌 화면은 변경하지 않았다. 이벤트 종료 화면에 본인 신청 상세 표시를 새로 추가한 변경으로 주장하지 않는다.
- 내전 repository의 `canApply`는 활성 플레이어, 시즌 신청 기간, 회차 미마감과 기존 신청 상태를 함께 확인한다. 마감 UI는 동일한 시즌·회차 사실을 사용한다. 승인 사용자의 `myApplication`은 마감과 별도로 조회되고 `myStatus`가 신청·예비·확정·거절·취소 상태, 신청일·회차·선택 라인·출처를 계속 표시한다. 닫힌 회차의 비활성 입력 대신 이 읽기 표시가 남는다.
- 변경 파일 목록과 diff를 대조했으며 `src/modules`, `src/platform`, `src/app/api`, `drizzle`에는 변경이 없다. 인증 경계, 본인 소유권 검사, 멱등성·revision 처리, 모집 정원, 투표 자격, 경기 결과·집계·원장은 이번 변경 대상이 아니다. 1.0.9 갤러리와 1.0.10 확정 진출 표시는 변경되지 않았다.

## 회귀 증거 검토

| 근거 | 확인한 범위와 결과 |
| --- | --- |
| [owner-lifecycle-before.log](owner-lifecycle-before.log) | 실제 멸망전 TSX 검사 9개 중 5 FAIL / 4 PASS. 종료 상태·인증 안내·MVP 로그인 복귀·기록 목적 표시에서 실패했다. |
| [owner-lifecycle-after.log](owner-lifecycle-after.log) | 새 검사 9개와 기존 UI 계약 3개, 12 PASS. 기존 신청 PUT·취소 DELETE·투표 POST 값, 승패 수정 예외, 신청/MVP 포커스, 조회·불확실 응답 복구를 포함한다. |
| [sibling-lifecycle-before.log](sibling-lifecycle-before.log) | 실제 Page/SSR 10개 중 2 FAIL / 8 PASS. 닫힌 시즌·회차와 닫힌 이벤트에서 인증을 먼저 안내하는 원본 동작을 재현했다. |

테스트에서 주입하는 세션·합성 DTO와 mutation stub은 격리 경계다. 실제 JSX·Page 분기와 반환된 링크·핸들러를 실행하지만 실제 인증 왕복, 네트워크 저장, CSS 배치나 브라우저 포커스 구현을 검증한 것으로 세지 않는다. 기존 회귀 기대값을 삭제하거나 실패 출력을 통과로 바꾸는 변경은 없다.

## 남은 릴리스 확인과 제한

이 문서는 소스와 개별 회귀 증거의 독립 검토다. 전체 필수 검사, 최적화 빌드, 운영의 31개 HTTP 표본, 네 화면 폭 및 실제 UI·로그인 복귀 확인과 배포 버전은 루트 담당의 별도 릴리스 증거로 판단한다. 운영 회원의 신청·투표를 변경하지 않아도 마감 안내·로그인 목적·공개 화면을 확인할 수 있다.

검토 범위에서 추가 제품 수정이 필요한 근거는 발견하지 못했다. 사이트 전체 기능이나 실제 기기·외부 연동의 추가 통과를 이 리뷰로 주장하지 않는다.
