## 고정한 조정과 기각 이유

기존의 `품질 위반 개수 → 기존 초과량 합계`를 `기존 초과량 합계 → 품질 위반 개수`로 한 번만 바꿨다. 초과량의 기준과 계수는 그대로다: 최대 라인 25점, 팀 합계 15점, 바텀 합계 10점, 15점 이상인 대면 격차가 1개를 넘으면 추가 역할당 15점. 기준을 느슨하게 하지 않았다.

가능 포지션·원딜과 서폿 각각의 현재 큰 티어 차이 <3을 먼저 탐색하고, 불가능하면 같은 10명에서 바텀 위반 수 → 초과량 → 미등록 역할 인원 순으로 최소화하는 정책도 그대로 유지했다. 이후 자료 부족, 기타 역할 부담과 규칙 1→6의 상대 순서를 바꾸지 않았다. 두 바텀 역할의 등급 차이를 평균내지 않았고 누락 티어는 검증 완료로 간주하지 않았다.

후보의 초과량 자체가 줄었다는 이유로 개선이라 판정하지 않았다. [사전 고정한 프로토콜](../../../scripts/balance-severity/PROTOCOL.md)의 독립 전력·부담 지표로 비교했다. 최대 라인·팀·원딜·서폿·바텀·큰 격차 수·기타 역할 수·부담 차이·부 역할 차이·미등록 수를 함께 비교한 결과는 다음과 같다.

[재현 명령](../../../scripts/balance-severity/README.md)과 [독립 검토](independent-review.md)를 제공한다.

전체 `npm run check`는 계약 728개·단위 1,178개 통과, 기존 별도 DB fixture 필요 테스트 1개 제외, lint 오류 0개·기존 경고 58개, 타입·ERD·이미지·production build 통과다. 신규 연구 집중 테스트 19개, 현재 파일 비밀정보 검사, 운영 의존성 감사(취약점 0개)도 통과했다. [검사 범위](validation.json)를 참고한다.

조정용의 baseline/candidate 각각 15개를 독립 전체 탐색과 대조했고 strict/relaxed 모두 포함했다. 해당 15개는 입력 순서·팀 색 교환도 통과했다. 별도 검토자가 선정 배치 1,000개를 다시 평가하고, 배정 점수에서 지표·등급 제한·138개 실패 검사를 독립 재계산해 일치를 확인했다. 원본 입력과 선수별 점수 구성은 보존됐다.

전체 감사까지 합한 runner의 독립 전체 탐색 대조는 baseline 44건·candidate 15건이다. 선정 배치 1,500개에서 고정/현재 점수와 선수별 구성 일치를 확인했고, 입력 순서·팀 색 44조합과 원본 입력 보존 1,000조합을 검사했다. 아래 추가 안정성 검사와 pilot 반복은 이 수치 및 고유 조합·배치 수와 별도로 기록한다.

추가 [안정성 검사](stability.md)는 이미 열린 조정용에서 층별 2개씩 16개를 사전 지정해 수행했다. 두 선택 방식 모두 입력 순서·팀 색·독립 전체 탐색은 16/16 일치했다. 고유 선수 교환 720개를 두 방식에 각각 적용해 424개 허용·296개 정책 거절을 확인했다. 허용된 교환의 최대 팀 격차 증가는 112.65점, 최대 라인 격차 증가는 57.70점이었다. 실제 서로 다른 선수를 교환한 영향과 역할 보정을 포함하는 수치이며 단순 수치 오차라고 해석하지 않는다.

**작은 점수 변화에 대한 민감도는 남아 있다.** 실효 점수 +0.1에 두 방식 모두 3/16개(18.75%) 추천이 바뀌었다. `S-0803a986088d`에서는 기존 탑 격차 14.92→15.02가 큰 격차 경계를 넘으면서 4명의 자리가 바뀌고, 원래 점수로 재평가한 원딜 격차가 0.02→12.44점으로 증가했다. 다른 사례에서는 팀 격차가 0.93→8.46점으로 증가했다. 이 결과를 “작은 변화에도 안정적”이라고 보고하지 않으며, 기각 후 기준 완화나 추가 튜닝에 사용하지 않았다.

작업자와 안정성 검사가 종료된 후 이전 연구의 고정 입력 9개로 단독 시간 측정을 했다. 첫 준비용 pilot은 보안 검사와 일부 겹쳤으므로 단독 측정으로 제시하지 않는다.

| 최종 단독 시간, n=9 | 중앙값 | p95 | 최대 |
|---|---:|---:|---:|
| 기존 전체 탐색 | 50.42 ms | 2,208.73 ms | 2,208.73 ms |
| 후보 독립 전체 탐색 | 47.12 ms | 2,265.88 ms | 2,265.88 ms |
| 두 선택 방식의 공유 탐색 | 42.62 ms | 2,319.64 ms | 2,319.64 ms |

9개로는 꼬리 지연을 정밀 추정할 수 없고 p95가 최대값과 같다. 4개 worker로 처리한 전체 1,000개의 공유 탐색 중앙값/p95/최대는 2,224.44/3,306.16/4,125.52 ms다. 일부 안정성 검사와도 겹친 경합 환경이며 운영 응답시간이나 새 후보의 속도 개선 근거로 사용하지 않는다.

**이번 조정안의 신규 운영 배포는 하지 않았다.** 사용자가 정한 “개선이 확인된 변경만 반영하고, 근거가 없으면 기존 계산식을 유지” 조건에 따른 결정이다. 유지 대상 운영 source는 `131abbf777a331b056a96ab587957cf654387a78`이다. 이 source의 실제 격리 PostgreSQL·Chromium 생성 → 교환 → 평가 → 저장 → 재평가 흐름은 앞선 작업에서 17항목, DB 계약은 9항목 통과했다. 이를 새 후보 배포·브라우저 통과로 바꾸어 보고하지 않는다. 최종 운영 alias·HTTP 재확인 근거는 [운영 상태](production.md)에 기록한다.
