# 운영 MMR 공식 전환 · 2026-10-08

사용자가 실제 최고관리자로 로그인한 뒤, 운영 1.0.8의 `/admin/balance-ai`에서 정식 확인창으로 재계산을 실행했다. 성공 안내와 generation 2·47회차/104게임·반영 대기 0을 실제 UI에서 확인했다. [완료 화면](mmr-production-transition.png), [전환 후 독립 READ ONLY 대조](mmr-after.json).

## 실행 전 근거

- [최신 환경 바인딩](environment-binding.md): 지정 배포/source, sensitive 환경 메타데이터, 인증 probe 표식, 공개 집계와 DB 집계가 일치했다. 민감 URL 원문 비교는 불가했다.
- [최신 영향 분석](mmr-transition-impact.json): generation 1 → 2, V1_INTERNAL_MMR_1 → V2_DETERMINISTIC_1, 42/91 → 47/104, 프로필 81 → 93. 기존 81명 중 점수 변경 65명(25명 상승/40명 하락), 변화 -10.17~+7.39점. 활성 회원은 당시 79 → 91명이다. 이전 날짜의 활성 회원 수를 재사용하지 않았다. 대기 이벤트 13개를 별도 경기 13개로 계산하지 않는다.
- [백업·복원](mmr-before-transition-backup.json): 새 exported snapshot 백업 143,099,592바이트, SHA256 `e293f8501a8ed308daab2ec06e74cdd5f33f8c493f95de435dd20db458d7e2d9`. 로컬 격리 복원 후 192개 테이블 행 수·논리 스키마·제약 922개·MMR 9개 테이블 내용·migration0047 일치. invalid constraint 0, 임시 cluster 종료 확인. 운영 DB는 읽기 전용으로 조회했고 원본을 복원 대상으로 사용하지 않았다.
- [전환 직전 기준](mmr-before.json): 원 generation 1의 프로필·포지션·경기 이벤트·실행 이력 전체 해시, 수동 조정, 미소비 이벤트와 원장 checksum을 보존했다. 외부 식별자·개인정보 원문은 증거에 남기지 않았다.

백업은 무시된 `.private/recovery/`의 새 UUID 경로에 보관한다. provider PITR와 Blob 파일 전체 복구를 검증한 것은 아니다.

## 실제 실행과 결과

운영 화면을 새로고침해 SUPER_ADMIN·generation 1·V1·반영 대기 13을 재확인했다. `전체 원장 재계산` → `확인 후 재계산`을 한 번 실행했다. 처리 중 관련 필드와 버튼이 잠기고, 완료 후 `전체 원장을 다시 계산했습니다.`와 generation 2·47/104·대기 0을 표시했다. 412/timeout/재전송은 발생하지 않았다. 수동 조정이나 실제 회원의 신청·경기·계정 시험 변경은 하지 않았다.

[전환 후 검증](mmr-after.json)은 다음을 모두 통과했다.

- 정확히 한 단계 증가, V2 공식 활성화, ADMIN 실행 및 실제 SUPER_ADMIN 역할.
- 현재 원장의 순수 재계산과 게시 checksum·93개 프로필·465개 포지션·1,040개 경기 이벤트의 필드별 결과 일치.
- 원 generation 1 전체 해시 보존, 수동 조정과 원본 입력 원장 checksum 불변.
- 기존 대기 이벤트 13개를 정확히 소비하고 남은 대기 0.
- 감사·outbox 연결, 성공 명령 영수증 1건, 같은 읽기 snapshot의 요약 불변.

예약 자동 갱신은 별도 자연 실행 관측으로 확인한다. 이 문서의 전환 성공을 cron 실행 성공으로 대체하지 않는다.

공개 `/rankings/mmr` 실제 브라우저에서도 집계 차수 2·공개 경기 47·반영 대기 0·활성 선수 91명을 확인했다. 기준 포지션을 탑으로 바꾸어 찾기 → 다음을 실행하면 `탑 MMR 순위`, `2 / 5`, 선택값 TOP과 다음 주소의 position=TOP이 유지됐다. 해당 PC viewport에서 가로 넘침은 없었다. 개인 이름과 점수 원문은 별도 증거에 저장하지 않았다.

## 복구 기준

전환 후 집계 불일치·오류 또는 소비 누락이 있으면 추가 재계산을 반복하지 않고 현 원장·영수증과 사전 해시를 먼저 대조한다. 기존 generation 1은 보존돼 있으나 임의 SQL로 게시 포인터를 바꾸지 않는다. 웹 배포를 되돌려도 DB 계산 버전은 되돌아가지 않는다. 원본 경기와 조정 원장이 보존된 상태에서는 검증한 전진 수정을 우선한다. 전체 DB 복원은 백업 이후의 다른 운영 변경을 잃을 수 있어 별도 복구 결정이 필요하다.
