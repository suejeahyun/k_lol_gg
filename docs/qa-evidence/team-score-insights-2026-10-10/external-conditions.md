# 운영 확인과 외부 조건

기준일: 2026-10-10 KST. 이 문서는 이번 작업에서 관측한 사실과 아직 필요한 외부 조건을 구분한다. 전체 구현·검증은 [통합 기록](README.md), 격리 복구 결과는 [복구 요약](recovery-result.json)을 따른다. 복구 요약은 통합 담당자가 전달한 실행 결과를 정리한 파일이며 원본 콘솔 로그가 아니다.

## 남은 조건과 최소 다음 행동

| 대상 | 이번에 없는 조건 | 사용자의 최소 다음 행동 | 준비 후 확인할 결과 |
|---|---|---|---|
| 인증된 운영 관리자 UI | 유효한 관리자 로그인 완료 확인 | 현재 열어 둔 운영 로그인 화면에서 본인의 관리자 계정으로 로그인한 뒤 완료 여부만 알려 준다. 비밀번호·인증 코드는 채팅에 전달하지 않는다. | 먼저 점수 화면·목록·이력의 조회와 확인창 열기·취소를 확인한다. 실제 점수 저장은 지정된 정상 운영 변경이 있을 때 그 대상·값으로 확인한다. |
| 카카오 실기기 | MessengerBot R가 설치된 기기의 접근 경로, 사용할 방과 허용된 시험 범위 | 사용할 기기와 시험 대상 방 1개를 지정하고 현재 설치본을 확인할 수 있게 한다. | 설치 버전·방 연결·읽기 응답을 먼저 대조하고, 지정된 범위에서 실제 수신과 서버 ACK·중복 방지·절전/재시작 복구를 각각 확인한다. 서버 ACK만으로 사람이 메시지를 받았다고 판정하지 않는다. |
| Riot RSO | 별도 OAuth 승인 상태와 실제 소유자의 동의 진행 | 승인 여부와 해당 앱을 관리할 수 있는 경로만 알려 준다. 이미 승인됐다면 소유자가 연결·동의 화면을 진행할 수 있어야 한다. | 설정 준비도, 등록 callback, 소유자의 동의·연결·해제 동작을 확인한다. 일반 Riot 공개 전적 동기화와 RSO 소유권 확인을 구분한다. 비밀값은 기존 민감정보 설정 경로에서 다룬다. |
| provider PITR·Blob 복원 | 별도 복원지, 복원 시점, 사용할 권한·비용/중단 범위 | 복원할 별도 대상과 시점, 허용 비용·중단 범위를 정한다. 기존 운영 대상을 덮어쓰는 선택을 기본값으로 삼지 않는다. | 지정 시점의 DB 복원, Blob 원본·DB 참조·checksum 대조, 실제 복구 시간과 손실 범위를 측정한다. 로컬 논리 복구 성공과 별개의 근거로 남긴다. |
| 실제 OCR | 사용이 허용된 대표 경기 이미지와 비교할 정답 | 개인정보를 가린 대표 이미지와 확인된 승패·선수·챔피언·KDA를 제공한다. | 합성 이미지가 아닌 실제 자료에서 필드별 정확도·누락·수동 수정과 재시도를 확인한다. 결과를 실제 경기로 공개하지 않는다. |

가장 먼저 필요한 행동은 운영 관리자 재로그인이다. 나머지 항목은 대상 기기·방·제공자·자료가 준비된 것부터 각각 진행할 수 있으며, 한 항목의 부재가 로컬 구현·격리 검증 전체를 중단시키는 조건은 아니다.

## 사용할 수 있는 확인 경로

- 관리자 `/admin`의 **자동 작업과 연동 상태**는 기존 권한 경계를 거쳐 읽기 전용 snapshot으로 집계한다. 인증 복구 후 현재 상태를 확인할 첫 경로다. [진단 런북](../../operations/ADMIN_OPERATIONAL_HEALTH_RUNBOOK.md)은 마지막 성공 시각·최근 요청·ACK와 실기기 수신의 의미를 구분한다.
- 카카오 기기·방 연결 절차는 [카카오 런북](../../operations/KAKAO_V2_CUTOVER_RUNBOOK.md)을 참고한다. 문서의 과거 버전·migration 숫자를 최신 설치 확인으로 간주하지 않는다. 실제 배포와 설치본은 통합 기록의 최신 근거로 대조한다.
- RSO 준비도·공개 전적 연결의 구분은 [Riot 활성화 런북](../../operations/RIOT_ACTIVATION_RUNBOOK.md)을 따른다. 이 문서 조사에서는 제공자 포털을 열거나 신규 승인을 신청하지 않았다.
- [MMR 읽기 전용 검증 스크립트](../../../qa/mmr-transition-verify-readonly.ts)는 대상 fingerprint, 읽기 전용 transaction, aggregate·digest 출력과 `ROLLBACK`을 사용한다. 기존 공식 전환의 before/after 기준을 요구하므로 일반 운영 상태 조회용으로 무조건 재실행하지 않는다. 현재 대상과 적합한 기준 파일을 확인하지 않은 상태에서는 실행하지 않았다.
- [스토리지 probe 스크립트](../../../scripts/operations/probe-storage.ts)는 이름과 달리 내부 job에 서명된 `POST`를 보내므로 읽기 전용 확인이 아니다. 이번 조사에서 실행하지 않았다. provider 저장소 왕복 시험과 전체 복원은 [복구 런북](../../operations/DATABASE_RECOVERY_RUNBOOK.md)에 따라 별도로 다룬다.
- 현재 도구 메타데이터에서는 이 작업의 Vercel·Neon·Riot·카카오 기기를 직접 다루는 전용 connector를 확인하지 못했다. 이 사실이 계정 연결 자체가 없거나 서비스가 장애라는 뜻은 아니다. 새 connector 설치·계정 연결은 이번 문서 작업에서 수행하지 않았다.

## 이번 문서 작업에서 실행하지 않는 범위

운영 환경변수·키·feature flag 변경, 회원을 대신한 Riot 연결·동의, 관리자 세션 생성·권한 승격, 운영 점수·신청·경기 변경은 실행하지 않는다. 임의 카카오 방이나 수신자에게 시험 메시지를 보내지 않는다. 예약 작업·수동 probe·OCR 제공자 호출·장시간 부하를 현재 상태 조회로 취급하지 않는다.

provider 복원·유료 자원 생성·운영 DB 덮어쓰기·Blob 업로드/삭제도 지정된 대상과 작업 범위 없이 실행하지 않는다. 기존 비밀값을 읽어 채팅·문서·QA 결과에 복사하거나 과거 관측을 새 측정 결과처럼 기록하지 않는다. 이 경계는 이번 문서 정리의 범위이며, 이미 승인된 로컬 구현·격리 검증·통합 담당자의 별도 작업을 취소하는 지침이 아니다.
