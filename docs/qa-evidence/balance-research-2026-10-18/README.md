# 실제 자료 기반 팀 밸런스 비교

**결론: 기존 추천 계산식을 유지한다.** 실제 선수 1,000개 고유 조합과 921,331,808개 고유 배치를 조사했다. 조정용 500개에서 추가한 두 선택 방식은 효과가 없거나 다른 격차를 악화시켜 기각했다. 검증된 운영 변경은 경기 표본이 0건인 선수를 자료 부족 인원에서 누락하던 진단 수정이다. 추천 순위나 개인 점수의 개선으로 보고하지 않는다.

이번 검증에서 말하는 최선은 확보한 자료와 명시된 정책 안에서 선택한 추천이다. 가상 편성의 실제 승패는 알 수 없으며 아래 비교를 실제 경기 승률 개선으로 해석하지 않는다. [기계 판독 실험 결과](experiment-report.json), [자료 집계](data-inventory.json), [독립 검토](independent-review.md), [변경 안내](../../patch-notes/inhouse-fairness-v2.0.2.md)를 함께 제공한다. [운영 배포·동일 source·복구 근거](production.md)를 확인했다. 후보·운영 HTTP 각 12조건과 source CI가 통과했다.

## 3. 유지한 추천의 전체 1,000개 지표

이 표는 기존 계산식의 남은 격차이며 개선율이 아니다. 단위는 기존 전력 점수 또는 명/역할 수다. 부담은 주=0·부=1·기타=2로 독립 집계했다.

| 지표 | 평균 | 중앙값 | p95 | 최대 |
|---|---:|---:|---:|---:|
| 팀 합계 차이 | 6.165 | 5.01 | 14.44 | 59.76 |
| 최대 대면 격차 | 25.003 | 22.87 | 51.47 | 88.65 |
| 15점 이상 격차 역할 수 | 1.400 | 1 | 4 | 5 |
| 원딜 개별 격차 | 12.214 | 8.30 | 34.58 | 88.65 |
| 서폿 개별 격차 | 10.956 | 8.00 | 32.10 | 58.70 |
| 바텀 합산 격차 | 8.274 | 5.96 | 26.25 | 79.60 |
| 양 팀 포지션 부담 차이 | 1.297 | 1 | 3 | 7 |
| 미등록 역할 배정 | 0.845 | 1 | 2 | 4 |
| 역할 표본 0건/없음 인원 | 5.831 | 6 | 9 | 10 |

조합당 평균 주 4.407명, 부 3.555명, 등록된 기타 1.193명, 미등록 0.845명이다. 규칙 1→6 위반 조합 수는 각각 **213 / 13 / 23 / 0 / 139 / 108**이며, 규칙 1의 위반 총수는 220건이다. 관측 가능한 바텀 티어 위반은 0이지만 **티어 미확인까지 검증 통과한 뜻은 아니다**. 조합당 평균 1.631명의 현재 티어가 없고, 688개 조합은 미확인 티어를 포함한다(312개는 10명 모두 확인). 바텀에 한정한 전체 검증 불가 조합 수는 별도 보존 지표가 없어 미집계로 남긴다. 아래 최악 사례는 원딜 제한을 검증할 수 없다.

단독 프로세스의 고정 pilot 9개에서 기존 전체 탐색 시간은 중앙값 **48.2ms / p95 2,365.7ms / 최대 2,365.7ms**였다. 같은 탐색을 세 선택 방식이 공유한 시간은 **42.8 / 2,647.0 / 2,647.0ms**였다. 소표본 p95는 최대와 같고 운영 속도 개선으로 해석하지 않는다. 전체 연구의 4 worker 공유 탐색은 **1,860.7 / 3,820.1 / 5,927.3ms**로, 자원 경쟁을 포함한 실험 측정이다.

## 4. 대표 사례와 남은 한계

- **기각 사례, 실제 관측 조합 `R-46292d0e6e61`:** SUB_SOFT_1이 부 역할 인원 차이를 2→0으로 줄였지만 전체 양보 부담 차이는 0→2, 최대 대면은 12.53→15.69, 큰 격차 역할은 0→1로 악화했다. 개선 사례라고 채택하지 않았다.
- **남은 최악 대면, 실제 선수 재조합 `R-886841e512d5`:** 팀 합계 차이는 0.51점이나 탑/정글/미드/원딜/서폿 격차는 42.79 / 39.80 / 14.09 / 88.65 / 19.64점이다. 큰 격차 4곳, 미등록 배정 2명, 현재 티어 누락 2명, 역할 표본 부족 7명이다. 원딜 현재 티어가 미확인인 상태를 제한 통과로 보고하지 않는다.
- **진단 개선:** 실제 14개 조합의 참가자 배정 140건에서 표본 부족 집계가 45→75건으로 정정되었다. 0표본 누락 30건을 바로잡았고 13개 조합에 영향이 있었다. 이는 고유 선수 30명이라는 뜻이 아니다. 추천의 독립 지표 변화는 0이었다.
- **교환 민감도:** 실제 14개 조합의 630개 고유 교환을 기존·현재로 각각 평가했다. 각 344개 허용·286개 정책 거절. 입력 역순·팀 색 반전은 모두 통과하고 실제 유효점수 +0.1에서 배치 변경 0/14였다. 허용 교환의 팀 격차 증가 최대 134.63점, 최대 대면 증가 63.51점은 여전히 남는다. 역할 감점·실력 차이에 따른 민감도이며 실제 승률 변화가 아니다.

[대표 사례의 양 팀 불리 라인·바텀 확인 상태](representative-cases.json), [실제 안정성·진단 비교](real-stability.json), [합성 경계](synthetic-stability.json)에 세부 근거가 있다. **실데이터에서 채택할 만한 추천 개선 사례는 없었다.** 자료 부족 진단 수정과 추천 품질 개선을 구분한다.

## 5. 채택한 변경과 유지한 수치

운영 변경은 `noSampleCount` 조건을 `sampleSize === null`에서 `sampleSize === null || sampleSize === 0`으로 정정한 것이다. 역할 표본이 0인데 전체 경기만 있는 경우도 자료 부족으로 집계한다. 점수·추천 서명·순위·원본 입력은 바뀌지 않는다. 기능 버전은 **inhouse-fairness-v2.0.2**, 점수 계산식은 **V2_INHOUSE_RELAXED_2026_10_16**을 유지한다.

기존 개인 기준의 최고/현재/내전 비중 0.6/0.3/0.1, 역할 감점과 MMR·신뢰도·최근 기록 계수, 대면 동급 3점·최대 대면 권장 25점·큰 격차 15점·팀 합계 15점·바텀 합계 10점 기준을 유지한다. 새 가중치나 복잡한 모델을 추가하지 않는다. 주·부·기타 감점·경기 수 신뢰도·오래된 기록 감쇠·최근 기록 가중치의 변경은 시간 누출 없는 결과 자료가 없어 근거 부족으로 보류했다. SUB_TIE와 SUB_SOFT_1은 위의 실제 비교 결과로 기각했다.

자동 추천·수동 미리보기·서버 평가·선택·저장·재평가는 기존 공통 도메인과 정책을 사용한다. 자동 조정 시 변경 역할과 남은 경고를 표시하며 수동 결과를 최선의 자동 추천이라고 부르지 않는다. 과거 초안의 점수 JSON은 덮어쓰지 않는다.

서로 다른 10명·팀당 5명·각 역할 1명을 보존한다. 등록 역할과 원딜·서폿 각각의 현재 큰 티어 차이 3단계 미만을 먼저 탐색하고, 불가능하면 바텀 위반 수 → 초과량 → 미등록 역할 인원 → 기존 전력·부담 → 규칙 1→6 순서로 비교한다. 미확인 티어는 통과로 간주하지 않는다.

## 자료 해석

운영 PostgreSQL은 한 번의 `REPEATABLE READ READ ONLY` 트랜잭션에서 조회하고 `ROLLBACK`한다. 동일 트랜잭션에서 실제 운영 rating provider를 실행한다. 이름·계정·인증 자료는 수집하지 않으며 원본 UUID는 일시적 결합 키로만 쓴다. 분석 자료는 식별자를 바꾸어 Git에서 제외된 `.private/balance-research/`에 보관한다.

등록 역할은 실제 신청·초안에서만 가져온다. 경기에서 맡았던 역할을 등록된 주·부 역할로 추정하지 않는다. 관측된 과거 10명 조합도 현재 고정 스냅샷으로 다시 편성하는 실험이며, 과거 예측 검증과 구분한다. 참가자 조합은 정렬한 10명 집합으로 중복을 제거하고 팀 색·입력 순서·반복 실행은 사례 수에 더하지 않는다.

티어별 관측 시각은 보관되어 있지 않다. 등록부 수정 시각을 티어 갱신 시각으로 간주하지 않는다. 재평가 시 초안의 참가자 rating snapshot은 갱신될 수 있으므로 이를 과거 경기 전 자료로 사용하지 않는다. 과거 후보의 배치·점수 JSON은 유지된다.

## 실험 후보와 보류 범위

1. 기존 계산식 `BASELINE`.
2. `SUB_TIE`: 모든 기존 우선순위와 숫자 비용이 같은 경우에만 양 팀 부 포지션 인원 차이를 비교한다.
3. `SUB_SOFT_1`: 기존 우선순위 뒤의 비용에 부 포지션 인원 차이 × 1을 추가한다.

개인 MMR·관리자 보정·등록 역할은 수정하지 않는다. 주/부/기타 감점, 역할 숙련, 경기 수 신뢰도, 오래된 기록, 최근 솔로 기록 가중치를 자기 점수에 맞춰 조정하지 않는다. 경기 전 정보와 결과의 시간 연결이 충분하지 않아 이들 점수 가중치의 학습·보정은 보류한다. 두 사전 후보가 악화 기준을 통과하지 못하면 추가 수치 탐색을 중단하고 기존 계산식을 유지한다.

## 재현

명령은 저장소 루트에서 실행한다. `snapshot.ts`의 첫 인수는 접근이 허용된 로컬 환경 파일 경로이며 내용이나 연결 문자열을 명령행·로그에 출력하지 않는다. 운영에 초안·참가자·경기·보정 쓰기를 만들지 않는다.

```powershell
node --import tsx scripts/balance-research/freeze-baseline.ts
node --import tsx scripts/balance-research/snapshot.ts <private-env-file>
node --import tsx scripts/balance-research/prepare-rosters.ts
node --import tsx scripts/balance-research/pilot.ts
node --import tsx scripts/balance-research/run.ts tuning
# tuning 통과 후보만 validation, 그 뒤 고정된 하나의 후보만 final
node --import tsx scripts/balance-research/run.ts validation
node --import tsx scripts/balance-research/run.ts final
```

기존 후보가 모두 탈락한 뒤 나머지 참가자 조합의 기본 계산을 점검할 때는 `--audit`를 사용한다. 이는 탈락한 후보의 최종 평가를 열어 다시 조정하는 과정이 아니다. 최초 스냅샷·기준 소스·프로토콜·참가자 집합의 해시로 실행 조건을 식별한다. 새 운영 스냅샷을 다시 추출하면 데이터 시점이 달라지므로 같은 실험 결과라고 표시하지 않는다.

이번 연구에서 실제 수행한 후속 명령은 아래와 같다. 정확한 재현에는 공개 해시와 같은 private 스냅샷·참가자 manifest가 필요하다. 원본 개인정보를 공개 저장소에 넣지 않기 때문에 공개 파일만으로 동일 선수 입력을 복원할 수는 없다.

```powershell
node --import tsx scripts/balance-research/run.ts validation --audit
node --import tsx scripts/balance-research/run.ts final --audit
# 연구 worker 종료 후 단독 시간 재측정
node --import tsx scripts/balance-research/pilot.ts
node --import tsx scripts/balance-research/inventory-summary.ts
node --import tsx scripts/balance-research/publish-report.ts
node --import tsx scripts/balance-research/stability.ts
node --import tsx scripts/balance-research/real-stability.ts
```
