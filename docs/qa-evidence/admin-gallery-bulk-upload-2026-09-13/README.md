# 관리자 갤러리 다중 업로드 QA

## 범위와 판정

- 확인됨: `/admin/images/new`에서 제목·설명과 최대 5장 이미지를 한 화면에서 선택한다.
- 확인됨: 사용자의 한 번 등록 동작을 내부의 DRAFT 생성 → 파일별 SHA-256 검사·순차 업로드 → 성공 자산 일괄 연결로 처리한다.
- 확인됨: 기존 갤러리는 남은 슬롯만큼 여러 장을 추가하고 선택 순서를 공개 표시 순서로 보존한다.
- 확인됨: PNG/JPEG/WebP, 장당 4MiB, READY 자산, same-origin, `If-Match`, 멱등성 키와 게시 상태 제한을 유지한다.
- 확인됨: 잘못된 파일은 정상 파일의 5장 슬롯을 차지하지 않으며, 부분 실패 파일명·원인을 URL이 아닌 1회성 session storage로 편집 화면에 전달한다.
- 확인됨: 업로드 또는 최종 연결이 실패해도 성공한 READY 자산을 보존하고 재연결 안내를 표시한다.
- 미반영: 운영 관리자 계정과 실제 Blob을 사용한 브라우저 업로드 E2E.

## 복구와 남은 위험

- DB migration과 기존 자산 변경은 없다. 문제가 있으면 애플리케이션을 직전 배포로 되돌린다.
- Blob 여러 건과 마지막 갤러리 연결은 하나의 외부 원자 트랜잭션이 아니다. 마지막 연결이 실패한 READY 자산은 삭제하지 않고 편집 화면에서 다시 연결한다.
- 실제 운영 Blob 쓰기 E2E는 테스트용 DRAFT를 사용하고, 사용자 콘텐츠를 덮어쓰지 않아야 한다.

## 다음 권장 패치

1. 파일별 미리보기와 드래그 순서 변경이 실제 운영에서 필요한지 확인한다.
2. READY 미연결 자산을 제목별로 더 쉽게 찾는 필터를 제공한다.
3. 업로드 단계별 실패율을 파일명·내용 없이 집계한다.
