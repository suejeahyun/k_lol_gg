# 홈 랭킹 쇼케이스 1.0.0 검증

## 요청과 발견한 문제

홈 순서를 소개 → 랭킹 → 주요 작업 → 소식 → 내 활동 → 기록으로 변경한다. 기존 홈에서는 랭킹이 소식과 내 활동보다 아래에 있었고, 승률·최다 참여자·최다 MVP가 각각 카드로 반복되어 시선이 분산됐다. 하단에는 소식 패널에 이미 나온 제한된 피드 건수가 반복되었으며, 이 숫자는 전체 기록 건수로 오해할 여지가 있었다.

## 변경

- 기존 순위 계산과 동률 처리 함수를 유지하고, 서버에서 공개 닉네임·Riot ID·표시 지표만 직렬화해 하나의 랭킹 캐러셀에 전달한다.
- 승률·참여·MVP를 한 번에 하나씩 보여주며 배경색, 왕관, 메달, 1위 강조 시상대, 짧은 전환 효과를 적용한다. 데스크톱에서는 2·1·3위, 모바일에서는 1위 아래에 2·3위를 배치한다. DOM 읽기 순서는 1·2·3위다.
- 이전/다음, 세 위치 버튼, 좌우 키, 터치 스와이프를 지원한다. 자동 넘김은 사용자가 재생을 선택할 때 시작하고 7초 간격으로 전환한다. 마우스가 올라가면 일시 정지하며 수동 조작·캐러셀 내 다른 요소의 포커스는 재생을 중지한다. 숨겨진 탭에서는 전환하지 않는다.
- 시즌 이름과 최소 참여 기준을 표시한다. 빈 결과·환경 미준비·조회 오류 안내를 유지한다. 순위가 없는 경우 가짜 플레이어를 넣지 않는다.
- 중복 피드 집계와 추상적인 홍보 문구를 제거하고, 마지막 기록 영역에 플레이어/경기 목록으로 이동하는 링크를 추가한다.

## 검증 결과

- `npm run check` 통과: lint 오류 0, 기존 경고 58; TypeScript; ERD 드리프트 검사; 계약 테스트 445 통과; 단위 테스트 1,036 통과·1개 기존 skip·실패 0; 여성 안내 챔피언 68개 이미지 검사; Next.js production build.
- `tests/home-current-state.test.mjs`: 요청한 여섯 섹션의 순서와 기존 공개 데이터 계약 검증.
- 격리 PostgreSQL 18에서 합성 랭킹 3명 및 긴 닉네임 fixture 사용. 승률 80%, 참여 40회, MVP 12회가 각 슬라이드 1위로 정확히 바뀌는 것을 브라우저에서 확인.
- 다음 버튼, 이전 버튼의 첫→마지막 순환, 위치 버튼, ArrowRight, 자동 넘김의 실제 전환 및 정지 확인. 화면에는 활성 슬라이드의 프로필 링크 3개만 존재하고 수동 상태의 live region은 polite.
- 320×844, 390×844, 768×1024와 기본 데스크톱에서 가로 overflow 없음. 모바일 조작 버튼 6개 모두 44×44px. 긴 이름은 말줄임하되 링크의 접근성 이름과 title에 전체 이름을 보존.
- 랭킹 fixture 없이 재시작해 빈 상태, 캐러셀 조작부 부재, 동일한 홈 순서, 모바일 overflow 없음 확인. [빈 상태 캡처](local-empty-mobile.jpg).
- 기존 격리 HTTP harness의 10개 경계 검사 통과. [결과](local-http.json). 운영 DB에 합성 데이터를 저장하지 않음.
- 모바일 기기의 실제 터치 스와이프와 OS 동작 줄이기 설정 전환은 실기기에서 검사하지 않았다. 스와이프의 가로/세로 거리 판정 및 `prefers-reduced-motion` 애니메이션 제거는 코드 검토로 확인했다.

## 재현

PowerShell에서 `PG_BIN_DIR`을 PostgreSQL 18 bin 경로로 지정한 뒤 `npm run check`를 실행한다. `V2_UX_QA_RANKING=true`, `V2_UX_QA_HOLD=true`로 `npx tsx scripts/test-db/run-ux-http-qa.ts`를 실행하면 격리 fixture 주소를 출력한다. 순위 없는 상태는 RANKING을 false로 실행한다. `.tmp/ux-qa/stop` 생성으로 서버와 일회성 클러스터를 정리한다. 이전 stop 파일은 다음 실행 전에 삭제한다.
