# 파티 복사 양식 재설계 — 설계 검토 1.0

상태: 설계 문서만 작성. 애플리케이션 소스·휴대폰 파일·운영 데이터·운영 배포 변경 없음. 기능 릴리스·Git tag는 아직 발급하지 않는다.

[설계안과 실제 메시지 시안](../../architecture/0011-kakao-party-editable-copy-flow.md)

## 요구사항

- N인파티 → 빈 양식 → 작성 전송 → 등록 완료와 전체 구인 목록 → 구인상세 N으로 다시 편집 → Nㅉ 마감.
- 사용자 확정: 이름 추가·삭제 및 시작·게임 수정 모두 허용. 마감은 번호 포함.
- 상단 양식코드, 짧은 구획, 번호형 참가 칸·예비 칸으로 읽기 쉬운 시안을 제시한다.

## 읽기 검토 근거

- 현재 파티 코드는 추가 전용이며 시간·게임 변경을 막는다. 앞선 내전 패치와 다른 경로다.
- R24 폰은 파티 헤더·번호행으로 감지해 원문을 전달하므로 상단 코드 배치는 서버 변경으로 수용 가능한 구조다. 실제 설치폰은 확인하지 않았다.
- 장식선은 다음 줄 입력을 지원하는 파서에서 값으로 읽힐 수 있다. 시안은 코드 아래·시작 위 한 곳에만 장식선을 둔다.
- 현황은 현재 20건 제한이고 상세도 목록을 이용한다. 21번째 이후 누락 방지를 설계에 포함했다.
- 현황을 읽을 때 모든 파티의 원본 코드를 발급하는 비용과 5초 전송 제한을 구현 검증 대상으로 기록했다.
- 저장 성공 후 현황 조회 실패를 구분하는 기존 함수가 있어 재사용 가능하다.
- DRAFT 상세와 DRAFT Nㅉ는 현재 경로에서 지원되지 않아 설계에 확장 범위를 명시했다.

## 검증 수준

소스 읽기와 독립 검토로 현재 동작·필요 변경을 대조했다. 문서 변경에는 앱 전체 검사·DB 테스트·실제 봇 송신을 실행하지 않는다. 구현 후 필수 검사 목록은 설계안 8절에 있다.

## 다음 구현 추천

1. **양식 편집 병합부터 구현**: 현재 추가 전용 가드가 삭제·시간 변경을 막는 직접 원인이므로, 표시 변경 전에 DB의 변경 보존 계약을 고정한다.
2. **상세 직접 조회와 가벼운 전체 현황**: 현재 20건 제한·원본 코드 일괄 발급을 제거해 상세 누락과 응답 지연을 함께 줄인다.
3. **DRAFT 재조회·취소와 실패 안내**: 잘못 만든 빈 양식도 찾고 정리할 수 있게 하며, 저장 후 조회 실패를 저장 실패로 안내하지 않는다.
