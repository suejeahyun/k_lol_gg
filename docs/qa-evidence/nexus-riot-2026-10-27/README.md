# NEXUS.GG 1.0.1 검증

## 범위

Riot 설정 정책의 DB 선택을 공통 서비스별 DB 검증으로 통일한다. 기존 런타임에만 있던 `DATABASE_URL` 임시 별칭을 제거하고 운영 health, API probe, 자동 레이팅에서도 `NEXUS_DATABASE_URL`을 사용한다. K-LOL은 계속 자신의 `DATABASE_URL`을 사용한다.

전용 DB 누락·잘못된 URL·동일 Neon DB의 pooled/direct 주소를 차단하는 회귀 테스트를 추가했다. 서버 실행 환경의 서비스 ID가 누락된 경우에는 빌드에서 고정한 서비스를 사용해야 한다.

## 현재 외부 연동 상태

- 기존 Riot API 키 공유는 사용자 승인 완료.
- Vercel의 기존 키는 `sensitive` 유형으로 복호화 조회에 원문을 반환하지 않았다.
- 보관된 로컬 기존 키를 KR 상태 API에 사용한 결과 401. 키 값이나 응답 본문은 기록하지 않았다.
- NEXUS의 Riot 환경변수와 DB 기능 플래그는 아직 활성화하지 않았다. 유효한 키를 받아 검증한 후 진행한다.
- 기존 K-LOL 프로젝트·DB·키를 변경하지 않았다. RSO 설정은 별도이며 복사하지 않았다.

## 검증·배포

- 최종 `npm run check` PASS: lint 오류 0·기존 경고 87, 타입·ERD·가이드 이미지·production build 통과.
- 계약 테스트 741 PASS, 단위 테스트 1,201 PASS·기존 fixture 1 SKIP.
- Riot 설정 focused 14/14 PASS. NEXUS import 이후 실행 환경의 서비스 ID를 제거하는 자식 프로세스 회귀 포함.
- 독립 리뷰에서 찾은 실행 환경 ID 누락 문제를 수정하고 재검토했다. 추가 지적 없음.
- 최초 전체 검사에서 로컬 환경 파일에 중복 인용부호가 남은 문제를 확인했다. 비공개 로컬 파일을 정규화한 뒤 전체 검사를 다시 통과했다. 운영 환경변수는 정상이며 변경하지 않았다.
- 운영 배포는 source 확정 후 별도 `production.json`에 기록한다. 실제 외부 Riot 연결은 여전히 유효한 키 입력 대기다.
