# GG HUB 자동 개설 연결 및 운영 worker 검증

2026-10-29 운영 HUB의 전용 자격증명을 사용하는 worker가 합성 QA 사이트를 `SUCCEEDED` / `VERIFIED`까지 준비했다. 중앙 사이트는 `AWAITING_OWNER`였으며 공개하지 않았다. **실패한 같은 작업을 수정 후 재개하여 완주한 검증**으로, 최초 요청부터 중단 없이 성공한 새 개설로 기록하지 않는다. 사후 검증과 QA 정리를 완료하고 예약 실행을 활성화했다. 빈 큐에서 자연 예약 호출이 HTTP 200으로 완료된 것도 확인했다. 사이트 생성 완주는 인증된 수동 worker 호출로 검증한 결과와 구분한다.

이전 [개설 스튜디오 0.1.0 검증](../community-site-studio-2026-10-29/README.md)과 [당시 provider 검증](../community-site-studio-2026-10-29/provider-live.md)은 해당 시점의 근거로 유지한다. 이번 검증은 이전에 삭제한 QA 자원을 재사용하지 않았다.

## 공급자 연결과 비용 범위

새 프로젝트 생성 권한이 있는 팀 범위의 전용 Vercel 토큰을 발급했다. 유효 기간은 90일, 만료일은 **2027-01-27**이다. HUB의 Vercel·Neon·마스터 키·cron 자격증명은 production 전용 `sensitive` 환경 변수로 연결했다. 서버 자동 개설 설정과 하위 엔진 설정은 [환경 확인 결과](environment.json)에 있다. 토큰과 DB 연결 문자열은 공개 증거에 포함하지 않는다.

사용자는 기존 요금제의 사용량에 따른 추가 비용을 허용했다. 새 고정 월정액 구독이나 요금제 업그레이드는 수행하지 않았다. 사용량 비용이 발생하지 않는다고 보장하는 구성은 아니다.

## 실제 발견한 두 결함과 재검증

### Blob 연결의 빈 HTTP 201 응답

최초 QA는 `PROJECT_CREATED`에서 `INVALID_PROVIDER_RESULT`로 멈췄다. 저장소와 연결은 만들어졌지만 일괄 환경 변수 설정까지 진행하지 못했다. 최초 조사 때는 원인을 확정하지 못했고 QA 토큰 환경 변수의 보호 유형만 수동으로 `encrypted`에서 `sensitive`로 변경했다. 당시 기록과 뒤의 빌드 실패는 [첫 QA 결과](failed-probe.json)에 보존했다.

새 엔진의 별도 QA에서도 같은 단계가 실패했다. 정확히 소유한 빈 QA 저장소의 연결을 해제한 뒤 다시 연결하여 응답 형식을 확인한 결과, Vercel의 Blob 연결 POST는 **HTTP 201·본문 0바이트·Content-Type 없음**을 반환했다. 기존 adapter가 이를 JSON으로 읽어 실패한 것이 확인됐다. [응답 형식 증거](blob-connection-response.json). 메타데이터 반영 지연이 확정 원인이었던 것은 아니다.

수정은 해당 Blob 연결 POST의 빈 201 응답에만 적용했다. 다른 공급자 응답은 기존 JSON 검증을 유지한다. 성공 응답 뒤에도 정확한 저장소의 소유권과 production 연결을 읽어 확인한다. 연결·토큰 보호 유형의 결과 조회는 최대 4회로 제한하고, 소유권·프로젝트·환경 범위가 다르면 즉시 차단한다. 확인이 늦다는 이유로 생성·연결 POST나 보호 유형 PATCH를 반복하지 않는다.

최종 QA에서는 실패한 같은 작업을 명시적으로 재개하고, 동일한 빈 QA 저장소의 연결만 다시 해제했다. 수정된 **운영 worker가 실제 연결 POST를 수행하여 빈 201 경로를 통과하고**, 환경 설정·배포·검증을 완료했다. 연결이 이미 존재하는 상태만 확인한 검증이 아니다. job·DB·프로젝트·설정·고정 하위 엔진은 재시도 중 교체하지 않았다.

### 사용자 지정 이름의 정규식 처리

최초 QA의 Blob 단계를 재개한 뒤에는 고정 하위 엔진 `dd71d851ce18473b1d9a89703374fe5cbc9bf46b`의 빌드가 `ERROR` / `nextjs_docs`로 종료됐다. `party-snapshot-parser.ts`가 짧은 사이트 이름을 동적 정규식에 그대로 삽입하여, 이름의 괄호 때문에 `SyntaxError`가 발생했다.

사용자 지정 이름의 정규식 특수 문자를 이스케이프하고 치환 문자열도 일반 문자로 보존하도록 수정했다. 최초 작업의 엔진을 새 코드로 덮지 않았다. 해당 실패 QA를 소유권·빈 Blob·125개 업무 테이블·합성 소유자만 존재함을 확인한 뒤 정리하고, 수정된 `7d669ec5bc2af56ab23c793f9a530bf5f6fbfc82`를 고정한 별도 QA를 만들었다. 첫 QA의 자원과 중앙 합성 행은 제거했으며 원본 manifest와 감사 기록은 보존했다. 이 정리는 최종 성공 QA의 정리와 별개다.

## 실제 검증 범위와 제한

운영 HUB에 로그인할 수 없는 합성 소유자와 작업 1건을 사용했다. 비밀번호·세션·약관 동의 기록을 만들거나 실제 회원·운영진을 사칭하지 않았다. 수동 QA seed와 재개는 actor가 없는 별도 감사 기록으로 남겼다. 기존 K-LOL/NEXUS 자원과 실제 회원 자료는 변경 대상으로 삼지 않았다.

목표는 공개 전 `AWAITING_OWNER`다. 사후 검증에서 새 하위 DB에 최종 migration 52개가 적용됐고, 125개 업무 테이블에 합성 소유자와 초기 설정 외 자료가 없음을 확인했다. 실제 도메인·배포 소스와 runtime의 커뮤니티 ID·revision 2·비공개 상태가 일치했고 익명 홈은 차단됐다. 업로드한 파일은 없으며 공개 활성화를 요청하지 않았다. QA 정리 직전 소유권과 자료를 다시 확인하고 중앙 원래 자료 수가 유지되는지 확인했다.

예약 설정은 검증 종료 후 켰다. Vercel Request Logs에서 `2026-10-29T00:51:33.178Z`의 `GET /api/cron/community-sites`가 현재 운영 배포 `dpl_A1SajgHGJ7GVEr6aeCmF7CAscKEk`에서 HTTP 200으로 564ms에 완료됐음을 확인했다. User-Agent는 `vercel-cron/1.0`, Request ID는 `vstmd-1793235093178-53b3f153301d`이며 수동 Run 버튼은 누르지 않았다. [예약 기록](scheduler.json), [요청 로그 화면](scheduled-invocation.jpg). 이는 **빈 큐의 자연 예약 호출** 증거다. 실제 사이트 생성 완주는 인증된 수동 worker 호출로 검증했으며, 자연 예약 호출이 사이트 생성 전체를 수행한 것으로 기록하지 않는다.

이번 합성 worker 검증은 일반 회원가입, 관리자 승인 UI, SSO 전체 흐름, 소유자의 공개 전환을 증명하지 않는다. 첫 실패부터 최종 성공까지 작업 이력을 보존하며, 중간 수정·수동 재개·연결 해제를 숨기지 않는다.

## 제공 범위와 후속 단계

이번 릴리스는 1단계 개설 스튜디오다. 중앙 가입·신청, 운영진 심사, Arena·Lounge·Club 세 테마, 색상·이미지·홈 구성, 기능 켜기·끄기, 독립 DB를 사용하는 신규 사이트 준비와 소유자 공개 확인 흐름을 다룬다. 기능 중지는 기존 기록 삭제를 의미하지 않는다.

연합, 공동 대회, 커뮤니티 간 운영 기록 공유, 기존 사이트의 본인 계정 연결, 휴대폰 봇의 동적 방 설정과 신규 Riot 연결은 후속 범위다. 이번 자동 개설 검증을 이 기능들의 완료로 표시하지 않는다.
