# 실제 브라우저 과업 검증 · 2026-10-07

대상: `followup-browser-before`가 만든 loopback PostgreSQL·Next production build. 합성 계정과 합성 파일만 사용했다. 운영 회원·경기·신청 자료는 변경하지 않았다. 이 단계의 UI는 배포 1.0.5 기준이며 후속 소스 변경은 최종 빌드에서 다시 확인한다.

## 확인한 과업

- 문의·건의: 관리자 메뉴 → 합성 접수 상세 → 검토 중/관리 메모 저장(변경 버전 1) → 새로고침 후 두 값 유지 → 완료 저장(변경 버전 2). 이전 ETag 오류가 실제 UI에서 해소됨을 확인했다. `operation-form-completed.png`.
- 하이라이트: 초안 생성 → 제목 변경 저장 → 게시 → 비로그인 공개 목록/상세에서 제목·설명·재생 버튼과 외부 보기 링크 확인 → 게시 내리기 → 보관 후 목록의 보관 상태 확인. 외부 YouTube 영상의 실제 재생은 이 검사에 포함하지 않았다. `highlight-published.png`.
- 갤러리: 새 초안에 합성 PNG 1장 동시 등록 → 편집 화면에서 두 번째 PNG 추가 → 2번째 이미지를 위로 이동 → 저장 → 새로고침 후 이미지 2장 유지 → 게시 전환(변경 버전 5) → 공개 목록/상세에서 두 이미지 확인. 분홍색 2번째 파일이 첫 사진으로 노출됨을 실제 스크린샷에서 확인했다. 다음 버튼으로 2/2, 해당 버튼 포커스에서 ArrowLeft로 1/2 복귀. `gallery-published.png`. region 자체는 포커스 대상이 아니어서 해당 위치로 키를 보낸 도구 실패를 제품 오류로 세지 않았다.
- 저장한 팀 → 결과 접수: 실제 로그인 후 해당 draft로 복귀 → ‘이 팀으로 경기 결과 접수’ → 연결 팀/제목 표시 → 주최자/경기일 입력 → 접수 생성 → 제목 수정 저장 → 서로 다른 합성 PNG 2장 등록 → 검토 대기. `submission-pending.png`.
- 관리자 경기 검토: 위 접수 목록 → 상세 → 앱 내부 거절 패널 → 공개 사유 저장 → 제출자 접수 코드 화면에 동일 사유/문의/새 결과 접수 링크 → 관리자 검토 재개(PENDING_REVIEW, 변경 버전 5). `submission-rejected-owner.png`. 빈 단색 이미지는 업로드·수명주기 검사 전용이며 OCR 정확도나 실경기 승인 근거로 세지 않는다.
- 징계: 실제 회원과 연결하지 않은 합성 표시명으로 주의 기록 생성 → 최고관리자 사유·메모 변경 저장(변경 버전 1) → 기록 취소(변경 버전 2, 종료). 운영 제한·실회원 계정 변경 없음.

## 완료하지 못한 실제 조작

참가 신청 1/10, 주 미드·부 서폿을 확인하고 native 클릭으로 ‘내 신청 취소’를 눌렀다. 브라우저가 `본인의 오늘 참가 신청을 취소할까요?` confirm을 표시했다고 도구가 명시적으로 보고했다. 이어 documented `getJsDialog`와 키보드 응답이 모두 시간 초과되어 완료를 확인하지 못했다. 도구 문제를 제품 오류로 단정하거나 확인 절차를 제거/우회하지 않았다. 사용자에게 확인창 조작을 요청하고 브라우저를 표시했다. 응답 없이 이전 테스트 서버를 정리한 뒤 최종 환경으로 넘어가므로 이 실제 취소→재신청과 native 확인을 쓰는 승인 완료는 여전히 미확인이다. 계정 권한/외부 연동 제한과 별개의 브라우저 도구 제약이다.

첫 harness는 `stop`으로 종료했고 PostgreSQL 중지·일회성 경로 제거와 프로세스 exit0를 확인했다.

최종 빌드의 새 탭(60426)에서는 관리자 로그인 화면과 입력이 정상 렌더되지만, locator 클릭과 확인 후 native 클릭 모두 로그인 제출로 진행되지 않았다. 앞선 confirm 제약이 새 탭에서도 계속돼 실제 수정 UI 클릭 통과로 세지 않았다. 사용자에게 이전 확인창과 로컬 탭 닫기를 요청했다. 인증 자체는 별도 실제 HTTP 검사에서 통과했고 이를 브라우저 클릭 성공과 혼합하지 않는다. 최종 harness도 `stop` 후 cluster 중지·일회성 경로 제거·exit0를 확인했다.

## 이 과정에서 추가 확인한 개선점

- 관리자 미디어 상태에 `DRAFT/PUBLISHED/ARCHIVED`, `rev.`가 표시된다. 의미가 직접 전달되는 한글 상태로 변경한다.
- 미디어 게시 직후 공개 화면으로 확인할 링크가 없다. 이미 존재하는 공개 상세에 연결한다.

브라우저 턴 중단으로 닫힌 임시 탭은 새 탭으로 이어갔으며, 합성 저장 결과와 세션은 유지되었다. 중단 자체를 제품 오류로 집계하지 않는다.
