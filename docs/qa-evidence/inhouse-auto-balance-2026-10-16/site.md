# 자동 최선 편성 UI·공유 검증

2026-10-16 (Asia/Seoul). 실제 운영 계정·참가 신청·팀 초안을 변경하지 않았다.

## 사용자 흐름

- 입력에서 주·부 포지션과 기타 포지션 허용 설정은 그대로 유지한다. 서버에 모든 역할을 허용한 것으로 바꾸어 보내지 않는다.
- 선택한 조건을 먼저 계산하며 조합이 없으면 필요한 조건을 자동 조정한다는 안내를 제공한다. 기존의 절대적인 `원포지션 고정`, `선택한 포지션만 허용` 문구는 실제 동작에 맞게 바꿨다.
- 자동 조정 결과는 `조건 조정 편성`으로 표시한다. 조정된 포지션 인원·바텀 티어 조건 수와 해당 선수 이름·배정 역할·사유를 보여준다. 사용자의 추가 확인이나 설정 변경 없이 저장·공유·경기 접수로 진행할 수 있다.
- 공유 문구에도 같은 선수별 사유를 넣는다. 원문 사유와 일반 경고가 중복되지 않도록 하며, 내부 선수 ID는 이름으로 치환한다. 세부 검사에서도 같은 치환을 적용한다.
- 이전 계산 결과는 `최신 자동 조정 기준으로 재평가`하도록 안내한다. 직전 버전에 이미 적용된 1→6 우선순위가 없었다고 표시하지 않는다.
- 자동 추천을 수동으로 변경한 뒤에는 `수동 배치에 적용된 조정 조건`과 현재 배치의 사유를 표시한다. 사용자가 바꾼 수동 결과를 최선의 자동 추천으로 표시하지 않는다.

## 수동 편성과 충돌 보호

수동 교환·미리보기·412 이후 입력 유지 검사는 서버와 같은 `evaluateTeamBalanceLayout` 옵션을 사용한다. 완화 가능 여부는 현재 평가 회차의 `AUTO`, rank 1 후보에 있는 `fairness.constraintRelaxation.applied`로만 결정한다. 사용자가 선택한 수동 후보에 marker가 있다는 이유만으로 완화하지 않는다.

따라서 자동 조정 초안은 미등록 역할로 교환한 뒤 서버 평가를 요청할 수 있다. 수동으로 엄격 조건을 만족하는 배치에 돌아갔더라도 같은 회차의 원래 자동 추천이 완화 초안이었다면 추가 교환은 허용된다. 기존 엄격 초안·과거 회차 marker·수동 marker만 있는 초안의 제한은 유지된다. API 요청 본문에 사용자가 완화 권한을 지정하는 필드를 추가하지 않는다.

진행 중 잠금, 미평가 수동 배치의 저장·공유·접수 차단, 412 뒤 최신 초안 비교 및 명시적 유지/버리기는 유지한다. 충돌 뒤 최신 자동 추천이 엄격 기준으로 바뀌면 이전의 미등록 역할 배치를 그대로 유지할 수 없다.

## 합성 브라우저 fixture

`.tmp/auto-balance-browser`는 실제 `TeamBalanceBuilder`와 `TeamBalanceDraftWorkspace`를 렌더링한다. 서버는 실제 도메인 `calculateTeamBalanceCandidates`와 `evaluateTeamBalanceLayout`을 호출하되 합성 메모리 초안만 다룬다. 전원 탑을 신청한 합성 10명 가져오기 → 자동 추천 → 다른 역할 간 수동 교환 → 서버 평가 → 저장을 확인할 수 있게 준비했다. Next navigation만 fixture 화면 갱신으로 대체했다.

운영 API·DB를 사용하지 않으며 브라우저 실제 실행 결과는 별도 증거로 구분한다. 이 준비만으로 실제 브라우저 검증이나 운영 저장 성공을 주장하지 않는다.
