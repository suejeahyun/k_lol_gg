# K-LOL.GG 운영진 기능 가이드

기준일: 2026-08-26

대상: 자원해서 방 운영을 돕는 관리자와 명예 관리자

목적: 사이트와 카카오봇을 이해하고, 서로 편하게 설명할 수 있도록 돕기

## 1. 이 가이드를 보는 방법

이 자료는 회사식 근무 매뉴얼이나 평가표가 아니다. 자원해서 운영을 돕는 사람이 사이트와 카카오봇을 처음 배울 때, 옆에서 화면을 보여주며 말로 설명하기 위한 안내서다.

처음부터 전부 외울 필요는 없다. 아래 세 가지 흐름을 먼저 이해하고, 나머지 메뉴는 필요한 상황이 생겼을 때 찾아보면 된다.

- 내전: 카카오 접수 → 사진 확인 → 사이트에서 수기 등록
- 경고: 카카오 접수 → 관리자 검토 → 승인·반려 → 차감 인증
- 운영: 구인·신청·오류를 확인하고 필요한 사람과 상의

이 가이드를 함께 본 뒤에는 다음 내용을 편하게 설명할 수 있으면 충분하다.

- 관리자 홈에서 접수와 오류가 어디에 보이는지 찾는다.
- 카카오 명령과 사이트 접수번호를 연결해 상태를 확인한다.
- 경고 접수를 검토하고 비공개 사유를 안전하게 기록한다.
- 경고 근거사진 0~3장과 차감 인증사진 일반 10장·내전 15장을 구분한다.
- 종료된 내전 결과사진 2장·3장을 확인하고 기존 내전 등록 화면에서 수기 확정한다.
- 구인·스크림·내전 모집번호 중복과 잘못된 양식을 판별한다.
- 잘 모르거나 애매한 상황에서 혼자 결정하지 않고 다른 운영진에게 물어본다.

> 같이 연습할 때는 실제 이용자에게 경고·벤을 부여하거나 운영 데이터를 삭제하지 않는다. 테스트 접수와 조회 기능만 사용하고, 승인 연습은 지정된 테스트 대상에 한정한다.

## 2. 말로 설명할 때 추천 순서

한 번에 모든 메뉴를 설명하면 기억하기 어렵다. 실제 화면을 함께 보면서 다음 순서로 이야기하는 것을 권장한다.

| 순서 | 권장 시간 | 함께 볼 내용 | 확인해 볼 것 |
|---|---:|---|---|
| 1. 전체 모습 | 10분 | 관리자 홈, 메뉴, 접수번호 | 경고·내전 메뉴 위치 찾기 |
| 2. 경고 | 20~30분 | 접수, 근거사진, 승인·반려, 차감 | 0~3장과 10·15장 구분하기 |
| 3. 내전 | 20~30분 | 2·3세트 사진, 접수 확인, 수기 등록 | 사진 순서와 등록 화면 연결하기 |
| 4. 카카오 운영 | 15~20분 | 구인·스크림·내전 명령과 로그 | 모집번호가 왜 필요한지 설명하기 |
| 5. 애매한 상황 | 10분 | 보류, 운영진 상의, 오류 기록 | 혼자 처리하지 않을 경우 구분하기 |

### 같이 보기 전 준비

- 사용할 관리자 계정과 권한 범위를 확인한다.
- 관리자 페이지 로그인과 2단계 인증 상태를 확인한다.
- 테스트에 사용할 카카오방과 테스트 표시 이름을 정한다.
- 실제 운영 대상과 구분되는 테스트 이름을 사용한다.
- 현재 사진 저장은 Vercel Blob 인증 문제로 성공 테스트가 제한될 수 있음을 먼저 알려준다.

## 3. 관리자 역할과 권한 원칙

| 역할 | 주로 돕는 내용 | 하면 안 되는 일 |
|---|---|---|
| 일반 관리자 | 접수 확인, 승인·반려, 내전·구인·콘텐츠 운영 | 권한 밖 설정 변경, 근거 없는 징계, 운영 기록 임의 삭제 |
| 최고관리자 | 사이트 설정, 감사 로그, AI 요청 로그, 고위험 권한 관리 | 비밀값 공유, 복구 계획 없는 전체 초기화 |
| 설명을 맡은 관리자 | 화면을 같이 보며 기능과 주의점을 안내 | 연습을 실제 이용자 데이터로 진행 |

관리자 처리는 `누가, 언제, 무엇을, 왜 변경했는지` 나중에 확인할 수 있어야 한다. 불확실하면 승인하지 말고 보류한 뒤 다른 운영진과 근거를 확인한다.

> 일반 관리자는 계정·권한 변경, 전체 데이터 삭제, 번호 초기화, 시즌 종료, 비밀값 변경처럼 영향이 큰 기능을 직접 처리하지 않는다. 이런 기능은 최고관리자와 먼저 상의한다.

### 즉시 중단해야 하는 상황

- 대상 이름이나 닉네임이 서로 다른 경우
- 사진의 경기 순서나 세트 수가 양식과 맞지 않는 경우
- 같은 접수번호를 여러 관리자가 동시에 처리 중인 경우
- 인증값, 토큰, 비밀번호가 화면이나 채팅에 노출된 경우
- 전체 삭제, 번호 초기화, 시즌 종료처럼 복구가 어려운 작업인 경우

## 4. 관리자 홈과 메뉴 지도

관리자는 로그인 후 `/admin`에서 접수, 오류, 자동화 상태를 확인할 수 있다. 메뉴 검색을 이용하면 기능 이름이나 상황 키워드로 빠르게 이동할 수 있다.

![관리자 홈: 왼쪽 메뉴와 현재 운영 현황을 확인하는 시작 화면](docs/assets/admin-training/01-admin-dashboard.jpg)

| 하고 싶은 일 | 주요 메뉴 | 언제 사용하나 |
|---|---|---|
| 전체 현황 보기 | 관리자 홈 | 접수나 오류가 있는지 궁금할 때 |
| 내전 등록·수정 | 새 내전 등록, 내전 관리 | 최종 경기 결과를 확정할 때 |
| 카카오 내전 접수 | 내전 접수 | `/내전등록` 사진을 검토할 때 |
| 파티·스크림 | 구인 관리, 스크림 구인 | 모집 상태와 참가자를 확인할 때 |
| 대회 | 이벤트·멸망전 관리 | 대회 생성, 참가자, 대진, 결과 처리 |
| 사람 | 플레이어 관리, 계정 관리 | 가입 승인, 연결 정보, 권한 확인 |
| 징계 | 주의·경고·벤 | 경고 접수와 차감 인증을 처리할 때 |
| 운영 신청 | 운영 신청 | 지인·건의·모임·외출 양식 처리 |
| 자동화 | 카카오 운영 요약, 처리 로그 | 명령 실패와 중복 인식 조사 |
| Riot·MMR | Riot 연동, K-LOL MMR 관리 | 동기화·밸런스 지표 점검 |
| 콘텐츠 | 하이라이트, 이미지 관리 | 사이트 공개 콘텐츠 관리 |
| 설정 | 자동화 설정, 보안, 시즌, 챔피언 | 기능 스위치와 기준 데이터 관리 |
| 최고관리자 | 사이트 설정, AI 요청, 감사 로그 | 고위험 설정과 변경 이력 확인 |

## 5. 관리 페이지를 열었을 때

### 먼저 보면 좋은 곳

1. 관리자 홈에서 미처리 접수와 오류 수를 확인한다.
2. `/admin/kakao`에서 자동화 요약과 기능 중지 상태를 확인한다.
3. `/admin/logs/kakao`에서 최근 반복 오류가 있는지 확인한다.
4. 구인·스크림·내전 모집의 진행 상태와 오래된 항목을 확인한다.
5. 경고와 내전 결과 접수 중 사진 대기·검토 대기 건을 확인한다.
6. 다른 관리자가 이미 보고 있는 접수번호가 있는지 확인한다.

### 처리를 마쳤을 때

1. 여러 사람이 알아야 하는 처리라면 접수번호와 결과를 운영진 방에 남긴다.
2. 보류 건은 이유와 추가로 필요한 내용을 짧게 적는다.
3. 오류 건은 시간, 방, 보낸 사람, 명령, 봇 응답을 기록한다.
4. 테스트 데이터와 실제 운영 데이터를 구분해 표시한다.
5. 로그아웃하고 공용 기기에 인증 정보가 남지 않았는지 확인한다.

## 6. 계정·플레이어 관리 교육

### 가입 계정 처리

1. `/admin/users`에서 신청 계정의 이름과 연결 정보를 확인한다.
2. 기존 플레이어와 중복되는 이름·닉네임이 있는지 검색한다.
3. 승인 기준을 충족하면 승인하고, 부족하면 반려 사유를 명확히 남긴다.
4. 관리자 역할 부여는 최고관리자 또는 승인된 절차를 따른다.
5. 비밀번호 초기화와 2FA 초기화는 본인 확인 후 실행한다.

### 플레이어 정보 수정

- 닉네임#태그, 이름, 포지션, 티어 변경 근거를 먼저 확인한다.
- Riot 동기화 값과 수기 입력값이 충돌하면 최신 동기화 시각을 확인한다.
- 밸런스 보정은 사유와 기대 효과를 기록한다.
- 플레이어 삭제보다 비활성화·복구 가능한 처리를 우선한다.

## 7. 카카오 구인·스크림·내전 운영

### 파티 구인

| 업무 | 명령·확인 | 관리자 판단 |
|---|---|---|
| 생성 | `5인파티`, `자랭구인` 등 | 봇이 모집번호를 발급했는지 확인 |
| 수정 | 번호가 포함된 양식 전체 전송 | `모집번호: #번호` 유지 여부 확인 |
| 현황 | `구인현황`, `구인상세 12` | 사이트와 카카오 인원이 일치하는지 확인 |
| 마감 | `12ㅉ`, `#12ㅉ` | 잘못된 번호를 마감하지 않았는지 확인 |

모집번호가 빠진 내전 양식은 새 구인이나 파티 양식으로 오인될 수 있다. 원본 헤더와 번호를 유지하도록 안내한다.

![공지 재사용 가능: 모바일 카카오 도움말의 5인 파티 생성과 모집번호 예시](docs/assets/admin-training/08-kakao-party-guide.jpg)

### 내전 구인

- `/내전구인 협곡`, `/내전구인 칼바람`, `/내전구인 증바람`으로 종목을 구분한다.
- 날짜·시간을 명령에 넣을 수 있으며 필요하면 끝에 `#번호`를 지정한다.
- `/내전현황`, `/내전상세 번호`로 반영 결과를 확인한다.
- 모집 명단을 수정할 때 헤더의 `#번호`를 삭제하지 않는다.
- 내전과 스크림 모집은 매일 오전 6시 자동 종료된다.

### 스크림

1. `/스크림구인`으로 양식을 호출한다.
2. 우리 팀이 번호가 포함된 양식을 먼저 등록한다.
3. 상대 팀은 같은 번호 양식에 정보를 추가한다.
4. `/스크림현황`과 `/스크림상세 번호`로 양쪽 정보를 확인한다.
5. 완료·취소 명령은 봇이 안내한 번호 기준으로 실행한다.

## 8. 경고 접수 관리자 실무

### 먼저 알아야 할 수량

| 사진 종류 | 수량 | 확인 목적 | 처리 시점 |
|---|---:|---|---|
| 경고 부여 근거 | 0~3장 | 위반 사실 검토 | 경고 접수 직후 |
| 일반 경고 차감 | 10장 | 일반 경고 해제 조건 | 승인 후 30일 이내 |
| 내전 경고 차감 | 15장 | 내전 경고 해제 조건 | 승인 후 30일 이내 |

> 가장 많이 발생할 수 있는 실수는 근거사진 0~3장을 차감사진 10·15장으로 오해하는 것이다. 두 사진은 제출자, 목적, 시점이 모두 다르다.

![공지 재사용 가능: 경고 접수 양식과 차감 사진 인증 흐름](docs/assets/admin-training/06-kakao-warning-guide.jpg)

### 경고 접수 처리 순서

1. 카카오 `/경고` 접수번호 `DS...`를 확인한다.
2. `/admin/discipline`에서 대상 이름, 닉네임#태그, 일반·내전 구분, 부여일을 확인한다.
3. 양식에 선언된 근거사진 수와 실제 사진 수를 대조한다.
4. 사진과 대상 정보가 부족하면 승인하지 않고 보류 또는 반려한다.
5. 승인할 때 경고 사유를 사이트 승인 창에 비공개로 입력한다.
6. 승인 후 생성된 `WR...` 인증번호와 목표 사진 수를 확인한다.
7. 대상자에게 `/경고인증 WR인증번호` 사용법을 안내한다.

![관리자 화면: 주의·경고·벤을 직접 등록할 때 사용하는 입력 화면](docs/assets/admin-training/02-admin-discipline-new.jpg)

### 차감 인증 처리

1. `WR...` 인증번호로 대상과 연결 경고를 확인한다.
2. 일반 10장 또는 내전 15장 목표와 현재 수량을 대조한다.
3. 한 판당 한 장인지, 서로 다른 경기인지 확인한다.
4. 30일 기한과 사진 순서를 확인한다.
5. 모든 조건이 맞을 때만 승인한다.
6. 승인 결과로 연결된 경고 1건만 비활성화됐는지 확인한다.

### 누적 정책

- 주의 3회는 경고 1회로 전환하고 사용된 주의 3건은 비활성 처리한다.
- 경고 3회 누적 시 강퇴 검토 건이 생성되며 관리자가 최종 확정한다.
- 자동 전환 결과가 의심되면 징계 통계와 대상별 기록을 함께 확인한다.

## 9. 종료된 내전 결과 관리자 실무

### 접수 확인

1. 카카오 `/내전등록` 접수번호 `MR...`를 확인한다.
2. `/admin/matches/submissions`에서 진행일, 진행자, 세트 수, 내전 회차를 확인한다.
3. 2세트면 사진 2장, 3세트면 사진 3장인지 대조한다.
4. 사진이 1세트부터 순서대로 들어왔는지 확인한다.
5. 팀 밸런스 번호가 있으면 기존 배정안과 참가자를 대조한다.

### 수기 등록

1. 모든 사진이 확인된 접수에서 `수기 등록 시작`을 누른다.
2. 기존 내전 등록 화면으로 이동했는지 확인한다.
3. 각 세트의 선수, 챔피언, KDA, 승리팀을 사진과 대조해 입력한다.
4. 같은 선수나 세트가 중복되지 않았는지 검토한다.
5. 저장 전 전체 세트 수와 최종 승패를 다시 확인한다.
6. 저장 후 내전 목록과 플레이어 통계 반영을 확인한다.

사진만으로 결과가 자동 확정되지는 않는다. `수기 등록 시작` 이후 최종 저장까지는 관리자가 책임지고 검증한다.

## 11. 대회·콘텐츠·Riot·MMR 운영

### 이벤트·멸망전

- 새 대회를 만들기 전에 일정, 참가 방식, 공개 범위를 확인한다.
- 참가자 가져오기와 팀 배정 전 중복 신청을 확인한다.
- 대진·경기 결과를 저장한 뒤 공개 화면에서 반영을 확인한다.
- MVP 투표는 대상 경기와 투표 기간을 확인한다.

### 하이라이트·이미지

- 제목, 공개 여부, 연결 경기, 저작권·초상권을 확인한다.
- 홈 노출 이미지는 모바일 잘림과 부적절한 내용을 확인한다.
- 삭제보다 공개 중지 또는 수정이 가능한지 먼저 검토한다.

### Riot·MMR

- Riot 실패 로그와 마지막 동기화 시각을 확인한 뒤 재시도한다.
- 전체 동기화와 전체 MMR 재계산은 영향 범위가 크므로 운영 시간과 백업을 확인한다.
- 수기 밸런스 보정은 사유와 기간을 기록한다.

## 12. 자동화 설정과 보안

### 카카오 기능 스위치

`/admin/kakao/settings`에서 경고 양식, 경고 현황, 사진 접수, 내전등록, 구인, 스크림, 전적·랭킹 기능을 각각 제어한다.

- 기능을 켜기 전에 DB, API 인증, 저장소 상태를 확인한다.
- 장애가 발생하면 전체 봇을 끄기보다 문제가 있는 기능만 중지한다.
- 응답 문구를 바꿀 때 명령어와 양식 항목명을 임의로 변경하지 않는다.
- 양식 버전을 변경하면 봇 코드와 사이트 템플릿을 함께 배포한다.

### 비밀값

- `KLOL_KAKAO_RECRUIT_SECRET`, `KLOL_KAKAO_OPENCHAT_SECRET`, `KLOL_KAKAO_SEARCH_PLAYER_SECRET`은 메신저봇R DataBase에 저장한다.
- `BLOB_READ_WRITE_TOKEN`은 카카오봇에 넣지 않고 Vercel에서만 관리한다.
- 토큰을 채팅, 공지, 스크린샷, 교육자료에 원문으로 남기지 않는다.
- Google Drive는 카카오 사진 저장소로 사용하지 않는다.

## 14. 함께 해보면 좋은 예시

### 실습 1. 카카오 상태 확인

해볼 일: `/봇버전`, `/도움말`, `구인도우미`의 용도를 서로 설명해 본다.

확인할 점: 봇 버전과 사이트 도움말 주소를 확인하고, 명령 오류 시 로그 위치를 찾을 수 있는지 본다.

### 실습 2. 파티 구인 수정

해볼 일: 테스트 파티를 만들고 모집번호를 유지한 채 참가자 한 명을 추가한다.

확인할 점: 새 구인으로 중복 생성하지 않고 같은 모집번호의 인원만 변경되는지 본다.

### 실습 3. 경고 0장 접수

해볼 일: 테스트 대상에게 근거사진 0장 일반 경고 양식을 접수하고 상태를 조회한다.

확인할 점: 경고 사유를 카카오에 쓰지 않고 `DS...` 상태가 검토 대기임을 설명할 수 있는지 본다.

### 실습 4. 경고 승인 판단

해볼 일: 테스트 접수의 대상, 구분, 날짜, 증빙을 같이 검토한다.

확인할 점: 승인·반려 근거를 말하고 일반 10장·내전 15장 목표를 구분한다. 실제 승인 실행은 함께 설명하는 관리자가 지정한 테스트 대상에만 한다.

### 실습 5. 내전 결과 2·3세트

해볼 일: `MR...` 접수의 세트 수와 사진 수를 대조한다.

확인할 점: 2세트 2장, 3세트 3장과 사진 순서를 설명하고 수기 등록 시작 위치를 찾을 수 있는지 본다.

### 실습 6. 장애 보고

해볼 일: 사진 저장 오류를 장애 공유 양식으로 정리한다.

확인할 점: 토큰을 노출하지 않고 시간, 방, 보낸 사람, 명령, 접수번호, 실제·기대 결과를 기록했는지 본다.

## 15. 설명을 마치기 전 같이 확인할 내용

시험이나 수료 기준이 아니다. 처음 안내받은 관리자가 헷갈리는 부분이 없는지 대화하면서 확인하는 목록이다.

- 관리자 홈에서 미처리 접수와 오류를 찾을 수 있다.
- 일반 관리자와 최고관리자 메뉴 차이를 설명할 수 있다.
- 실제 제재·삭제·전체 초기화를 교육 중 실행하지 않는다.
- `DS`, `WR`, `MR`, 모집번호의 차이를 설명할 수 있다.
- 경고 근거 0~3장과 차감 인증 10·15장을 구분할 수 있다.
- 경고 사유가 사이트 승인 창의 비공개 정보임을 안다.
- 내전 결과 2·3장 접수 후 수기 등록이 필요한 이유를 설명할 수 있다.
- 모집번호가 빠진 양식의 위험을 설명할 수 있다.
- 카카오 기능 스위치와 처리 로그 위치를 찾을 수 있다.
- `BLOB_READ_WRITE_TOKEN`을 카카오봇에 넣지 않는다는 것을 안다.
- 오류 보고에서 토큰과 개인정보를 제거할 수 있다.
- 보류·반려·승인 판단 근거를 다른 운영진이 알 수 있게 남길 수 있다.

모르는 항목은 그 자리에서 다시 화면을 열어 함께 확인한다. 모든 메뉴를 외우는 것보다, 애매할 때 누구에게 물어보고 어디에서 기록을 찾는지 아는 것이 더 중요하다.
