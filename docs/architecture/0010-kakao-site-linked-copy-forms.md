# ADR 0010: 사이트 연동 파티·내전의 짧은 복사 양식과 추가 전용 저장

- 날짜: 2026-09-20
- 대상: 카카오 R24 복사 양식
- 상태: 사용자 위임으로 결정한 소스 구현 정책. 운영 배포·휴대폰 설치는 미반영.
- 승인 근거: “파티 내전 모두 저렇게 적용 스크림은 삭제”, 이후 “설계가 완벽하게 … 처음보는 사람도 따라하기 쉽고 진입장벽이 낮게”, 최종 “설명은 필요없을거같아 너가 생각하기 최고의 선택지로 만들어줘”.

## 배경과 우선순위

참가자에게 새 모집 명령, 주최자 입력, 긴 저장기준, 인원 계산을 요구하면 이름 한 줄을 추가하는 일보다 준비 과정이 복잡해진다. 반대로 복사한 명단 전체를 현재 명단으로 교체하면 같은 빈칸에 동시에 신청한 사람이나 사이트에서 먼저 수정한 내용을 잃을 수 있다.

사용자에게는 익숙한 복사·붙여넣기를 유지하고, 원본과 최신 저장 상태의 비교는 서버가 담당한다. 파티와 내전은 같은 참가 흐름을 제공하지만, 내전의 회원 식별·신청 상태·사이트 신청 소유권은 기존 도메인 규칙을 유지한다.

본 ADR은 [ADR 0009](./0009-kakao-copy-first-rosters.md)의 R23 정책 중 긴 저장기준을 기본 노출하던 방식, 최신 양식의 명단 교체·빈칸 삭제 허용, DB migration 불필요 결정을 대체한다. ADR 0009 자체는 당시의 결정 기록으로 보존한다.

[ADR 0008](./0008-kakao-v1-exact-v4-transport-adapter.md)과 동결 V1 fixture의 역사적 기준, HMAC 전송, 5초 단일 요청, event 멱등성, 논리적 installation 범위는 계속 유지한다. R24 사용자 경험은 승인된 확장이며, V1 원본과 같은 동작이라고 주장하지 않는다.

## 결정 1: 참가자에게는 이름 한 줄만 요구한다

기본 흐름은 **가장 최근 봇 명단 전체 복사 → 빈칸에 이름 입력 → 전체 전송 → 저장 결과와 최신 명단 확인**이다.

- 참가 안내와 모집 생성 안내를 구분한다. 기존 모집에 들어갈 사람에게 `5인파티`나 `내전구인`을 먼저 실행하도록 안내하지 않는다.
- 생성 직후에도 정원만큼의 빈 참가 슬롯과 예비 슬롯을 보여준다. 주최자 입력은 필수가 아니다.
- 메시지는 모집 종류·번호·현재 인원, 필요한 시간·게임/모드, 한 줄 참가 안내, 참가 명단, 예비, 양식코드 순으로 짧게 구성한다. 저장 결과는 최신 양식보다 먼저 보여준다.
- 사용자는 인원수와 양식코드를 수정하지 않는다. 서버가 실제 저장 결과를 기준으로 인원과 최신 명단을 다시 출력한다.
- 미입력 시작 시간은 `미정`으로 표시한다. 이름만 추가했다고 현재 시각을 시작 시각으로 지정하지 않는다.
- 협곡 내전의 `이름/주라인/부라인`은 선택 입력이다. 이름만 제출한 기존 참가자의 라인은 보존한다.
- 상세·현황과 보조 추가/삭제 명령은 유지한다. 참가 취소·정리는 명시적인 보조 명령이나 허용된 사이트 관리 경로로 수행한다.

## 결정 2: 전체 메시지 전송은 명단 교체가 아니라 참가 추가다

복사 양식은 **추가 전용**으로 저장한다. 코드가 최신이어도 기존 이름을 지우거나 다른 이름으로 교체하는 방식의 취소는 허용하지 않는다.

| 상황 | 저장 정책 |
| --- | --- |
| 원본의 빈 번호에 새 이름 추가 | 최신 DB 명단에 추가한다. |
| 원본의 기존 이름 삭제·교체·이동 | 저장하지 않고 최신 양식과 다음 행동을 안내한다. |
| 다른 사람이 같은 번호에 먼저 참가 | 일반 번호형 명단이면 최신 상태의 빈 번호에 추가한다. |
| 파티의 탑·정글·미드 등 지정 라인에 선행 참가 | 다른 라인으로 임의 이동시키지 않고 충돌을 안내한다. |
| 본 참가 정원 초과 | 자동으로 예비로 보내지 않는다. 예비 참가를 원하면 예비 칸을 직접 선택한다. |
| 예비 칸에서 동시 신청 | 본 참가로 승격하지 않고 빈 예비 칸에 추가한다. |
| 원본에 있던 사람이 최신 상태에서 이미 취소 | 오래된 명단으로 그 사람을 다시 참가시키지 않는다. |
| 동일한 내용 재전송 또는 이미 저장된 이름 | 중복 참가를 만들지 않는다. |
| 같은 양식 안의 구분 불가능한 중복 이름 | 안전하게 저장할 수 없는 요청으로 처리한다. |

모집 정보는 일반 참가 복붙으로 임의 변경하지 않는다. 초기 DRAFT에서 필요한 모집 정보를 설정하는 기존 흐름은 유지하되, 활성 모집의 시간·게임·정원·모드 등을 오래된 참가 양식으로 덮어쓰지 않는다. 최신 서버 정보를 우선하며 안전한 병합 여부를 판단할 수 없으면 저장하지 않는다.

DB transaction 안에서 권한과 현재 상태를 확인한 후 원본 대비 추가분만 적용한다. 무수정 제출은 불필요한 명단 변경을 만들지 않아야 한다. 저장 실패와 저장 성공 후 최신 명단 조회 실패도 혼동하지 않도록 구분한다.

## 결정 3: 짧은 양식코드는 서버에 보관된 원본을 가리킨다

`양식코드: XXXXX-XXXXX`는 사람이 직접 입력할 비밀번호가 아니다. 복사한 메시지의 원본 상태를 찾기 위한 식별자이며, 이름을 추가할 때 그대로 둔다.

- `recruiting.kakao_form_snapshots`에 원본 JSON과 SHA-256 상태 해시를 보관한다. 코드 자체는 암호학적 난수에서 생성한 대문자·숫자 10자리이며 `0`, `1`, `I`, `O`는 제외한다.
- 같은 종류·scope 해시·대상·운영일·원본 상태는 기존 코드를 재사용한다. 동시 발급은 unique index와 충돌 처리로 같은 원본을 재사용하며, 우연한 코드 충돌은 재시도한다.
- 조회는 코드뿐 아니라 `PARTY`/`INHOUSE`, 인증된 논리적 installation scope의 해시, 실제 파티 또는 내전 원본 대상, 운영일을 모두 묶는다. 같은 모집번호가 재사용돼도 다른 실제 대상의 코드는 적용하지 않는다.
- 운영일은 KST 06:00 경계다. 코드는 해당 운영일 다음 날 06:00 KST에 만료되며, 자정에는 만료되지 않는다. 이전 운영일 코드는 새 모집으로 자동 해석하지 않는다.
- 원본은 순수 JSON 객체이며 깊이·크기를 제한한다. DB에도 JSON 객체·64 KiB 제한, 해시 길이, 코드 형식, 만료 시각 제약을 둔다.
- 코드는 인증·권한·사용자 본인 확인을 대신하지 않는다. 기존 서명, 권한 재검사, 대상 잠금, 논리 scope 경계, event receipt를 우회하는 근거로 사용하지 않는다.
- 코드가 잘못되었거나 대상·운영일이 다르면 코드 없는 구형 양식으로 낮춰 저장하지 않는다. 저장하지 않았다는 안내와 최신 양식을 제공한다.
- 구형 긴 저장기준과 코드 없는 양식의 호환 경로도 기존 명단 보존을 우선한다. 짧은 코드로 원본을 확인할 수 없는 구형 양식에는 동일한 동시 추가 병합을 보장하지 않는다.

### 원본 데이터 보존과 정리의 한계

만료 시각 이후에는 원본을 저장 근거로 사용할 수 없다. 다만 논리 만료와 물리 삭제는 구분한다.

현재 물리 정리는 정상 발급·조회 요청에서 실행하며, 한 번에 만료된 원본을 최대 **256건**까지 `FOR UPDATE SKIP LOCKED`로 선택해 삭제한다. 유효한 원본은 정리 대상이 아니다. 별도 호출용 `pruneExpiredKakaoFormSnapshots`도 제공한다.

현재 구현은 무트래픽 시간의 자동 물리 삭제를 보장하지 않는다. 요청이 오랫동안 없거나 만료 데이터가 처리량보다 많으면 만료 원본의 개인정보가 더 오래 보관될 수 있다. 정기 정리 작업과 운영 보존기간 모니터링은 별도 운영 결정 대상이며, 이번 패치에서 새로운 운영 스케줄러를 배포했다고 주장하지 않는다. 만료 원본 본문이나 참가자 이름을 진단 로그·QA 문서에 남기지 않는다.

## 결정 4: 사이트와 별도의 카카오 전용 명단을 만들지 않는다

파티는 기존 `recruiting.parties`를 저장 원본으로 사용한다. 봇에만 있는 별도 최종 명단을 만들지 않으며, 사이트의 기존 공개 구인 조회도 같은 파티 데이터를 읽는다. 카카오에 이름을 적는 것은 사이트 계정 생성이나 본인 확인을 뜻하지 않는다.

내전은 기존 시즌 신청·예비·회원 확인 대기 구조에 연결한다.

- 정확히 식별한 기존 회원의 신청은 기존 시즌 신청 도메인 규칙에 따라 반영한다.
- 미등록·동명이인 등 바로 식별할 수 없는 이름을 임의의 회원에게 연결하지 않는다. 기존 확인 대기 경로를 사용하고 `회원 확인 필요 · 아직 참가 확정 전`으로 분리한다.
- 일반 참가, 예비, 회원 확인 필요를 명단·인원 요약에서 구분한다. 이름이 표시됐다는 이유만으로 운영진의 참가 확정 판단을 대신하지 않는다.
- SITE 출처 신청도 동일 내전의 표시 명단과 정원 계산에 포함한다. 카카오 복붙으로 SITE 신청의 출처·확정 상태·라인을 덮어쓰거나 취소하지 않는다.
- 동시 신청 병합은 최신 SITE·KAKAO 상태를 포함해 안전한 빈자리를 확인한다. 같은 회원을 다른 별칭으로 추가하거나 최신 상태의 참가자를 중복으로 만드는 요청은 그대로 저장하지 않는다.
- 회원 확인 필요 접수는 가입 완료나 자동 회원 연결을 보장하지 않는다. 기존 가입·이름 확인·운영진 확인 경로가 필요하다.

## 결정 5: 카카오 스크림 기능은 종료하고 과거 기록은 보존한다

파티와 내전만 복사 양식의 기본 모집 대상으로 제공한다. 카카오 SCRIM 명령·양식·도움말은 종료하며, 구형 휴대폰의 스크림 요청도 서버 경계에서 종료 안내로 처리한다. 새 스크림 저장 호출로 연결하지 않는다.

게임 정보나 일반 파티 이름에 `스크림`이라는 단어가 들어간 것만으로 정상 파티를 차단하지 않는다. 기존 스크림 DB 기록, 웹 조회, 관리자·대회 도메인은 이번 제거 범위가 아니며 삭제하지 않는다. 원본 V1 fixture와 과거 compatibility JSON도 수정하지 않는다.

## 배포 조건과 확인 범위

R24 서버는 신규 원본 저장 테이블을 사용한다. **서버 코드를 운영에 배포하기 전에 `0040_kakao_form_snapshot_codes`까지 migration 적용이 필수**다. R23의 “DB migration 없음” 기록을 R24에 그대로 적용하면 안 된다.

마이그레이션은 새 테이블과 인덱스 생성만 포함한다. 기존 파티·내전·스크림 데이터 삭제나 변환은 포함하지 않는다. Drizzle 스키마·생성 migration·journal·ERD가 함께 관리 대상이며, 운영 반영 전 격리 PostgreSQL에서 fresh·upgrade·재실행을 검증한다. 복구는 즉석 down migration이나 기존 데이터 삭제가 아니라 검증된 복구 절차 또는 forward-fix로 다룬다.

확인해야 할 증거는 다음과 같다. 이 ADR은 최종 테스트 수나 설치본 해시를 대신하지 않는다.

- 생성→복사→이름 추가→저장→최신 출력과 무수정 재전송의 서버·휴대폰 계약
- 동시 번호형 신청, 라인 충돌, 정원 초과, 예비 유지, 탈퇴자 재등장 차단
- 원본 코드의 scope·대상·날짜 경계, 발급 동시성, transaction rollback, 만료 정리 제한
- 사이트 신청 보존, 기존 회원 연결, 미식별 이름 분리, 확정·예비 상태 보호
- 구형 양식 호환과 잘못된 코드의 fail-closed 동작
- 카카오 스크림 종료와 기존 데이터·원본 fixture 보존
- 전체 정적 검사·계약 검사·격리 DB 검사·빌드, 생성 봇 ES5/Rhino 검사, 비밀정보 검사
- 별도 승인 후 운영 migration·서버 배포 근거, 휴대폰 실제 교체 및 카카오 복사·붙여넣기 실기기 확인

이번 결정과 소스 변경만으로 운영 배포나 휴대폰 설치가 완료되었다고 표시하지 않는다.
