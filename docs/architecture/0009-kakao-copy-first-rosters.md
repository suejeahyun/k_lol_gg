# ADR 0009: 파티·내전 전체 양식 복붙 우선과 카카오 스크림 종료

- 날짜: 2026-09-20
- 상태: 사용자 승인 범위의 소스 구현, 운영 미배포
- 근거 요청: “파티 내전 모두 저렇게 적용 스크림은 삭제”

## 결정

1. 파티와 내전은 생성부터 빈 참가 슬롯과 예비 슬롯을 포함한 전체 양식을 출력한다. 사용자는 전체 복사 → 빈칸 이름 입력 → 전체 전송으로 저장한다. 저장·빠른 수정 후 최신 전체 양식을 다시 출력한다. 빠른 추가·삭제는 보조 기능이다.
2. 첫 이름 입력으로 DRAFT가 활성화된다. 주최자는 필수 입력이 아니다. 내전은 기존 회원 식별을 유지하고 미등록 이름은 가입 안내한다. 이름-only 제출은 이미 설정된 라인을 보존한다.
3. 파티 저장기준은 운영일 + aggregate ID 해시 + revision, 내전은 운영일 + round/활성 신청 행 fingerprint다. 인증 토큰이 아니라 동시 수정 감지용이다. 권한·서명·논리적 installation 범위는 기존 서버 경계를 유지한다.
4. 최신 저장기준이 일치할 때만 명단 교체/빈칸 삭제를 허용한다. DB transaction의 최신 잠금 상태에서 재검증한다. 이전 운영일·당일 번호 재사용·다른 사용자의 선행 저장은 덮어쓰지 않는다. 저장기준 없는 과거 양식은 기존 참가자·메타데이터를 보존하는 추가만 허용한다.
5. 편집용 파티 양식은 시간·게임 설명·이름을 꾸미거나 예비 번호를 다시 매기지 않는다. 무수정 재제출은 변경을 만들지 않아야 한다.
6. 카카오 SCRIM 명령·양식은 종료 안내로 끝내며 서버 dispatcher/저장 호출을 하지 않는다. 구형 휴대폰 요청도 서버 경계에서 차단한다. 문자열에 ‘스크림’이 들어간 일반 파티명·게임 설명은 정상 처리한다. 기존 DB 기록·웹 조회·관리자 대회 데이터는 삭제하지 않는다.

## 이전 결정과의 관계

ADR 0008의 원본 fixture, HMAC, 5초 단일 요청, event 멱등성, 두 논리 프로필 경계는 유지한다. ‘첫 양식은 메타데이터만 출력’, ‘스크림도 동일하게 제공’, ‘V1 응답을 그대로 유지’ 부분은 이번 사용자 요청 범위에서 본 ADR이 우선한다. 동결 V1 fixture와 과거 compatibility JSON은 역사적 증거로 수정하지 않는다. 생성물은 빌더에서만 만들며 크기 제한 때문에 빈 줄·선행 들여쓰기를 제거하되 실행문 동일성·ES5/Rhino 검사를 유지한다.

## 배포 경계

DB migration과 운영 데이터 직접 변경은 없다. 서버 배포 및 휴대폰 설치는 별도 승인·실기기 검증 대상이다. R22 private 파일은 로컬 백업 후 R23을 생성하며 비밀값은 Git·공지·로그에 출력하지 않는다.
