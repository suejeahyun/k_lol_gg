# 사이트 이용 현황

2026-09-30. 구현 경로: `/admin/usage` (ADMIN 이상 + 관리자 2단계 인증).
운영 기준 d6e8ce44116858e6b783cf6dbc6e2c9339ee9c58에서 이 기능의 변경만 분리한다. 배포 결과는 docs/releases/registry.json과 해당 QA 근거를 따른다.

## 지표와 한계

- 등록 회원: 현재 삭제되지 않은 USER 계정. 승인 회원 수를 별도로 표시한다.
- 기간 이용 회원: 선택 기간에 수집된 이벤트의 고유 회원 계정. 현재 관리자·삭제 계정·설정된 제외 계정은 보고서에서도 제외한다.
- 승인 회원 이용률: 현재 승인 회원 중 선택 기간에 이용한 계정 / 현재 승인 회원.
- 전체 방문자: 날짜별 또는 기간별 고유 브라우저 쿠키. 사람 수의 추정치이며 기기 변경·쿠키 삭제로 중복될 수 있다.
- 회원은 계정, 비회원은 브라우저 기준이다. 로그인 전후 중복이 있어 두 수를 더해 전체 방문자로 사용하지 않는다.
- 방문: 브라우저의 30분 비활동 또는 로그인 계정 변경 후 첫 이벤트가 새 방문을 만든다. 서버에서 결정한다. 로그인 세션 발급 횟수와 다르다.
- 월 평균/중앙값: 해당 월에 이용한 회원별 방문 횟수의 평균/중앙값. 비활성 회원은 분모에 포함하지 않는다. 월평균 이용 일수와 2일 이상 이용 회원도 표시한다.
- 페이지 유형·주요 클릭·연속 조회 경로: 방문 목적의 간접 지표. 기능 성공/완료나 정보 만족도를 뜻하지 않는다.
- 날짜 경계: Asia/Seoul 00:00부터 다음 날 00:00 미만. 기본 최근 30일(오늘 포함), 최근 180일 안에서 최대 92일 조회.
- 첫 이벤트 이전은 미수집. 첫 수집일·오늘·일부만 선택된 월은 부분 집계. 브라우저 차단·네트워크 오류·수집 중단 중의 활동은 누락된다. 장애 시간의 완전한 수집 이력은 제공하지 않는다.

## 수집 범위

2026-09-30 후속 변경: 일반 관리자(ADMIN + 2단계 인증)도 이용 통계·CSV·감사 로그·AI 요청 이력과 카카오 설정/건강 상태를 조회할 수 있다. 사이트 설정은 SUPER_ADMIN 전용이며 기존 변경/재계산/복구 실행 권한은 유지한다. 비로그인 방문자 집계 카드를 추가하고 로그인·회원가입 페이지도 경로 유형만 수집한다. 비회원 식별은 가입이나 계정 생성 없이 서명된 브라우저 쿠키로 수행한다.

서버에서 활성화된 공개 레이아웃에만 수집기를 표시한다. 허용된 경로 유형으로만 변환해 보내며 동적 ID, URL query/hash, 검색어, 입력값, 원본 IP, DOM 텍스트는 저장하지 않는다. 플레이어 검색은 검색어가 있는 결과 화면 조회만 기록한다. 공개 내부 링크는 목적지 유형으로 집계한다. 팀 밸런스 추천 계산, 코인 시작/결과 복사는 고정 action으로 계측한다. 나머지 임의 버튼과 기능 완료 이벤트는 포함하지 않는다.

회원 식별자는 서버의 검증된 ACCOUNT 세션에서만 얻는다. 브라우저 식별자는 서명된 HttpOnly/SameSite=Lax 쿠키로 발급한다. 이벤트 UUID 중복 전달은 한 번만 저장한다. 관리자 쿠키, USER 외 역할, 미승인 계정, fixture, 제외 UUID, 인식 가능한 봇, DNT/GPC, 수집 제외 브라우저는 기록하지 않는다. 로그아웃 상태의 관리자와 인식하지 못한 봇은 완전히 구별할 수 없다.

공개 수집 API는 같은 출처만 허용하며 1 KiB JSON 제한과 허용 필드 검사를 적용한다. DB 기반 분당 전체 6,000건/브라우저 120건 제한은 서버 인스턴스 간 공유된다. 수집 오류는 사용자 기능을 중단하지 않는다. API와 CSV는 no-store이며 CSV에도 개인별 식별자를 노출하지 않는다.

쿠키는 90일, 이벤트는 180일, 비활성 visitor 상태는 90일 기준이다. 각 분 첫 수집 요청에서 오래된 이벤트 최대 5,000건과 visitor 상태 최대 1,000건을 정리한다. 수집 중단 때 정리도 중단되므로 즉시 삭제 보장으로 해석하지 않는다. `/privacy`에서 수집 안내와 브라우저 제외 설정을 제공한다. 제외 설정은 이전 기록을 삭제하지 않는다.

## 운영 반영

1. 현재 배포 소스와 DB 연결을 확인하고 이 기능의 변경만 릴리스에 포함한다. 기존 다른 작업은 자동으로 함께 배포하지 않는다.
2. 복구 지점을 확인한 뒤 기존 migration 관리 절차로 `0047_usage_analytics.sql`을 적용한다. 기존 0000~0046 적용 상태를 먼저 확인한다. 새 `usage` 스키마/3개 테이블/인덱스만 추가한다. 요청 처리 중 DDL이나 자동 migration은 실행하지 않는다.
3. Production에 `USAGE_ANALYTICS_ENABLED=true`, 독립된 무작위 `USAGE_ANALYTICS_SECRET` (32자 이상), 필요한 테스트 계정 UUID 목록 `USAGE_ANALYTICS_EXCLUDED_USER_IDS`를 설정한다. 비밀값은 클라이언트 변수에 넣지 않는다. `V2_PUBLIC_DATA_SOURCE=postgres`와 `V2_PUBLIC_ORIGIN`도 확인한다.
4. 해당 소스를 배포하고 관리자 메뉴 **운영·감사 → 사이트 이용 현황**을 연다. API `/api/usage/events`, CSV `/api/admin/usage/export`가 배포에 포함되어야 한다.
5. 설정한 제외 계정으로 사용자 기능과 통계 접근권한을 확인한다. 실제 수집 검증을 위해 별도의 합성 브라우저가 생성한 데이터는 운영 통계와 구분하여 정리한다.
6. 첫 수집 시각 이후의 데이터만 보고한다. 1개월이 충분히 쌓이기 전 부분 집계를 월 전체 이용률로 발표하지 않는다.

Vercel preview/development 환경에서는 수집하지 않는다. 로컬은 명시적 설정과 격리 DB로 검증 가능하다. 중지하려면 플래그를 false로 변경하고 새 배포에 반영한다. 읽기 화면은 이미 저장된 데이터를 수집 중단 안내와 함께 표시한다. 통계 테이블과 과거 기록은 삭제하지 않는다.

## 검증 명령

```powershell
npm run typecheck
npm run lint
npm test
npm run build
$env:PG_BIN_DIR='C:/Program Files/PostgreSQL/18/bin'
$env:V2_DB_CONTRACT_SCOPE='usage'
npm run test:db
# 빌드 후, 독립 PostgreSQL과 localhost Next 서버로 HTTP/브라우저 검증
npx --no-install tsx scripts/test-db/run-usage-http-qa.ts
```

테스트는 합성 계정·키와 loopback PostgreSQL만 사용한다. HTTP 검증은 출처·본문 제한, 중복 기록, 회원 귀속, 관리자·TOTP 보호, CSV를 검사한다. 브라우저 검증은 1440/390px 렌더링·접근성 및 실제 페이지/검색/링크 수집·제외 설정을 검사한다. 스크린샷 수치는 합성 데이터다.

## 기존 DB 읽기 전용 조사

```powershell
node scripts/usage-readonly-report.mjs '<로컬 환경파일 경로>' '.tmp/usage-existing-data.json'
```

READ ONLY 트랜잭션으로 집계한다. 계정 원문·토큰·연결 문자열을 출력하지 않는다. 세션 발급 기록은 방문으로 변환하지 않는다. V1/V2 계정은 중복될 수 있어 합산하지 않는다. 조사 결과는 비공개 로컬 산출물로만 보관한다.
