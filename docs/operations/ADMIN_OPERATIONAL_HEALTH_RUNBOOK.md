# 운영자 화면 상태 진단

`/admin`의 **자동 작업과 연동 상태**에서 확인한다. 기존 ADMIN 권한·관리자 세션·2단계 인증 경계를 통과한 후에만 서버에서 조회한다. 새 API, 예약 작업, DB 테이블, 외부 알림 발송, 쓰기·재시도 버튼은 추가하지 않는다.

화면 진입과 새로고침 때 한 번 조회한다. 자동 polling은 없다. 읽기 전용 repeatable-read 트랜잭션에서 고정 8개 SELECT를 실행하며 각 SQL 5초, lock 1초 제한을 적용한다. 실패하면 일부 값으로 정상 상태를 추측하지 않고 진단 전체를 미확인으로 표시한다. 계정·회원·Riot ID·방·설치 ID·해시·비밀값·원본 오류 메시지는 DTO에 포함하지 않는다.

| 카드 | 근거 | 표시와 조치 |
|---|---|---|
| 경기 통계 반영 | `competition.match_recalculation_outbox` | 대기/처리 중·실패 수, 가장 오래된 대기, 마지막 전달 시각. 실패 또는 15분 이상 대기면 점검 필요. `/admin/balance`에서 시즌별 상태를 확인한다. |
| 카카오 일일 마감 | `operations.maintenance_runs`, `kakao-daily-close` 최신 1건 | KST 06:00 운영일 경계와 15분 여유를 적용한다. 이전 운영일의 성공만 남거나 실패·15분 이상 실행 중이면 점검 필요. 기록 없음은 확인 필요. 수동 실행도 포함하므로 cron 자체 호출 증거와 구분한다. |
| 비공개 이미지 저장소 | 같은 테이블의 `storage-probe` 최신 1건 | 실제 저장소 여부는 `countsJson.realStorage`만 읽는다. 합성 성공은 확인 필요. 실패·2분 이상 실행 중이면 점검 필요. 수동 검사의 오래된 성공만으로 장애나 현재 정상 여부를 판정하지 않는다. |
| Riot | 사이트/서버 flag, 공통 설정 준비도 helper, `riot.sync_jobs`, `riot-api-probe` 최신 1건 | 대기/처리 중 수, 최근 24시간 완료된 FAILED/PARTIAL 수와 최근 완료 시각을 표시한다. 30분 이상 대기·실패는 점검 필요. API 진단 실패는 flag와 무관하게 점검 필요. 진단 없음은 실제 API 수락 미확인. RSO 설정은 별도이며 공급자 승인을 뜻하지 않는다. |
| 사이트 충원 카카오 알림 | 현재 방 범위·대상 해시와 일치하는 `recruiting.kakao_site_notices`, 현재 설치 principal의 nonce 시각 | 활성 대기/전송 중, 보관 중 실패, 만료 정리 대기를 분리한다. 실패·만료 정리 대기·5분 이상 대기는 점검 필요. 인증 요청 없음/2분 경과는 확인 필요이며 장애 단정은 하지 않는다. |

표의 시간은 운영 점검 기준이다. 작업을 자동으로 다시 실행하거나 데이터를 바꾸지 않는다. 현재는 진단을 조회할 때 판정하며 외부 수신처로 경보를 보내지 않는다.

## 확인할 수 없는 범위

- 통계 5분 cron은 빈 대기열 호출을 영속 기록하지 않는다. 마지막 이벤트 소비가 최근 cron 호출 자체를 증명하지 않는다.
- 일일 마감은 트랜잭션 자체가 실패하면 실패 행이 남지 않을 수 있다. 오래된 성공/기록 없음만 확인할 수 있다.
- Riot API 진단 성공은 해당 시각 status-v4 엔드포인트가 키를 수락한 결과다. 전적 API 권한, production key 등급, RSO 승인이나 현재 연결 보장이 아니다.
- 카카오 **최근 인증 요청**에는 수동 서명 점검도 포함된다. nonce 정리 후에는 과거 시각이 사라질 수 있다. **최근 전송 확인 응답**도 실제 휴대폰의 메시지 수신을 보증하지 않는다. 실기기 수신은 별도 증거가 필요하다.
- 카카오 알림 비활성/설정 불가 상태에서는 대상별 집계를 읽지 않아 0으로 표시한다. 실패 수는 현재 대상의 보관된 실패 전체이며 최근 장애 발생 시각을 뜻하지 않는다.

## 검증과 배포

근거: `docs/qa-evidence/admin-operational-health-v1.0.0-2026-09-22/README.md`.

통합 릴리스에서 `/admin` ADMIN 세션 정상 조회, USER/비로그인 접근 거부, 좁은 화면 줄바꿈을 확인한다. 운영 DB에는 이 기능을 위한 migration이나 seed를 실행하지 않는다. 운영 반영은 통합 배포 ID와 해당 SHA·health·관리자 화면 증거가 확보될 때 따로 기록한다.
