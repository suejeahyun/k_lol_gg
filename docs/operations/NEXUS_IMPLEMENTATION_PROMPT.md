# NEXUS.GG 실행 프롬프트

확정일: 2026-10-27 (Asia/Seoul)

현재 K-LOL.GG의 기능과 화면을 유지하는 별도 커뮤니티 NEXUS.GG를 구현한다. 기존 서비스와 공통 기능 코드를 유지하되 배포 환경, 데이터베이스, 인증 비밀값, 파일 저장소와 카카오톡 봇 설정은 서비스별로 분리한다.

## 확정 요구사항

1. 기존 기능, 명령어, 참가·모집·내전·경기·전적·랭킹·관리자 흐름을 유지한다. 표시 이름과 신규 서비스 안내는 NEXUS.GG로 적용한다.
2. NEXUS는 **빈 DB**로 시작한다. 기존 회원, 선수, 시즌, 경기, 랭킹, 모집, 미디어, 봇 등록 자료를 복사하지 않는다. 기존 migration으로 구조를 만들고 동작에 필요한 기본 설정만 초기화한다. 최초 관리자 생성은 독립된 절차로 제공한다.
3. 기존 K-LOL의 DB, 배포, 봇 설정을 변경하지 않는다. NEXUS 설정이 없으면 기존 DB·URL·비밀값으로 자동 연결하지 않는다.
4. 동일 휴대폰에서 기존 K-LOL 봇과 NEXUS 봇을 운영한다. NEXUS 대상 방은 정확히 `NEXUS`, `NEXUS 구인구직방`이다. 서비스별 서버 주소, 서명키, identity 키, 로컬 저장키와 알림 대상을 구분하고 잘못된 방에서 중복 반응하지 않도록 한다.
5. Vercel에 별도 NEXUS 프로젝트를 생성하고 Neon에도 새 프로젝트·DB를 생성한다. 사용자가 요청한 `nexus-gg.vercel.app` 주소는 사용 가능 여부를 확인하며, 사용 중이면 대체 주소를 사용자에게 확인한다. 개발본은 별도 로컬 주소로 실행한다. DB 연결·배포·휴대폰 설치는 실제 완료 근거로 구분한다.
6. K-LOL 기본 설정의 기존 호환성을 지킨다. 복사 양식의 브랜드를 바꿔도 서버가 정상적으로 다시 파싱하고 같은 기능을 처리해야 한다.
7. 비밀값을 출력하거나 추적 파일에 저장하지 않는다. 기존 데이터에 삭제·초기화·복사 작업을 실행하지 않는다.

## 완료 근거

- 실행 가능한 NEXUS 개발본과 환경변수 예제, 초기화·운영 절차.
- 빈 데이터 초기화, 비어 있지 않은 DB 거부, 서비스 설정 분리 검사.
- 같은 휴대폰 저장소에서 두 봇의 설정·응답·대상 방이 섞이지 않는 검사.
- 브랜드 변경 및 양식 왕복 호환, 기존 기능 회귀 검사와 프로덕션 빌드.
- 소스 반영, 로컬 실행, 외부 배포, 실기기 설치 상태를 각각 기록.

사용자 확정: “빈 데이터로 시작”, “카톡방 이름은 NEXUS와 NEXUS 구인구직방 사이트는 미정 아직 만들지 않음”.

추가 확정: “vercel로 새로 만들어서 주소를 k-lol-gg.vercel.app처럼 nexus-gg.vercel.app로”, “NEON에도 NEXUS용 DB를 다시 만들고”.

최종 주소 확정: `nexus-gg.vercel.app`은 다른 프로젝트가 사용 중이므로 사용자가 선택한 `https://nexus-gg-kr.vercel.app`을 사용한다.
