# 카카오 이중 비밀키 전환 런북

## 현재 상태

이 문서는 코드 준비 절차다. Production 배포, 환경변수 변경, 카카오봇 호출자 전환, 기존 키 폐기·회수는 이 작업에 포함되지 않는다. 비밀값·값의 길이·해시·일부 문자열은 문서, 로그, QA 증거에 기록하지 않는다.

대상 키는 다음 두 쌍이다.

- `KAKAO_RECRUIT_SECRET` / `KAKAO_RECRUIT_SECRET_NEXT`
- `KAKAO_SEARCH_PLAYER_SECRET` / `KAKAO_SEARCH_PLAYER_SECRET_NEXT`

## 전환 순서

1. 외부 비밀 저장소에서 각 NEXT 키를 생성하고 담당자 2인이 active와 다르며 비어 있지 않은지만 확인한다. 저장소 밖으로 값을 복사해 기록하지 않는다.
2. 서버 Production 환경에 NEXT 키를 추가하되 active 키를 유지한다. `SECURITY_REQUIRE_KAKAO_SECRET=true`와 query secret 비활성 상태를 확인한다.
3. 배포 검증기를 통과시킨 뒤 이중 수락 서버 버전을 배포한다. active 호출과 별도 통제된 NEXT 호출이 모두 성공하고 잘못된 키가 거부되는지 확인한다.
4. 카카오봇의 보호 저장소에 NEXT 참조를 연결한다. [호출자 전환 템플릿](./kakao-dual-secret-bot-opt-in.template.js)의 두 스위치는 계속 `false`로 둔다. 기본 경로가 active를 사용하는지 확인한다.
5. 모집 호출자 스위치를 먼저 켜고 관찰한다. 이상이 없으면 전적 검색 호출자 스위치를 켜고 다시 관찰한다. 응답 코드와 기능 성공 여부만 기록하고 인증정보는 기록하지 않는다.
6. 합의한 관찰 기간이 끝나면 NEXT 값을 새 active로 승격하고 NEXT 항목을 제거하는 서버·호출자 변경을 같은 변경 창에서 준비한다. 새 active 배포와 호출 검증이 끝난 뒤에만 이전 active를 폐기한다.
7. 키 전환과 호출자 검증이 모두 끝난 뒤 별도 승인 작업으로 저장소 이력 정리를 진행한다. 이력 정리를 키 회전보다 먼저 수행하지 않는다.

## 실패 시 롤백

호출자 전환 중 문제가 생기면 해당 봇 스위치를 즉시 `false`로 되돌린다. 서버가 active와 NEXT를 모두 수락하는 중첩 기간이므로 active 호출로 복귀할 수 있다. active 복귀가 확인되기 전에는 NEXT 서버 설정을 제거하거나 active를 폐기하지 않는다.

서버 배포 자체에 문제가 있으면 호출자 스위치가 모두 `false`인지 확인한 뒤 이전 서버 릴리스로 롤백한다. NEXT 환경 참조 제거는 롤백 검증 후 별도 변경으로 수행한다.

## 운영 확인표

- 배포 검증기: active-only와 active+NEXT 조합 통과, 빈 NEXT·동일 NEXT·인증 강제 없는 Production 조합 거부
- 서버: 모집·전적 검색에서 active와 NEXT 각각 수락, 다른 기능 키와 임의 키 거부
- HMAC 사용 시: active와 NEXT 서명 각각 수락, 누락·변조 서명 거부
- 봇 기본값: 두 opt-in 스위치 모두 비활성, active 호출 유지
- 증거: 키 이름과 성공·실패 판정만 기록; 값·길이·해시·접두·접미·요청 헤더 기록 금지
- 최종 폐기: 새 active 호출 관찰 완료 후 이전 active 회수
