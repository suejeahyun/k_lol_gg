# 팀 밸런스 보조 데이터 운영

작성일: 2026-09-22. 이 문서는 소스·격리 테스트 계약이다. 운영 배포 및 Riot 실계정 동기화 성공을 뜻하지 않는다.

## 데이터 경로

- 기존 서명된 `POST /api/internal/jobs/riot-sync`가 연결 계정의 티어를 가져온 뒤 Match-v5 최근 솔로랭크(queue 420) 최대 20경기를 읽는다. 동시 요청은 2개, 전체 최근 경기 시간 예산은 25초, 각 요청은 기존 5초 이하, route 최대 실행 시간은 60초다.
- match ID 목록 최대 8 KiB, 개별 경기 응답 최대 256 KiB를 읽는다. 원본 JSON·추가 PUUID는 저장하지 않는다. 정확히 일치하는 참여자, queue 420, 소환사의 협곡, 10인 경기만 인정한다. 명시된 조기 종료 경기는 집계에서 제외한다.
- `riot.summaries.recent_solo_json`에는 경기수·승수·KDA·주/부 포지션·포지션 신뢰도·평균 피해량·평균 시야 점수만 저장한다. 포지션은 Riot의 `teamPosition`을 사용하며, 알 수 없으면 추정하지 않는다. KDA는 전체 (킬+도움)/max(1, 전체 사망), 포지션 신뢰도는 주 포지션 경기수/집계 경기수다. 동일 빈도는 기존 포지션 순서 TOP/JGL/MID/ADC/SUP로 정렬한다.
- 최근 경기 일부가 누락·오류이면 편향된 일부 표본을 저장하지 않는다. 성공한 티어는 저장하고 job은 PARTIAL이다. 429이면 성공한 티어를 저장하면서 기존 RETRY_WAIT 및 Retry-After 정책을 유지한다. 같은 계정의 기존 최근 요약과 그 시각은 유지하되, Riot ID 또는 link가 달라지면 비운다.
- 팀 계산 provider는 CONNECTED, 동일 link/player/Riot ID, 현재 연결 시작 이후 수집, 24시간 이내 조건을 모두 만족하는 요약만 소비한다. 재연결·연동해제·오래된 요약·미수집은 `RECENT_SOLO` 미제공이다. API 빈 목록은 확인된 0경기로 구별한다.
- 내전 경험 수와 포지션별 경험 수는 게시된 경기 시리즈의 게임 참여자만 집계한다. 작성 중·무효 경기는 제외하며, 무효화/복구는 다음 계산부터 즉시 반영한다. 무효 경기의 원본 참여자는 감사·복구를 위해 보존한다.

## 팀 편성 전용 보정

- `/admin/balance-ai`의 「팀 편성 전용 보정」에서 플레이어 검색 → 현재값 확인 → 정수값과 사유 저장 순서로 사용한다. ADMIN은 조회, SUPER_ADMIN의 유효한 관리자/TOTP 세션만 변경한다.
- `GET/POST /api/admin/balance-ai/team-overrides`를 사용한다. 쓰기는 동일 출처, If-Match, Idempotency-Key, 트랜잭션 내 정확한 역할/세션 재검증을 요구한다. 같은 요청 재전송은 receipt를 반환하고 감사 이벤트를 중복 생성하지 않는다. 오래된 revision은 412다.
- 허용값 -1000~1000은 기존 `team-balance.ts`의 입력 계약이다. 범위를 새로 확대한 것이 아니다. 자동으로 값을 만들거나 기존 회원 점수를 수정하지 않는다. 미설정은 0이며 `BALANCE_OVERRIDE` 미제공으로 표시한다. 명시적 0 저장은 설정된 중립값이다.
- 보정은 팀 편성 점수에 1회만 적용한다. MMR 수동 조정·원장·기존 저장 초안과 별개다. 새 계산 또는 기존 초안의 명시적 재평가부터 적용한다. 사유 3~300자, 변경 전후 값·revision·행위자를 `TEAM_BALANCE_OVERRIDE_SET` 감사 기록에 남긴다.
- 입력 오류/오래된값은 화면에서 재확인한다. 잘못된 값 복구는 삭제가 아닌 원래 점수와 복구 사유를 새 revision으로 저장한다.

## 배포·활성화 조건

1. 운영자는 DB 백업/복구 기준을 확보한 뒤 총괄 배포 절차로 0043(테이블/nullable 요약) 및 0044(NULL pair CHECK 강화)까지 적용한다. 기존 데이터 보정·backfill은 없다. 구버전 코드와 호환되는 추가 구조이므로 애플리케이션 되돌림 시 컬럼·감사·보정 기록을 삭제하지 않는다.
2. 팀 기능 공개 읽기와 ADMIN 조회, SUPER 저장/412/중복 요청을 합성 계정에서 확인한다. 실회원 보정값은 운영자의 확인 없이 입력하지 않는다.
3. Riot 실사용은 승인된 앱 자격증명, 기존 암호화/state/job secret, 명시적 계정 연결 및 site feature를 갖춘 뒤 허용된 계정으로 진행한다. 이 패치는 자격증명을 발급하거나 Riot 기능을 자동 활성화하지 않는다. 2026-09-22 총괄 운영 점검에서 feature false 및 RSO 설정 부재가 확인되어 실계정 수집은 미검증이다.
4. 기존 서명 작업 호출 경로에서 1개 job을 처리하고, rank 성공과 recent 수집 시각·집계수·job 상태를 개인정보 없이 확인한다. 429는 Retry-After가 지난 뒤 재시도한다. PARTIAL/지속 누락은 자격·upstream 응답을 확인하고 승인된 기존 동기화 요청으로 재시도한다.
5. 팀 계산의 미제공 표시와 실제 적용 요약을 확인한다. 24시간 경과 후 자동 추정 대신 미제공으로 돌아가야 한다. 저장 초안은 과거 계산의 스냅샷이므로 자동 변경하지 않는다.

## 검증 근거

`docs/qa-evidence/operational-readiness-v1.0.0-2026-09-22/`의 `team-auxiliary-focused.log`, `team-auxiliary-db.log`, `team-auxiliary-riot-db.log`, `team-auxiliary-lint.log`, `team-auxiliary-typecheck.log`를 배포 기록과 함께 보관한다. 격리 DB 테스트는 기존 team-tools/riot scope에 포함되어 추가 runner 등록이 없다. 실제 브라우저·운영 배포·실계정 결과는 총괄 릴리스 증거로 별도 판정한다.

공식 계약: [Riot League of Legends 문서](https://developer.riotgames.com/docs/lol), [Match-v5 API](https://developer.riotgames.com/apis#match-v5), [공식 Match-v5 API 명세 데이터](https://developer.riotgames.com/api-details/match-v5). 지역 라우팅, queue/count 제한과 `teamPosition` 설명을 확인했으며 이 구현은 기존 내전 팀 계산의 보조 입력만 공급한다.
